## 결론 요약

1. **DS004 는 엔드포인트가 정확히 2개다** — `majorstock.json`, `elestock.json`. 그 외는 없다(근거는 §3).
2. **`elestock.json`(임원·주요주주 소유보고)은 우리 계획에 없는 신규 데이터다.** 내부자 매매 팩터의 원천이며 즉시 적재해야 한다.
3. **[기존 기록 정정] `majorstock.json` 은 "전체 이력"이 아니다.** `elestock` 과 마찬가지로 **접수일 기준 최근 약 2년치만** 돌려준다. 2024-08-26 이전 데이터는 이 API 로 영구히 받을 수 없다.
4. **`elestock.json` 은 실제 공시의 부분집합이다.** 완전 슬라이스 표본에서 11건 중 2건(18%) 누락 실측. 완전성이 필요하면 `list.json` 교차검증이 필수다.

## 2. 실측 결함 3건

### DEFECT-D004-1: `majorstock`·`elestock` 은 최근 약 2년치만 반환 — 기존 기록("corp_code 만으로 전체 이력")이 오류

- **상황**: 조사일 2026-08-24. 상장 유지 중인 대형주.
- **인풋**:
  1. `api.dart('elestock.json', corp_code='00126380')` → 3,398행, `rcept_dt` 최소 **2024-08-26**
  2. `api.dart('majorstock.json', corp_code='00126380')` → 40행, 최소 **2024-10-25**
  3. 대조: `api.dart('list.json', corp_code='00126380', bgn_de='20200101', end_de='20201231', pblntf_ty='D', page_count='100')` → **`total_count=128`**, 1페이지 내역이 `임원ㆍ주요주주특정증권등소유상황보고서` 98건 + `[기재정정]…` 1건 + `주식등의대량보유상황보고서(일반)` 1건
  4. 과거 지정 시도: `elestock.json` 에 `bgn_de=20180101&end_de=20181231` / `bsns_year=2018&reprt_code=11011` 를 붙여도 **응답 3,398행·범위 2024-08-26~2026-08-21 로 완전 동일** (파라미터 전부 무시)
- **에러 위치**: API 서버 측 조회 범위 제한. 클라이언트 코드 문제가 아니다. 개발가이드(`guide/detail.do?apiGrpCd=DS004&apiId=2019021/2019022`)에는 기간 제한 문구가 **없다** → 문서만 읽으면 전체 이력으로 오해한다.
- **위험성**: **silent truncation.** 에러가 아니라 `status=000 정상` 으로 잘린 데이터를 준다.
  - 2020년 삼성전자에 지분공시가 128건 실재하는데 API 는 0건을 준다 → 백테스트 유니버스에서 2024-08 이전 내부자 시그널이 통째로 **결측이 아니라 "이벤트 없음"으로 위장**된다. 팩터가 최근 2년만 신호를 갖고 그 이전은 0 으로 채워지면, 시그널 유무와 시점이 완전 교란되어 IC 가 무의미해진다.
  - **롤링이면 시간이 지날수록 과거가 사라진다.** 오늘 안 받으면 내일 없다.
- **관측의 한계 (미확인)**: 최소 접수일 2024-08-26 이 조사일 −2년(2024-08-24 토, 25 일 → 첫 영업일 08-26 월)과 정확히 일치한다. **롤링 2년 윈도우로 강하게 시사되나 1회 관측이므로 "2024-08-26 고정 컷오프" 가능성을 배제하지 못한다.** 다만 어느 쪽이든 결론(과거는 API 로 못 받는다 / 지금 적재해야 한다)은 같다. 판별하려면 수일~수주 뒤 동일 corp_code 의 최소 접수일이 전진하는지 재측정하면 된다.

### DEFECT-D004-2: `elestock` 은 실제 공시의 부분집합 — 표본 18% 누락

- **상황**: 윈도우 안쪽(2026-07~08) 이라 §DEFECT-1 과 무관한 별개 누락.
- **인풋**:
  1. `list.json(corp_code='00126380', bgn_de='20260729', end_de='20260803', pblntf_ty='D', page_count='100')` → `total_count=12, total_page=1` (**페이지 잘림 없는 완전 슬라이스**). 내역: 임원소유보고 10 + `[기재정정]`임원소유보고 1 + 대량보유(일반) 1
  2. 같은 기간 `elestock.json(corp_code='00126380')` 결과를 `rcept_no[:8]` 로 필터 → **9행**
- **에러 위치**: `elestock.json` 서버 응답 자체. 누락된 2건은
  - `20260803000004` 2026-08-03 박태훈 `임원ㆍ주요주주특정증권등소유상황보고서`
  - `20260729000314` 2026-07-29 여명구 `임원ㆍ주요주주특정증권등소유상황보고서`
  (둘 다 `[기재정정]` 이 아닌 **원본 공시**다. 반대 방향 — elestock 에만 있고 list 에 없는 건 — 은 **0건**이므로 elestock 은 엄격한 부분집합)
- **위험성**: `status=000` 으로 조용히 빠진다. 내부자 매수/매도 **건수·수량 집계가 체계적으로 과소계상**되고, 하필 하루에 여러 건 보고한 인물(= 대량 거래 가능성이 높은 케이스)에서 빠지는 경향이 관측되어 **결측이 랜덤이 아닐 수 있다**. 누락 원인은 **미확인** (정정에 의한 원본 대체 가설은 이 표본으로 확증 못 함 — 이 슬라이스의 `[기재정정]` 1건은 elestock 에 정상 포함되어 있었다).
- **대응**: `list.json(pblntf_ty='D')` 를 정본 카운트로 두고 elestock 을 조인해 누락률을 상시 감시. 누락분 상세가 필요하면 `document.xml` 파싱.

### DEFECT-D004-3: `rcept_dt` 가 `rcept_no` 접수일과 불일치 (3,398건 중 18건)

- **상황**: 삼성전자 elestock 전량.
- **인풋**: `r['rcept_no'][:8] != r['rcept_dt'].replace('-','')` 검사
- **에러 위치**: 응답 필드 정합성. 예 — `20240920000459` / `rcept_dt=2024-09-23`, `20241015000467` / `2024-10-16`, `20241204000382` / `2024-12-05`. **전부 `rcept_dt` 가 접수번호 날짜보다 뒤(주말·익일)** 다.
- **위험성**: 시점 기준(as-of) 을 `rcept_no` 앞 8자리로 잡으면 최대 3일 **look-ahead**. 두 값 중 **늦은 쪽(`rcept_dt`)** 을 정보 가용 시점으로 써야 안전하다. 18/3,398 = 0.5% 로 작지만 방향이 한쪽(미래)이라 체계적 편향이다.

```
                report_resn, ingest_dt)
```

- `rcept_no` 단독 PK 로 upsert → 반복 스냅샷을 무손실 누적. `ingest_dt` 로 윈도우 이탈 시점 추적.
- **as-of 는 `rcept_dt`** (DEFECT-D004-3). `rcept_no` 앞 8자리 금지.
- 파싱 시 `api.num()` 사용(콤마·부호). `isu_exctv_ofcps` 는 `.strip()` 필수.
- `stock_code` 없음 → `corpCode.xml` 로 매핑.
