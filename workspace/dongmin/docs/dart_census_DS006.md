## 0. 결론 3줄

1. DS006 은 **6개 엔드포인트가 전부**다(목록 실측 확보). 그중 `stkdpRs`(증권예탁증권)는 2회 프로브 모두 `013` → **해당 없음**.
2. 나머지 5개는 전부 **`group` 배열 구조**다. 기존 8개 엔드포인트가 쓰던 평면 `list` 키가 **없다** — 파서를 그대로 재사용하면 조용히 0행으로 읽힌다(실제로 1차 프로브에서 status=000·rows=0 으로 오판했다).
3. **우리 계획에 없는데 반드시 받아야 할 것 = `dvRs` + `mgRs` + `extrRs`.** `DATA_CATALOG.md` CA-02(인적분할 대응관계, **P0**)와 `COLLECT_PLAN.md` P12("실패 시 DART 분할공시 파싱이 유일 경로")가 요구하는 **분할비율·당사회사·발행증권수**를 정형 JSON 으로 준다. HTML 파싱이 필요 없다.

### 공통 실측 사실

- **응답 스키마**: `{"status","message","group":[{"title":"<한글 그룹명>","list":[...]}]}`. `013` 일 때는 `group` 키 자체가 없다.
- **`corp_code` 는 필수.** 날짜만으로 전종목 스윕 불가 — 실측:
  `estkRs.json bgn_de=20260101 end_de=20260131` (corp_code 생략) → `status=100 / "필수값(corp_code,bgn_de,end_de)이 누락되었습니다."`
  ⇒ **1콜 = 1 corp_code 규약이 강제된다.** DS002 와 동일한 콜 구조.
- **`list.json` 의 3개월 제한이 여기엔 없다.** `bgn_de=20150101 end_de=20260818` (11.6년) 1콜 정상. `bgn_de=19990101` 도 `status=000`.
  ⇒ **corp_code 당 1콜로 전체 이력을 받는다. 연도 루프 불필요** (`irdsSttus` 와 정반대).
- **소급 하한**: 가이드는 `stkdpRs`/`extrRs`/`dvRs` 파라미터 설명에 "※ 2015년 이후"를 명시. `estkRs` 를 `bgn_de=19990101` 로 확장해도 반환 행이 2015년 이후 4건 그대로였다(두산에너빌리티 2019·2020·2022). **다만 두산이 2015년 이전에 지분증권 신고서를 냈는지 자체를 확인하지 않았으므로, "2015 하한"은 가이드 근거이고 실측 확정은 아니다 — 미확인.**
- **행수 상한(페이징)**: `page_no`/`page_count` 파라미터가 없다. 관측 최대 22행. **상한 존재 여부 미확인.**

### 3.1 `estkRs.json` — 지분증권

| group | 행수 | 필드 (실측) | **최소 PK (실측 검사)** |
|---|---|---|---|
| 일반사항 | 4 | `rcept_no, corp_cls, corp_code, corp_name, sbd, pymd, sband, asand, asstd, exstk, exprc, expd, rpt_rcpn` | **`rcept_no`** |
| 증권의종류 | 4 | `+ stksen, stkcnt, fv, slprc, slta, slmthn` | **`rcept_no`** (⚠ §3.1a) |
| 인수인정보 | 22 | `+ stksen, actsen, actnmn, udtcnt, udtamt, udtprc, udtmth` | **`(rcept_no, actnmn)`** |
| 자금의사용목적 | 10 | `+ se, amt` | **`(rcept_no, se)`** |

필드 의미(가이드 원문 한글 라벨):
`sbd` 청약기일 · `pymd` 납입기일 · `sband` 청약공고일 · `asand` 배정공고일 · **`asstd` 배정기준일** ·
`exstk/exprc/expd` 신주인수권(행사대상증권/행사가격/행사기간) · `rpt_rcpn` 주요사항보고서 접수번호 ·
`stksen` 증권의종류 · **`stkcnt` 증권수량** · `fv` 액면가액 · **`slprc` 모집(매출)가액** · `slta` 모집(매출)총액 · **`slmthn` 모집(매출)방법** ·
`actsen` 인수인구분 · `actnmn` 인수인명 · `udtcnt/udtamt/udtprc/udtmth` 인수수량/금액/대가/방법 ·
`se` 구분 · `amt` 금액 · `hdr` 보유자 · `rl_cmp` 회사와의관계 · `bfsl_hdstk/slstk/atsl_hdstk` 매출전/매출/매출후 보유증권수 ·
`grtrs` 부여사유 · `exavivr` 행사가능투자자 · `grtcnt` 부여수량.

실측 샘플 (두산에너빌리티 2020-11-27 유상증자):
`sbd="2020년 12월 03일 ~ 2020년 12월 04일"`, `pymd="2020년 12월 11일"`, `asstd="2020년 10월 16일"`,
`stksen="기명식보통주"`, `stkcnt="121,495,330"`, `slprc="9,640"`, `slta="1,171,214,981,200"`, `slmthn="주주배정후 실권주 일반공모"`.

**⚠ §3.1a — `증권의종류` 의 PK 는 `rcept_no` 단독이 아니다.**
두산 표본은 신고서 1건당 증권 1종이라 우연히 유일했다. 2019-04-01 에 보통주(`...1224`)·우선주(`...1267`) **신고서를 따로 냈기 때문**이다.
한 신고서가 보통주+우선주를 함께 담으면 `rcept_no` 가 중복된다. **저장 PK 는 `(rcept_no, stksen)` 으로 잡아야 안전하다** — 근거는 alotMatter 가 `se` 단독으로 중복났던 것과 같은 패턴이다. (해당 반례를 실제로 프로브하지는 않았다 — **미확인, 방어적 설계**.)

**⚠ §3.1b — `exprc`/`expd` 필드명이 두 그룹에서 충돌한다.**
`일반사항`의 `exprc/expd` = 신주인수권 행사가격/기간. `일반청약자환매청구권`의 `exprc/expd` = 풋백옵션 행사가격/기간. **의미가 다르다.** 6개 그룹을 한 테이블로 평탄화하면 조용히 덮어쓴다 → **그룹별 테이블 분리 필수**.

## 4. 결함 / 회귀 위험

### DEFECT-DS006-01: `bdRs` 가 실제 제출된 증권신고서(채무증권)를 **누락한다**

- **상황**: 현대자동차(`00164742`)는 2015-01-01~2026-08-18 사이에 채무증권 증권신고서를 **3 라운드**(2016-09-22 / 2020-04-23 / 2021-01-28) 제출했다. `list.json corp_code=00164742, pblntf_detail_ty=C002` 로 실측 확인 — 원신고서 3건 + `[기재정정]` 2건 + `[발행조건확정]` 6건 = 총 11건.
- **인풋**:
  1. `api.dart('bdRs.json', corp_code='00164742', bgn_de='20150101', end_de='20260818')` → `status=000`, 일반사항 4행, **`rcept_no` 는 `20160922000326` 과 `20200429001450` 단 2개**
  2. `api.dart('bdRs.json', corp_code='00164742', bgn_de='20210101', end_de='20211231')` → **`013` 조회된 데이타 없음**
  3. 그런데 `list.json` 에는 `20210128000530 증권신고서(채무증권)`, `20210203000486 [기재정정]`, `20210203000495`·`20210208000711 [발행조건확정]` 이 명확히 존재
- **에러 위치**: DART 서버측 요약정보 추출 누락. 클라이언트 코드 문제가 아니다. 우리 쪽 발현 지점은 "행수 > 0 이면 성공"으로 판정하는 수집기 검증 로직.
- **위험성**: **silent partial data.** 2021년 3,900억 규모 회사채 발행이 `status=000` 응답 안에 **없다는 신호조차 없이** 빠진다. `bdRs` 만으로 "이 기업은 2021년에 채권을 발행하지 않았다"를 결론내면 **거짓**이다. 부채조달 이벤트 팩터·차환 리스크 지표가 조용히 틀어진다.
- **추가로**: 2016 라운드는 **원신고서** `rcept_no`(20160922000326)를, 2020 라운드는 **`[기재정정]`** `rcept_no`(20200429001450, 원본은 20200423000368)를 돌려준다. **어느 버전을 주는지 규칙이 일정하지 않다.** `rcept_no` 로 `list.json`·`dart_disclosure` 와 조인할 때 매칭 실패가 난다.
- **완화**: `list.json pblntf_detail_ty=C001~C005` 로 뽑은 신고서 목록을 **정답지**로 두고, DS006 반환 `rcept_no` 집합과 대조해 **커버리지율을 원장에 기록**한다. 대조 없이 DS006 단독으로 "발행 없음"을 판정 금지.
- **재현 test**: 없음(작성 필요). `tests/test_ds006_coverage.py::test_bdRs_hmc_2021_missing`

### DEFECT-DS006-02: `group` 스키마 — 기존 평면 파서가 조용히 0행을 읽는다

- **상황**: DS001/DS002/DS003 8개 엔드포인트는 전부 `{"status","message","list":[...]}` 다. DS006 6개는 **`list` 가 없고 `group":[{"title","list"}]`** 다.
- **인풋**: `j = api.dart('estkRs.json', ...); rows = j.get('list') or []`
- **에러 위치**: 이번 조사 1차 프로브 스크립트가 정확히 이 실수를 했다 — `status=000 rows=0` 으로 6개 중 4개를 "데이터 없음"으로 오판했다.
- **위험성**: `status` 는 `000` 이고 예외도 안 난다. **완전 무증상**. 수집기가 `ingest_log` 에 `success, rows=0` 을 남기고 재시도조차 안 한다. `013` 과 구분이 불가능해진다.
- **완화**: DS006 파서는 `'group' not in j and j['status']=='000'` 을 **예외로 던져야 한다.**

### DEFECT-DS006-03: `tm` 회차 값의 개행 오염
- **상황/인풋**: `bdRs.json corp_code=00164742` → 일반사항 `tm` 값 `"317-\n1"`(실측). 같은 응답의 다른 행은 `"317-2"`, `"317-3"` 로 정상.
- **에러 위치**: DART 원문 HTML 의 줄바꿈이 그대로 전달됨.
- **위험성**: `tm` 은 `bdRs` **4개 그룹 전부의 PK 구성요소**다. 정규화 없이 적재하면 `317-1` 회차의 일반사항·인수인·자금목적·매출인이 **서로 다른 키로 흩어져 조인이 끊긴다.** UPSERT 를 쓰면 재수집 때마다 중복 행이 늘어난다.

### 예상 콜 수

`corp_code` 필수 · 페이징 없음 · 구간 전체 1콜 ⇒ **콜 수 = 대상 corp_code 수 × 엔드포인트 수**, 정확히 계산 가능하다.

| 방식 | 콜 수 | 근거 |
|---|---|---|
| **A. 전수 (권장 없음)** | 5 × N | N = 우리 유니버스 corp_code 수. N=3,700 이면 **18,500콜** = 일한도 20,000 의 92%. 1일 소진 |
| **B. 사전 필터 후 대상만 (권장)** | **디스커버리 ~400 + 본수집 ~4,000 ≈ 4,400콜** | 아래 |
| C. N1 만 (P0 최소) | 디스커버리 ~120 + 본수집 ~1,000 ≈ **1,100콜** | `list.json pblntf_detail_ty=C004` 만 |

**방식 B 절차**
1. **디스커버리**: `list.json` 을 `corp_code` 없이 `pblntf_detail_ty ∈ {C001,C002,C004}` × **3개월 창**으로 돌려 신고서를 낸 `corp_code` 집합을 만든다.
   - 창 수 = 2015-01 ~ 2026-08 = **47분기**. 실측 표본: C004 2025Q1 = 44건(1페이지), 2024Q4 = 69건(1페이지), C005 2025Q1 = 20건.
   - C004·C005 는 분기당 1페이지로 충분(실측). **C001(지분증권)·C002(채무증권)은 건수가 훨씬 많아 페이징이 필요할 것 — 페이지 수 미확인.**
   - 보수 추정 47창 × (C001 4p + C002 3p + C004 1p) ≈ **~380콜**. 반환 == `page_count` 면 창 재분할(기존 규칙 그대로).
2. **본수집**: 디스커버리로 나온 corp_code 에 대해서만 해당 엔드포인트 1콜.
   - 추정 대상 corp 수 — **추정치이며 실측 아님**: `estkRs` ~2,500 / `bdRs` ~450 / `mgRs` ~700 / `dvRs` ~150 / `extrRs` ~100 → **~3,900콜**
3. **검산**: 디스커버리 `rcept_no` 집합 ⊇ DS006 반환 `rcept_no` 집합 인지 대조하고 **커버리지율을 `ingest_log` 에 기록**(DEFECT-DS006-01 때문에 필수).

**주의 — 소급 하한 2015.** 우리 백테스트가 2010년부터라면 **2010~2014 구간의 유상증자·합병·분할은 DS006 으로 못 채운다.** 그 구간은 여전히 KIS `ksdinfo/*` 가 유일 소스이며, **DS006 은 2015 이후 구간의 교차검증축으로만 기능한다.** CA-01/CA-02 를 DS006 단독으로 대체할 수 없다.
