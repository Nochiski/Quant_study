## 1. 층 계약

허용 변환: stage 위에서 **조인 · 격자 · 판본 선택 · 파생(계수·정정 링크·정지 상태·무거래 연속일·기간축)** 을 한다. 하지 않는 것: 임계값·판정 결과를 팩트 행에 굽기, 통계 정규화, 최신 판본 선택, `_current` 테이블로 과거 필터, 게이트 술어를 산출식으로 재계산.

원칙 6(ERD v0.1): ① 전 팩트 행 PIT 게이트 ② 원주가 불변 + 계수 분리 ③ corp/ticker 이축 ④ 결측은 결측 ⑤ 지식은 카탈로그 ⑥ 읽기 전용 SQL 계약(PIT 뷰 4 + 보조 3).

**정본 우선순위(사용자 확정 09-03)**: KRX 가 주는 사실은 KRX 정본. 폐지일도 KRX(listing 소멸) 우선, KIS 는 대조축. basis 어휘: stage 4종 `measured`·`derived`·`default`·`unknown` + equity 신설 `convention`.

## 5. 뷰 · 매크로 (`equity.duckdb`, 기본값 `:=`, 랙은 본문 서브쿼리)

```sql
v_universe(d, policy := 'all', lag_override := NULL)         -- 정책 미적용 기본, 컬럼군별 세션 랙 (T9, 미구현)
v_cum_adj(as_of, lag_override := NULL)                        -- (ticker, date ≤ as_of) 별 cum_price_factor·cum_share_factor  [S06 구현]
v_adj_price(as_of, lag_override := NULL)                      -- price_daily 원주가 + adj_open/high/low/close = 원주가 × cum_price_factor → FIELD_MAP `price.adj_close`  [S06]
v_adj_volume(as_of, lag_override := NULL)                     -- adj_volume = volume_shr × cum_share_factor  [S06]
v_fin_latest(as_of, lag_override := NULL, vintage := 'restated')  -- CFS 우선(fs_div_used), ttm 은 4분기 전부 보일 때만, has_correction = (first_correction_dt ≤ as_of − lag)

v_firm_mktcap(d)                                              -- (corp_code, firm_ticker, date, n_leg, firm_mktcap_krw): 그날 가격 행이 있는 종류주 시총 합 (독립 재계산 게이트 EG3-P05)  [S06]
```

S06 실체(`src/equity/views.py` 템플릿 → `catalog.publish` 가 `equity.duckdb` 에 `CREATE MACRO … AS TABLE` 로 굽는다, 09-05):
- 매개변수는 **`as_of`** — `asof` 는 duckdb 예약어(ASOF JOIN)라 매크로 인자로 못 쓴다. 호출 `v_adj_price(DATE '2018-05-04')` · `v_cum_adj(DATE '…', lag_override := 1)`.
- `v_cum_adj`: `cutoff` = as_of 에서 `coalesce(lag_override, 0)` 세션 전 거래일(`trading_calendar` 역산). `cum_*(d)` = Π(`adj_factor` ok 행 : d < **apply_date** ≤ as_of ∧ available_date ≤ cutoff), 같은 (ticker, apply_date) 는 곱으로 접고(복합 성분) 뒤에서부터 누적한 뒤 ASOF JOIN 으로 '그날 이후 첫 적용 세션' 의 누적값을 붙인다 — base = as_of 에서 1. 축은 apply_date 이지 명목 효력일이 아니다(S06 2차 — 감자는 정지 뒤 재개일에 기준가가 바뀐다). 가격 행은 `date ≤ as_of`. **랙 기본값 0 세션**(`views.FACTOR_LAG_SESSIONS`): `dataset_profile`(S19)이 아직 없어 본문 상수이며, 근거는 계수 available_date 가 이미 '그날 알 수 있었던 날'(min(공시, apply_date 다음 세션), stage 가격류 lag_known=true 와 같은 규약)이고 랙을 더 두면 분할 당일 조정가가 하루 늦게 붙어 EG8 점프가 생긴다는 것. `dataset_profile` 이 생기면 그 값으로 교체.
- `v_adj_price`·`v_adj_volume` 은 `v_cum_adj` 를 호출한다(한 식). 매크로 본문의 parquet 경로는 MANIFEST 파티션 절대경로(`_reject/`·구버전 `v=` 를 물지 않는다), `hive_partitioning=false`.
- 같은 템플릿을 EG8 게이트가 빌드 세션의 TEMP VIEW 위에 TEMP MACRO 로 올려 쓴다(`views.install_temp_macros`) — 게이트가 본 계산과 소비자가 보는 계산이 갈릴 수 없다.
- `catalog` 단계 전역 게이트(GATES §9 §8-6): **EG11** 임시 카탈로그를 별도 read_only 연결 2개로 열어 고정 표본(`trading_calendar.asof_sample_dates × asof_sample_tickers`, `v_cum_adj`·`v_adj_price`) 해시 동일 · **EG5c** 직전 `_asof/<view>/<snapshot_id>/` 표본과 행 해시 차이 0(첫 실행 skip(no_previous_snapshot), 차이는 FAIL → `catalog --rebase-asof` 로 사람이 승인) · **EG3_firm_mktcap**(EG3-P05) 표본 날짜마다 isin8 축 독립 재계산 대조. 하나라도 FAIL 이면 `equity.duckdb` 를 교체하지 않는다(`_failed/catalog_<snapshot_id>.json`). 통과하면 `os.replace` → `_asof/` 기록(keep=3) → `_catalog_meta.json`(gates·asof 포함).

패널 질의(`[start, end]` × 종목 × 필드, 세션별 컷오프)는 어댑터가 `trading_calendar` 를 돌며 위 뷰를 호출하거나 세션 조인 SQL 로 구현한다(E-1). 카탈로그 `snapshot_id` = 전 테이블 build_id 정렬 해시.
