# Strategy Workbench의 사실은 한 곳만 소유한다

## 정본 대장

| 사실 | 유일한 owner | 나머지 레이어 |
|---|---|---|
| 원천 값·공개 시점·coverage | Equity DB view + `dataset_profile` | `EquityDataPort`와 `RawObservationPort` 두 포트로 조회하며, 같은 셀에 같은 값·공개일을 답하는 것이 어댑터 계약이다 |
| Equity 연결 계약 | backend application outbound port | adapter가 구현 |
| equity 필드 계약(단위·값 타입·랙·빈도) | 원장 `dataset_profile`(S19)이 정본이고, 원장 빌드가 그 표를 만드는 선언은 `database/src/equity`의 `rules_s*.py`다. duckdb 어댑터는 원장 스키마를 옮긴 선언표 `equity_duckdb/_specs.py`(`FIELD_SPECS`의 `FieldSpec`, `SOURCE_SPECS`의 `SourceSpec`)로 답하고, 랙은 부팅 때 `dataset_profile`의 `recommended_lag_sessions`를 읽어 적용한다 | mock(`equity_mock/_fixture.py`)은 단위·값 타입·빈도를 duckdb 선언표에, 랙을 원장 선언에 맞추고, 선언표의 값 타입은 원장 선언과 같다(#221·#243). compile 은 연결된 어댑터의 계약으로 단위·`field_missing`·값 타입을 판정하므로, 두 어댑터가 같은 field_id에 다른 계약을 답하면 mock 으로 green 인 문서가 실데이터에서만 다르게 동작한다. `tests/contract/test_equity_field_contract_parity.py`가 선언표와 원장 선언을 직접 읽어 대조한다. 대장에 행이 없는 필드의 폴백 랙(`SourceSpec.lag_sessions`, 원천 안에서 갈리면 `FieldSpec.lag_sessions`)은 원장 선언의 사본이고 `tests/contract/test_equity_fallback_lag.py`가 대조하며, 폴백을 쓰면 duckdb 어댑터가 부팅 때 `profile_lag_fallback` 경고를 한 번 남긴다(#255). 필드 목록·단위를 소비자에 따로 적지 않는다 |
| 재무 셀의 기간 선택과 흐름 계정 TTM | 원장 뷰 `database/src/equity/views.py`의 `v_fin_latest`: 흐름 계정(손익·현금흐름)을 회계기간 순서의 분기값 4개 합(`ttm_*`, #212)으로 세우고, 행마다 "그 공개일까지 공개된 가장 최근 기간인가"(`period_frontier`, #225)를 판정한다 | duckdb 어댑터(`equity_duckdb/_specs.py`의 `fin` 원천)는 `ttm_*` 열을 field_id에 매핑하고 `period_frontier`가 참인 행만 고른다. 기간·합산 규칙을 어댑터에 다시 적지 않는다. #225 전에 만든 카탈로그라 뷰에 `period_frontier` 열이 없으면 재무 원천만 빼고 경고한다(#233). 부팅 때의 열 확인이 카탈로그·파일 성격의 duckdb 오류를 내면 그 원천만 빼고(`catalog_macro_unreadable`), 잠김·일시적 오류는 원천을 빼지 않고 코드화된 `EquityDuckdbSetupError` 로 올려 다음 부팅에서 다시 확인한다(#245·#247) |
| equity 산출 규칙 판본 | `database/src/equity/model.py`의 `RULES_VERSION`(`BuildRecord.rules_version`에 실린다). 언제 올리는가의 정본은 `database/docs/EQUITY_HANDOFF.md` §6 | 산출식·선언 컬럼·`field_profiles`·게이트 술어(`sql/*.sql`·`rules_*.py`)를 바꾸거나 선언면을 늘리면 같은 변경에서 판본을 올리고 `model.py` 주석 블록에 이력을 한 줄 남긴다. 판본을 안 올리고 산출을 바꾸면 재현성 게이트 EG5a 가 새 판을 폐기한다 |
| 팩터 정의·방향·단위·입력 요구 | backend Factor Registry | UI는 catalog 표시. `backend/FACTORS.md`는 사람이 읽는 사본이며, registry의 모든 `factor_id`가 문서에 있는지와 `implemented` 행 수를 `tests/domain/test_factor_research.py`가 대조한다 |
| 연산자 정의·설명 키·가용성 | `domain/factor/_operators.py`의 `OperatorDefinition` 레지스트리(키 `(kind, operator)`, 스키마 enum과 같은 집합임을 `tests/domain/test_factor_operators.py`가 양방향으로 강제한다) | 프론트 팔레트·노드 라벨·Contract Inspector는 `GET /api/v1/strategy-documents/operators`와 runtime schema의 `x-operator`(`enum 값 → 설명 키 stem`)로 이 카탈로그를 읽는다. 연산자 목록·arity·가용성·설명 키를 손으로 적지 않는다. `availability`는 연결된 어댑터 capability로 판정한다(P2-07): kind가 요구하는 필드 값 타입(`_REQUIRED_FIELD_VALUE_TYPES`, 그룹 연산 → `group_series`)을 어댑터 필드 계약이 하나라도 갖는지를 `operator_availability` 하나가 가르고, 카탈로그 응답과 compile 진단 `strategy.operator.unsupported`가 같은 함수를 읽는다. 어댑터가 없으면 아무 필드도 없는 것으로 본다. `reads_past_sessions`(입력의 과거 세션 값을 읽는가: time_series 전부와 `unary.lag`)는 카탈로그가 소유하고, `test_factor_operators.py`가 실제 이력 추론(`minimum_history_sessions`)과 대조한다. compile 의 원주가 warning 이 이 값을 읽는다(BACKLOG-018). 출력 단위 추론의 owner 는 검증기다: 입력 단위를 지우는 연산은 `domain/factor/_validation.py` 의 무차원 집합(`_DIMENSIONLESS_SECTIONS`·`_DIMENSIONLESS_GROUP_OPERATIONS`)이 정한다. 카탈로그의 `unit_rule`(`UnitRule.DIMENSIONLESS` 포함)은 그 추론을 사람 말로 옮기는 표시값이고, `test_factor_operators.py` 가 실제 `validate_factor_graph` 결과와 묶는다(Phase 2 감사 NB-6) |
| 그래프 노드 정수 파라미터의 하한(`window`·`lag`·`periods`) | 노드 dataclass 필드 옆의 `minimum` 선언(`domain/factor/_nodes.py`의 `minimum()`). 검증기는 `field_minimum()`으로 읽고(선언이 없으면 `KeyError`), 스키마 빌더(`domain/strategy/_schema.py`)는 같은 metadata 키 `minimum`을 optional로 읽는다 — 하한이 없는 정수 property도 있어 스키마 쪽은 `field_minimum()`을 쓰지 못한다 | `_validation.py`가 그 값으로 검사하고 runtime schema가 같은 값을 JSON Schema `minimum`으로 발행한다. 하한을 검증기와 스키마에 따로 적지 않는다 — 스키마에만 없으면 화면이 스키마로 만든 기본값(`materializeSchemaValue`)이 `window: 0`이 되어 backend가 곧바로 거부한다(P1-04). `tests/domain/test_node_parameter_bounds.py`가 정수 property의 선언 누락과 두 소비자의 불일치를 양방향으로 막는다. 관계 제약(분위수 `lower < upper`)은 필드 하나로 표현되지 않아 이 계약 밖이고 `_validation.py`가 소유한다 |
| 팩터 **값** | `FactorGraph` 평가 (`domain/factor`) | 계산자는 `application/portfolio_design/_service.py` 하나뿐, 어댑터는 원천 필드만 답한다 |
| 팩터 값의 공개일 | 그 팩터 plan이 읽는 필드들의 `available_date` 최댓값 | 컴파일러 FUTURE_DATA 가드가 그대로 읽는다 |
| 결합 전 정규화 방식과 합성 공식 | `domain/portfolio/_compiler.py` 가 `spec.signal.normalization` 을 읽어 `composite = Σ(sign(direction) × weight × norm(x)) / Σ|weight|` 를 계산한다(P2-04, spec D4). `norm` 의 횡단면 순위·표준화 공식 자체는 `domain/factor/_statistics.py` 의 `cross_sectional_rank`·`cross_sectional_zscore` 하나씩이 소유하고, 팩터 그래프의 `CrossSectionalOperator` 도 같은 함수를 부른다 — 같은 문서가 두 가지 순위를 내지 않는다. `Σ` 에 들어가는 팩터 집합은 `domain/strategy/_models.py` 의 `composite_factors`·`inverse_risk_factor_id` 가 소유한다(P2-06, spec D3 S6): `weighting: risk` 이고 `risk.risk_factor_id` 가 있으면 그 팩터는 가중 합·분모·정규화 모집단에서 빠지고 역가중에만 **정규화 전 원시값**으로 쓰인다. 컴파일러·검증(`strategy.risk.risk_factor_excluded`·`strategy.signal.no_alpha_factor`)·설명이 같은 함수를 읽는다 | 정규화 모집단은 팩터 그래프 횡단면 연산자와 같은 동료 집단 규칙을 쓴다: 한 리밸런싱 프레임은 기준일 하나이므로 `universe_member` 가 같은 행끼리만 서로의 순위에 들어간다. 결측(`missing` 정책 적용 뒤에도 `None`)·공개일이 기준일보다 늦은 값·비유한값은 모집단에서 빠지며, 이는 `_score_candidate` 가 같은 값을 점수에서 버리는 사유(`MISSING_FACTOR`·`FUTURE_DATA`·예외)와 같다. 즉 순서는 항상 결측 처리 → 정규화 → 가중 합이다. `normalization` 은 canonical payload에 들어가므로 `spec_hash`·`tape_hash` 가 값마다 다르다. frontend 는 값을 문장으로 옮기는 i18n 만 갖고(P3-01) 공식을 복제하지 않는다. `weighting: factor_score` 의 비중 규칙은 `_compiler.py` 의 `_margin_strengths` 하나가 소유한다: 선정이 2종목 이상이면 선정 종목 강도 = 합성 점수 − 기준점, 기준점 = `min(선정 최저 점수 이하인 eligible 비선정 종목 중 최고 점수, 선정 최저 − (선정 최고 − 선정 최저) / (선정 수 − 1))`(컷 아래 종목이 없으면 뒤 항), 선정 1종목이거나 강도가 모두 0 이면 균등 배분, 숏은 합성 점수 부호를 뒤집어 같은 규칙(PLAN P2-04 결정 5). 합성 점수 절댓값, eligible 최저 점수, 컷 아래 최고만을 기준점으로 쓰지 않는다 — 차례로 `direction: low`·공매도 쪽 순서 반전, 선정 종목 비중 0, 근접 동점 dust 를 만든다 |
| compile 이 읽는 필드 계약과 팩터 출력 타입 경계(P2-07, spec D5) | 필드 계약은 연결된 equity 어댑터가 `application/strategy_authoring/ports/outgoing/field_catalog.py`의 `FieldCatalogPort`(`factor_field_catalog`)로 답하고, 실행 경로의 `resolve_factor_fields`와 같은 변환을 거친다. 출력 타입 판정은 `domain/strategy/_validation.py`의 `strategy.factor.output_type`, boolean 출력의 0/1 승격은 `domain/strategy/_promotion.py`(hydrate 가 canonical 그래프 끝에 `__promote_<factor>` 조건 노드와 상수 둘을 붙인다) | compile 은 매 호출 계약을 읽어 없는 `field_id`·그룹 연산 capability·단위를 실행과 같은 계약으로 판정한다. 그래프 밖 필드 참조(eligibility·유동성·레짐·리스크)는 모델 metadata `catalog: equity-field`(runtime schema `x-catalog` 의 원천)로 대상을 찾아 `strategy.field.missing`·`strategy.field.value_type` 을 낸다 — 대상 목록을 따로 적지 않는다("검증 통과 = 실행 가능"). 실행 경계의 `_reject_non_numeric_factor_outputs`는 방어선으로 남고 compile 통과 문서에서 발화하면 결함이다(`tests/integration/test_compile_gate_property.py`). 승격 노드는 사용자 문서(원문·tree)에 없고 spec·`spec_hash`·실행 계획에만 있다 — 화면이 문서 노드를 찾을 때 `__promote_` 접두사 노드는 문서에 없는 것이 정상이다. 화면은 접두사를 적지 않고 **backend wire 표식**으로 가른다(P3-01, BACKLOG-014·Phase 2 감사 #13): 실행 계획 설명(`POST /api/v1/factors/explain`)의 `synthesized_nodes`(`node_id`·`origin: "promotion"`·`role`)를 `_promotion.py`의 `synthesized_factor_nodes`가 그래프만 보고 낸다(걷어 낸 뒤 다시 승격해 같을 때만 인정한다). `PROMOTION_NODE_PREFIX` 는 예약 네임스페이스다: 문서가 이 접두사로 시작하는 node_id 를 쓰면 compile 이 `strategy.factor.reserved_node_id` error 로 거절하므로(`_validation.py`, 리뷰 #232 DEFECT-232-01) compile 된 spec 의 접두사 노드는 승격이 붙인 것뿐이다. 그래프만으로는 사용자가 쓴 같은 모양을 가를 수 없어서 거절이 이 표식의 전제다. `features/edit-strategy/model/use-execution-plans.ts`의 `compiledNodeOrigin`이 `promoted_output`을 `boolean-score`("참/거짓을 1/0으로", 소스 열기는 조건 노드의 predicate 인 원래 출력), `promotion_constant`를 `support`(숨김)로 부르고, 실행 계획·그래프 화면·디버거가 같은 함수를 읽는다(디버거는 문서 노드만 추적하므로 trace 요청·응답에는 붙인 노드가 나오지 않는다). 의미 diff 는 붙인 노드를 걷고 비교한다 — revision diff 는 `_promotion.py`의 `demote_boolean_factor_outputs`(승격의 정확한 역함수, 표시 전용)를 `_diff.py`가, 편집 중 draft diff 는 `diff-projection.ts`가 문서 tree 멤버십으로 걷는다. 승격은 사용자 그래프의 함수라 걷어 낸 두 payload 가 같으면 `spec_hash` 도 같다. 저장소 무결성 검사(`source_spec_hash`)는 어댑터 계약 없이 compile 한다: 어댑터를 바꿔도 저장본은 읽힌다. 원주가 판정도 필드 계약이 소유한다(BACKLOG-018): 분할·증자 조정 없는 원주가 필드는 계약의 `adjusted_field_id`(mock `ADJUSTED_FIELD_BY_RAW`, duckdb `FieldSpec.adjusted_field_id`, 지금은 `price.close` → `price.adj_close`)로 조정 짝을 알리고, `_validation.py`가 과거 세션을 읽는 연산자(`reads_past_sessions`)의 입력을 거슬러 원주가 잎을 찾으면 `strategy.field.unadjusted_price` warning 을 그 `field_id` 에 낸다. 목록을 validator 에 따로 적지 않는다 |

## 금지

- frontend에 팩터 공식, 지표 공식, 전략 validation 규칙, 서버 status transition을 복제하지 않는다.
- 저장된 서버 응답을 Redux/Zustand 같은 client store에 한 벌 더 두지 않는다.
- 파생 가능한 값, 실행 plan, generated code, composite score를 원본으로 저장하지 않는다.
- StrategySpec을 화면별 별도 포맷으로 만들지 않는다. YAML/JSON source ↔ StrategySpec ↔
  JSON/Form/Graph/Diff projection은 같은 `spec_hash`로 lossless round-trip해야 한다. 표현식 문자열
  DSL과 단위 literal은 v1 범위가 아니다 (`docs/superpowers/specs/2026-09-04-strategy-authoring-contract-adr.md`).
- canonical `spec_hash`와 semantic validation은 backend 응답만 신뢰한다. frontend가 만든 spec이나
  hash를 표시·실행에 쓰지 않는다.
- 캐시를 SoT로 취급하지 않는다. 캐시 키는 입력 spec hash, **실행 설정 `environment_hash`**, 데이터
  snapshot, registry/engine version, cost model, seed를 모두 포함한다. 결측 정책은 실행 설정으로
  옮긴 뒤에도 팩터 실행 plan의 일부라 `plan_hash`에 남는다 — 팩터 행렬 캐시가 결측 처리만 다른 두
  실행을 같은 키로 묶으면 두 번째 실행이 첫 번째 결과를 조용히 재사용한다.
- 실패·pruned trial을 결과에서 지우지 않는다. 전체 trial 수와 실패 이유는 audit 대상이다.
- frontend에 1.0 → 1.1 → 1.2 업그레이드 규칙과 필드 적용 조건표를 복제하지 않는다. 업그레이드는
  `POST /api/v1/strategy-documents/upgrade`가 돌려준 원문을 편집기 범위 교체 한 번으로 적용한다.
  AI 어시스턴트의 전략 제안도 같은 방식(편집기 전체 범위 교체 한 번, 문서가 바뀌었으면 적용 전 확인)으로만 적용한다.

같은 사실이 두 위치에서 변경되어야 한다면 구현을 멈추고 owner를 한 곳으로 합친다.
