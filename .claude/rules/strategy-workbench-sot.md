# Strategy Workbench의 사실은 한 곳만 소유한다

## 정본 대장

| 사실 | 유일한 owner | 나머지 레이어 |
|---|---|---|
| 원천 값·공개 시점·coverage | Equity DB view + `dataset_profile` | `EquityDataPort`와 `RawObservationPort` 두 포트로 조회하며, 같은 셀에 같은 값·공개일을 답하는 것이 어댑터 계약이다 |
| Equity 연결 계약 | backend application outbound port | adapter가 구현 |
| equity 필드 계약(단위·값 타입·랙·빈도) | 원장 `dataset_profile`(S19)이 정본이고, 원장 빌드가 그 표를 만드는 선언은 `database/src/equity`의 `rules_s*.py`다. duckdb 어댑터는 원장 스키마를 옮긴 선언표 `equity_duckdb/_specs.py`(`FIELD_SPECS`의 `FieldSpec`, `SOURCE_SPECS`의 `SourceSpec`)로 답하고, 랙은 부팅 때 `dataset_profile`의 `recommended_lag_sessions`를 읽어 적용한다 | mock(`equity_mock/_fixture.py`)은 단위·값 타입·빈도를 duckdb 선언표에, 랙을 원장 선언에 맞추고, 선언표의 값 타입은 원장 선언과 같다(#221·#243). compile 은 연결된 어댑터의 계약으로 단위·`field_missing`·값 타입을 판정하므로, 두 어댑터가 같은 field_id에 다른 계약을 답하면 mock 으로 green 인 문서가 실데이터에서만 다르게 동작한다. `tests/contract/test_equity_field_contract_parity.py`가 선언표와 원장 선언을 직접 읽어 대조한다. 대장에 행이 없는 필드의 폴백 랙(`SourceSpec.lag_sessions`, 원천 안에서 갈리면 `FieldSpec.lag_sessions`)은 원장 선언의 사본이고 `tests/contract/test_equity_fallback_lag.py`가 대조하며, 폴백을 쓰면 duckdb 어댑터가 부팅 때 `profile_lag_fallback` 경고를 한 번 남긴다(#255). 필드 목록·단위를 소비자에 따로 적지 않는다. 빈도 어휘는 어댑터가 `list_fields()` 로 내는 `domain/equity` 의 `FieldFrequency`(daily·monthly·quarterly·annual·event)이고 원장 `dataset_profile` 의 빈도 어휘(session·report 등)와 다르다 — 화면은 값마다 문구를 두고 생성 SDK 유니온으로 누락을 typecheck 가 막는다(#350). 백테스트 bar의 거래대금(`MarketBarRecord.trading_value`)은 `price.trading_value`와 같은 원천(`price_daily.value_krw`)·원화 단위이고, 질의의 워밍업(`BacktestDataQuery.history_sessions_before_start`) bar는 측정 구간 bar와 같은 거르기 규칙으로 `BacktestDataset.history_bars`에 따로 답하며 측정 구간 bar·경고를 바꾸지 않는다 — 두 어댑터의 답을 `tests/contract/test_backtest_data_port.py`가 대조한다(검증 랩 V2-02) |
| 재무 셀의 기간 선택과 흐름 계정 TTM | 원장 뷰 `database/src/equity/views.py`의 `v_fin_latest`: 흐름 계정(손익·현금흐름)을 회계기간 순서의 분기값 4개 합(`ttm_*`, #212)으로 세우고, 행마다 "그 공개일까지 공개된 가장 최근 기간인가"(`period_frontier`, #225)를 판정한다. TTM 이 완성되는 날(창 안 네 분기값 공개일의 max — `ttm_income_available_date`·`ttm_cf_available_date`, #238)도 뷰가 싣는다 | duckdb 어댑터(`equity_duckdb/_specs.py`의 `fin` 원천)는 `ttm_*` 열을 field_id에 매핑하고 `period_frontier`가 참인 행만 고른다. 흐름 5필드는 `FieldSpec.available_expr`로 그 공개일 열을 가리켜, 고른 기간의 TTM 이 아직 완성 전이면 그날까지 결측으로 둔다(다른 기간 값으로 대신하지 않는다, #212). 기간·합산·공개일 규칙을 어댑터에 다시 적지 않는다. #225·#238 전에 만든 카탈로그라 뷰에 이 열들이 없으면 재무 원천만 빼고 경고한다(#233). 부팅 때의 열 확인이 카탈로그·파일 성격의 duckdb 오류를 내면 그 원천만 빼고(`catalog_macro_unreadable`), 잠김·일시적 오류는 원천을 빼지 않고 코드화된 `EquityDuckdbSetupError` 로 올려 다음 부팅에서 다시 확인한다(#245·#247). 카탈로그 파일이나 meta(`_catalog_meta.json`)를 읽을 수 없으면 카탈로그가 없을 때처럼 매크로 원천을 모두 뺀다(`catalog_unreadable`, #278). 부팅 뒤 카탈로그가 잠긴 동안 도는 질의와 멈추는 질의는 `EQUITY_FIELD_MAP.md` §3 「부팅 검사」가 정본이다(#278). 손 픽스처 카탈로그(`LEDGER_MACROS`)도 본문을 옮겨 적지 않고 원장 템플릿을 렌더한다 |
| 신용잔고의 무상증자 척도 창(#249) | 원장 뷰 `database/src/equity/views.py`의 `v_credit_balance`: 권리락일(`corp_event.effective_date`)부터 `BONUS_SCALE_WINDOW_SESSIONS` 세션의 잔고를 결측(`fill_kind.kind='empty_response'`, 표시 `bonus_window`)으로 내고, 공시 접수일 다음 행부터만 가린다(PIT) | duckdb 어댑터(`equity_duckdb/_specs.py`의 `credit` 원천)는 이 뷰를 읽고 창 규칙을 다시 적지 않는다. 카탈로그가 없거나 낡으면 신용 원천을 빼며 표로 돌아가 읽지 않는다(가린 창이 조용히 다시 열린다). 팩터 `credit.margin_balance_change_20d`는 20세션 창 안에 결측이 하나라도 있으면 결측이라 그대로 따른다. mock 은 무상증자 사건 없이 가린 셀 하나(`MOCK_MASKED_CREDIT`)로 MASKED 만 흉내 낸다(#298). 손 픽스처 카탈로그(`tests/equity_fixture.py`의 `LEDGER_MACROS`)는 본문을 옮겨 적지 않고 원장 템플릿을 렌더한다 |
| 수정주가의 조정 공백(#220) | 원장 뷰 `database/src/equity/views.py`의 `v_adj_close`: S23 표 `price_adj_daily`의 `adj_close`를 그대로 내되, 원장이 그날 사건을 접지 못한 **적용일 행** — KRX 기준가로 적용일을 정한 ok 계수가 늦게 공개된 사건(`apply_basis = 'krx_base_price'` ∧ `available_date > apply_date`)과 `krx_base_inconsistent` — 을 결측(`adj_gap`)으로 낸다. 이 술어의 정본은 같은 파일의 `v_unfolded_event` 이고 백테스트 손익 경로도 같은 뷰를 읽는다(아래 #369 행). PIT 근거: 적용일의 KRX 기준가 재설정은 그날 가격 데이터(랙 0)에 이미 보이므로, 값을 바꾸지 않고 결측만 만드는 가림은 공개일을 기다리지 않는다. 예외: 그날 보이는 재설정 가운데 무엇을 가릴지는 다음 세션 정보(늦은 공시·주식수 랙 1)로 갈린다 — 영향은 적용일 as_of 에 랙 0 으로 그 행을 읽는 셀뿐이다(기본 12-1 모멘텀은 랙 21 이라 무관). 공개 전 계수를 접지 않는 fold 규칙은 S23 그대로다 | duckdb 어댑터(`equity_duckdb/_specs.py`의 `adj` 원천)는 이 뷰를 읽고 가림 규칙을 다시 적지 않는다. 가린 행은 원장이 가린 셀(MASKED)이다(아래 #298 행). 카탈로그 소비 규칙(없거나 낡거나 매크로가 없으면 원천을 빼고 표로 돌아가지 않는다)은 신용잔고 행과 같다. 표는 parquet 소비자와 조정 규칙의 저장본이라 그대로 둔다. `unknown_price_only`·명목일 사건은 가리지 않고 `backend/FACTORS.md`에 한계로 적는다 — 명목일·가격 매칭으로 적용일을 정한 늦은 ok 계수도 그날 기준가 재설정이 없어 PIT 근거가 서지 않으므로 가리지 않는다(#301 리뷰 P3-1). mock 에는 공백 사건이 없다 |
| 백테스트 bar 경로의 미조정 사건(#369) | 무엇이 원장이 접지 못한 사건인가는 원장 뷰 `database/src/equity/views.py`의 `v_unfolded_event`(위 #220 행과 같은 술어. `factor_ok` 는 그 (ticker, 적용일)에 층 이동을 설명하는 ok 계수가 있는가)가, 손익 경로의 처리는 duckdb 어댑터 `load_backtest_dataset`(`equity_duckdb/_adapter.py`)이 소유한다: `factor_ok` 가 거짓인 행을 적용일 KRX 기준가 비(앞 행 종가 ÷ `price_daily.base_price_krw`)만큼 보유 수량을 바꾸는 `split`·`reverse_split` 사건(`detail` 「원장 미접힘·기준가 비」)으로 싣고, 사건마다 WARNING `equity.unfolded_level_shift` 를 낸다 | 엔진은 원주가 × 조정 수량으로 평가하므로(#218 설계 결정 1) 사건 없이 bar 만 내면 층 배수가 곧 손익이다. 어댑터는 술어를 다시 적지 않는다 — 카탈로그가 없거나 낡거나 그 뷰가 없으면 표로 돌아가지 않고 백테스트를 멈춘다 — 포트 예외 `BacktestDataNotReadyError` 로 run 은 `backtest.run.data_not_ready` 로 끝나고, 조치(카탈로그 재생성 뒤 서버 재시작)는 사유 문장이 `catalog_*` 코드와 함께 말한다. 앞 행은 정지일 기준가 행을 포함한다: 원장 기준가 원천이 비를 재는 분모(`sql/adj_factor.sql` bp)와 같아 한 정지 구간의 재설정 여럿이 겹쳐 곱해지지 않는다. 기준가는 적용일 개장 전에 공표되는 값이라 수량 조정이 미래 가격을 읽지 않는다. 비를 세울 수 없으면(기준가·앞 행 없음) 조정하지 않고 경고만 낸다. 기존 분할·병합 경로를 그대로 타므로 엔진·벤치마크 곡선·충격 σ 에 새 분기가 없다. 두 어댑터가 bar 사이 층 배수를 사건으로 설명하는지는 `tests/contract/test_backtest_data_port.py` 가 본다(mock 에는 층 이동이 없다). `unknown_price_only`(유상 권리락 등)는 조정하지 않아 손익이 비관 쪽으로 남는다 — 한계는 `database/docs/EQUITY_FIELD_MAP.md` §3 이 적는다 |
| 원장이 가린 셀과 결측 정책(#298) | 무엇을 가리나는 원장 뷰(`database/src/equity/views.py`)가, 어느 열이 가림 표시인가는 같은 파일의 `MASK_COLUMNS`(`v_credit_balance.bonus_window`·`v_adj_close.adj_gap`)가, 가린 셀의 종류 `CellKind.MASKED`(값 없음)는 `domain/equity` 가, 무엇을 채우나는 평가기(`domain/factor/_evaluation.py` 의 `_field_values`)가 소유한다. 실행 결측 정책(`RunEnvironment.missing`)은 모르는 결측만 채우고 MASKED 셀은 비워 두어, 그 셀을 품는 창은 어느 정책에서나 결측이다. 가린 셀은 사건 경계라, 값이 대표하는 시점 구간에 가린 칸이 들면 결측이다 — 구간은 필드마다 잇고, `unary.lag` 는 옮기기만 하고 창 연산은 창만큼 넓히며 두 값을 섞는 연산(이항·비교·조건)은 두 구간을 덮는 구간이다. 이 규칙은 평가기의 `_value_spans`(구간)와 `_NodeEvaluator._masked_in`(가린 칸이 닿는 칸) 한 곳이 소유한다(#315·#337) | duckdb 어댑터는 `SourceSpec.masked_expr` 로 뷰의 가림 표시를 읽어 셀 종류만 정하고 가림 판단을 다시 적지 않는다. 그 배선이 `MASK_COLUMNS` 와 같은지는 `tests/contract/test_equity_field_contract_parity.py` 가 본다 — 한쪽만 있으면 가린 셀이 MISSING 으로 나가 결측 정책이 다시 채운다(#311 리뷰 P2-1). 가림 표시는 결측 사유보다 먼저다: 가림 창 안에서 원래 값이 없던 행(`not_collected`·`src_omitted`)도 MASKED 다(`_adapter._cell_kind`, 창의 값은 척도가 섞여 채우면 틀린다 — #311 리뷰 P3-1). 관측 변환(`_to_factor_observation`)과 팩터 관측 포트가 `FactorFieldValue.masked` 로 평가기까지 나른다. mock 은 원장이 가리는 필드에 같은 종류를 선언하고(`tests/contract/test_equity_field_contract_parity.py`), 두 어댑터가 가린 셀을 값 없는 MASKED 로 내는지는 `tests/contract/test_raw_observation_port.py` 가 본다. 추적 상태 `masked` 는 평가기가 노드마다 남긴 칸(`_NodeEvaluator.masked`)을 읽기만 하고 구간을 다시 계산하지 않는다(#350) |
| equity 산출 규칙 판본 | `database/src/equity/model.py`의 `RULES_VERSION`(`BuildRecord.rules_version`에 실린다). 언제 올리는가의 정본은 `database/docs/EQUITY_HANDOFF.md` §6 | 산출식·선언 컬럼·`field_profiles`·게이트 술어(`sql/*.sql`·`rules_*.py`)를 바꾸거나 선언면을 늘리면 같은 변경에서 판본을 올리고 `model.py` 주석 블록에 이력을 한 줄 남긴다. 판본을 안 올리고 산출을 바꾸면 재현성 게이트 EG5a 가 새 판을 폐기한다 |

## 금지

- frontend에 팩터 공식, 지표 공식, 전략 validation 규칙, 서버 status transition을 복제하지 않는다.
- 저장된 서버 응답을 Redux/Zustand 같은 client store에 한 벌 더 두지 않는다.
- 파생 가능한 값, 실행 plan, generated code, composite score를 원본으로 저장하지 않는다.
- StrategySpec을 화면별 별도 포맷으로 만들지 않는다. YAML/JSON source ↔ StrategySpec ↔
  JSON/Form/Graph/Diff projection은 같은 `spec_hash`로 lossless round-trip해야 한다. 표현식 문자열
  DSL과 단위 literal은 v1 범위가 아니다 (`docs/superpowers/specs/2026-09-04-strategy-authoring-contract-adr.md`).
- canonical `spec_hash`와 semantic validation은 backend 응답만 신뢰한다. frontend가 만든 spec이나
  hash를 표시·실행에 쓰지 않는다.
- 캐시를 SoT로 취급하지 않는다. 캐시 키는 입력 spec hash, **실행 설정 `environment_hash`**, **해소된
  파라미터 값**(spec D4 — 실행 지문은 `run_spec.parameter_values`, 팩터 행렬 캐시 키는 `parameters`), 데이터
  snapshot(필드 계약 판 포함, #235), registry/engine version, cost model, seed를 모두 포함한다. frontend 추적 결과 캐시
  키(`prepareStrategyTrace` 의 `ownerKey`)는 요청에 싣는 값 전부(실행 설정 포함)로 만들고 요청 칸을 따로 골라 적지 않는다
  — 실행 설정이 빠져 옛 추적이 새 설정의 결과로 보였다(#351). 결측 정책은 실행 설정으로
  옮긴 뒤에도 팩터 실행 plan의 일부라 `plan_hash`에 남는다 — 팩터 행렬 캐시가 결측 처리만 다른 두
  실행을 같은 키로 묶으면 두 번째 실행이 첫 번째 결과를 조용히 재사용한다.
- 실패·pruned trial을 결과에서 지우지 않는다. 전체 trial 수와 실패 이유는 audit 대상이다.
- frontend에 1.0 → 1.1 → 1.2 업그레이드 규칙과 필드 적용 조건표를 복제하지 않는다. 업그레이드는
  `POST /api/v1/strategy-documents/upgrade`가 돌려준 원문을 편집기 범위 교체 한 번으로 적용한다.
  AI 어시스턴트의 전략 제안도 같은 방식(편집기 전체 범위 교체 한 번, 문서가 바뀌었으면 적용 전 확인)으로만 적용한다.

같은 사실이 두 위치에서 변경되어야 한다면 구현을 멈추고 owner를 한 곳으로 합친다.
