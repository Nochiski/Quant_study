# 실데이터 확인 절차와 열람 기록

2026-10-17 사용자 결정: 기능을 구현할 때마다 실데이터를 연결해 **우선** 확인한다. mock(합성 종목 3개)
테스트는 계약·회귀를 지키지만, 실원장 규모·결측·기업행동·소요 시간에서만 드러나는 문제를 보지 못한다(예:
팩터 회귀는 mock 에서 늘 "관측 부족"으로 끝나 계산 경로가 실제로 돈 적이 없었다).

## 절차

1. 로컬 원장(`~/quant-ledger/data/equity`, `_catalog_meta.json` 이 있는 루트)에 연결한 서버를 **별도 포트·별도 DB
   경로**로 띄운다. 개발 서버(8000)·e2e(8710)와 상태를 섞지 않는다.

   ```bash
   S=<scratch 폴더>
   cd backend && \
   STRATEGY_WORKBENCH_EQUITY_ADAPTER=duckdb \
   STRATEGY_WORKBENCH_EQUITY_ROOT=$HOME/quant-ledger/data/equity \
   STRATEGY_WORKBENCH_DB_PATH=$S/strategy.sqlite3 \
   STRATEGY_WORKBENCH_RESEARCH_DB_PATH=$S/research.sqlite3 \
   STRATEGY_WORKBENCH_CONTINUOUS_DB_PATH=$S/continuous.sqlite3 \
   STRATEGY_WORKBENCH_ARTIFACT_ROOT=$S/artifacts \
   STRATEGY_WORKBENCH_ASSISTANT_DB_PATH=$S/assistant.sqlite3 \
   STRATEGY_WORKBENCH_ASSISTANT_SECRETS_PATH=$S/secrets.json \
   STRATEGY_WORKBENCH_CREDENTIALS_ENV_PATH=$S/auto_trading.env \
   STRATEGY_WORKBENCH_ASSISTANT_FAKE_PROVIDER=1 \
   uv run --no-sync server --port 8720
   ```

2. 그 기능의 사용자 경로를 끝까지 돌린다(HTTP 또는 화면). 계산이 끝나는가, 값이 채워지는가, 비는 칸이 있으면
   그 사유가 무엇인가, 걸린 시간을 본다. 화면이 있는 기능은 opt-in e2e project(`E2E_REAL_EQUITY_ROOT`)나 실데이터
   서버에 붙인 화면으로 한 번 연다.
3. 아래 열람 기록에 한 줄 남기고 PR 본문 테스트 계획의 "실데이터 확인" 칸에 같은 내용을 적는다.

## 규칙

- 구간은 연구 하한 2020-01-02 이후만 쓴다. 봉인 구간(2016-01-01 ~ 2019-12-31)은 어떤 결과도 보지 않는다
  (`.claude/rules/holdout-window.md`). 워밍업 읽기는 제약 밖이다.
- 기술 확인이지 성과 판정이 아니다. 본 수치로 전략·설계·기준을 바꾸면 그 사실을 기록에 남긴다 — 이미 본
  구간은 탐색 표본이다(연구 로드맵 6절).
- 실원장·보존본(S01)을 고치거나 다시 짓지 않는다. 키움·실계좌는 이 절차의 범위 밖이다.
- 원장 판(`data_snapshot_id`)을 기록한다. 같은 확인을 다시 하면 판이 바뀌었는지부터 본다.

## 기능별 인계와 미실행 범위

2026-10-18 #546 회귀 접수 상한과 #548 선택 파라미터 배선의 기술 확인은 아래 각 행의 snapshot·기간·실제 관측 범위에 한정한다.
#546·#548은 머지됐다. 머지된 #547은 V6 합성 모의 core이며 실자료 기술 QA가 아니다. #549·#550·#551도 각각 main
`45328d0b`·`366dc241`·`c2f46dfb`로 머지됐고 각 12개 검사가 통과했다. 아래 실행 기록은 해당 QA 당시의 입력과
근거이며 최종 CI에서 실자료 QA를 새로 수행했다는 뜻은 아니다.
후속 V5-04 후보 지도·V5-06 비용/회귀 화면·V5-07 IDE 진입점의 합성 회귀나 mock 브라우저 통과를
새 실자료 과업 통과로 대신하지 않는다. IDE의 짧은 선택 실행→현재 환경→실험 미리 계산 QA는 아래 실제 실행·메타데이터 근거로 기록한다. 짧은 기간이 기존 학습/검증 분할에 부족하면 명시적 거절도 기술 확인 대상이며,
성공한 실험 접수로 적지 않는다. V6 합성 모의 core는 실자료 QA나 실제 봉인 개봉을 수행하지 않는다.

수익성 평가는 2026-10-19 주간 예정인 별도 사전 명세 연구다. 아래 골든 fixture 결과나 화면 연결의
기술 확인을 S03 신호 채택·S04 비용 후 계좌 성과 검증으로 올리지 않는다.
