# V5-04 파라미터 지도와 명시적 후보 선택

## 의도와 범위

최종 목적은 비용 후 수익을 내는 자동매매이며, 이 화면은 최고 숫자 한 칸만 보고 설정을 고르는 실수를
줄이는 도구다. US-CS-10의 흐름은 실험 지도 → 칸 점수·주변 평균·민감도 비교 → 학습 창과 이유 명시 →
서버 선택 기록 → 그 실행의 결과 검증 카드다. 추천은 수익 보장이나 실거래 허가가 아니다.

이 문서는 구현 범위와 검증 근거를 기록한다. ROOT의 실제 mock 브라우저·PNG 확인은 완료했으며,
실자료 기술 QA와 메타 보존도 완료했으며 공식 CI·머지는 별도 게이트다. PLAN의 V5-04 완료나 검증 랩 전체 완료를 선언하지 않는다. 키움·실계좌·주문 전송,
봉인 열람·S01 보존본 갱신·실자료 수익성 판정은 범위 밖이다.

## 정본과 책임

- 계약 정본은 [설계 D9](../../superpowers/specs/2026-09-29-validation-lab-design.md)와
  [WORKFLOW V4-03·V5-04](./WORKFLOW.md)다. 칸 판정·추천 양수 경계·이웃 평균·민감도는 기존
  `domain/experiment/_plateau.py`가 소유한다. 화면은 서버 값과 판정을 표시하며 점수나 후보를 다시 고르지 않는다.
- `GET /api/v1/experiments/{id}/parameter-map`의 `cells`·`no_recommendation`은 기존 entity query가
  소유한다. 생성 SDK의 `CellPlateau`·`CellVerdict`·`ExperimentSelectionRequest`를 그대로 쓴다.
- `POST /api/v1/experiments/{id}/selections`는 기존 `ExperimentRunService.select`를 호출한다.
  프론트는 사용자가 고른 `trial_index`와 이유만 전달한다. 허용 여부는 `ExperimentTrialState.selectable`과
  서버의 최종 거절이 소유한다. 학습 완료 뒤 검증 실행이 남아 있을 수 있으므로 `Experiment.finished`로
  선택 조건을 다시 정의하지 않는다. API가 허용하는 취소 후 선택 정책도 바꾸지 않는다.
- 기록한 N·DSR·원장 대표 샤프·시점은 `ExperimentSelection` 스냅숏이다. 현재 계열 원장 query로
  재계산하거나 덮어쓰지 않는다. 대표 샤프를 선택한 학습 창 실행의 샤프라고 부르지 않는다.
- 선택 응답에는 run ID가 없으므로 해당 `trial_index`의 기존 최신 attempt run 링크를 사용한다.
  완료 trial은 기존 재시도 대상이 아니다. 결과 화면의 검증 카드는 조회 시점의 원장 값임을 기존대로 안내한다.
- V5-02의 선택 파라미터 추적·미리보기 연결과 워크포워드 창별 자동 선택을 유지한다.
  지도 추천과 창별 자동 선택은 목적과 정책이 달라 서로 다를 수 있다.

## 읽기와 조작

- 추천·봉우리·점수 있음·실패/파산·점수 없음은 글자와 배경을 함께 사용한다. 실패/파산은 빗금을
  더하며 실제 파산 여부는 trial의 서버 상태로 설명한다. 값이 0인 칸은 점수 없음으로 바꾸지 않는다.
- 기본 지도는 서버 고원 점수를 7단계 상대색으로 읽으며 칸 점수로 명시 전환할 수 있다. 전체 실험의
  유효값 min/max를 표시용으로 구간화하며 페이지·고정값으로 범례를 다시 잡지 않는다. 이는 차트 색일 뿐
  추천·금융 통계를 다시 계산하지 않는다. 같은 값은 중간 한 색, 결측·실패/파산은 별도 상태·빗금이며
  추천은 실선, 봉우리는 점선 윤곽·문구다. 기본 min/max와 펼친 실제 구간 범례를 읽고 진한 색을 수익으로 해석하지 않는다.
  비교 상세에는 칸 점수·고원 점수·민감도 원수치와 실제 `sensitivity_cell`을 읽는다. 비교 칸 버튼은 그 좌표로 이동한다.
- 0축은 한 칸, 1축은 한 줄로 표시한다. 다축은 가로·세로축을 명시하고 나머지 축 값을 native select로
  고정한다. 탐색하지 않은 기본 파라미터도 접힌 고정값에서 읽는다. 표시 단면을 바꾸어도 판정은 전체 실험 기준이다.
- 각 표시 축은 6개 값씩 페이지 처리하여 최대 36칸을 렌더한다. 표만 이름과 키보드 초점이 있는 가로
  스크롤을 가지며 문서 전체가 가로로 넘치지 않게 한다. 기존 서버 응답은 전체 cells이며 새 네트워크
  페이지 API를 만들지 않는다. 이 제한은 DOM 표시량의 제한이지 서버 계산·응답량 최적화는 아니다.
- 칸은 native button이고 Enter/Space로 비교 상세를 연다. 학습 창은 자동 확정하지 않으며 사용자가
  native select에서 명시하고 이유를 적는다. 선택 기록은 되돌릴 수 없다고 제출 전에 안내한다.
  성공하면 당시 통계와 분명한 결과 검증 카드 링크를 제공한다.
- 다른 실험으로 이동하면 칸·학습 창·이유가 이전 실험에서 넘어오지 않는다. 지도 응답은 실험별
  query key가 소유한다. 조회 실패는 명시 재조회, 오래된 선택 허용 상태의 409 거절은 공통 코드 번역과
  접힌 서버 원문으로 표시하며 사용자가 적은 이유는 보존한다.

## 검증과 남은 게이트

대상 MSW 회귀는 최고 점수와 별개인 양수 추천·봉우리 fixture, 0 이하 추천 없음, 실패/파산,
0축·다축·페이지 전환, 명시 선택 payload, 미완료/실패 거절, 스냅숏과 다른 실험의 지연 응답 경계를 검사한다.
CSS class 존재나 점수 공식을 복제하는 검사는 추가하지 않는다.
색 표시의 범위·결측·동일값은 별도 UI 투영 회귀가 지킨다. 실제 토큰의 숫자 대비는 라이트 최저 5.14:1,
다크 최저 6.80:1로 확인했다. 이는 색/문자 정적 검사이며 실제 화면의 읽기 공간 확인을 대신하지 않는다.

ROOT의 전체 프론트 단위 1,478개가 통과했다. 후속 조회 실패 정책 보완은 관련 12개 단위 회귀로
확인했다. 두 결과는 중복 범위이므로 합산하지 않는다. 진행 중 503 이후에는 타이머와 실험 prefix
invalidate도 자동 GET을 만들지 않고 명시 재조회로 복구하는 것을 포함한다. query의 오류 상태만
사용하며 재마운트·focus·reconnect 자동 재조회도 막는다. 프론트/E2E 타입·변경 파일 lint가 통과했다.

`frontend/e2e/stories/cs.candidate-map.spec.ts`의 실제 mock 실험은 1440×640 라이트·360×640 다크
두 시나리오 모두 통과했다(2.6분). ROOT가 지도·선택 이유·범례 PNG를 직접 확인했다. 지도·원수치 비교,
키보드 선택·이유 기록·서버 스냅숏 보존·결과 카드 이동을 확인했으며 CS10 상태와 생성 traceability에
반영했다. 이는 실자료 수익성이나 전체 CI 통과를 뜻하지 않는다.

초기 시도에는 신규 fixture의 두 오류가 있었다. 첫째, 합성 그래프의 `scaled + offset`이 단위 불일치로
저장 422를 반환하여 마지막 연산을 곱셈으로 수정하고 기존 authoring compiler에서 진단 0을 확인했다.
둘째, 공용 hold 15초를 고려하지 않은 60초 완료 대기가 실패했다. 최소 2×2 격자 한 창은 직렬 학습
4회와 선택 검증 최대 1회이므로, 공용 `TRIAL_HOLD_SECONDS` 기준 75초에 엔진·HTTP 여유 30초를 더한
105초 대기와 UI 과업 30초를 더한 135초 case 예산으로 수정했다. 서버가 만든 1창·2축·각 2값도
단언한다. 공용 hold·슬롯·기존 회귀·제품 예산을 바꾸거나 실제 DOM/API 단언을 완화하지 않았다.

별도 실자료 기술 QA는 [REAL-DATA-CHECKS](./REAL-DATA-CHECKS.md)에 따라 격리 DB/서버에서
2020-01-02 이후만 사용한다. 이 구현 작업 자체는 사용자 원장·서버·브라우저를 열지 않는다.
`frontend/e2e/candidate-map/workbench.real-equity.spec.ts`는 기존 최소 split 계약에 맞춘 2023~2024
1개 창·3세션 모멘텀×scale ±1 두 칸의 opt-in 시나리오다. ROOT 초기 기술 QA는 1개 통과(1.8분,
`browser-real.log`)했으나 최초 첨부에는 데이터 판 식별이 빠져 있었다. 기존 GET 결과 응답의 Manifest와
검증 보고서, 지도·trial 원문 첨부를 보강한 최종 재실행도 1개 통과(1.7분, `browser-real-final.log`)했다.
선택·기간·기준·기존 단언·시간 예산은 유지했으며 같은 실행의 식별 근거 보존을 위한 재검증이다.

최종 원문의 데이터 판은 `2164ba776cbd99f2:3d4aa095f7837c29`, 실행은
`400bad21-83cc-4acb-a5db-ad01850d56ff`다. 결과와 검증 보고서의 실행 지문이 같고, 저장 전략의
ID·리비전·spec/source hash와 선택 파라미터가 Manifest와 일치한다. 선택 당시 N=2, DSR·대표 샤프·이유와
영속 선택 기록을 확인했다. 이는 원수치 전달·선택 기록의 기술 검증이며 실자료 수익성 판정이 아니다.
외부 `candidate-map-20261018/real-metadata-final/`에 최종 test-results·HTML 보고서·내장 ZIP과
`technical-selection-inputs.json`을 보존했다. `raw-attachment-provenance.json`은 원본 보고서 경로·ZIP
entry·보고서/ZIP/첨부 SHA256을 기록한다. 초기 1.8분 증거는 `real-final/`에 별도로 유지한다.
