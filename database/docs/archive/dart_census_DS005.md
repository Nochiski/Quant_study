# DART 전수조사 — DS005 주요사항보고서 주요정보

조사일 2026-08-24 · **실사용 콜 25 / 예산 25**

## 요약 (먼저 읽을 것)

1. **DS005 는 36개 엔드포인트다.** 공식 가이드(`guide/main.do?apiGrpCd=DS005`)에서 36개 전부 목록 확보 — 추정 아님.
   URL 경로 36개는 **개별 상세 페이지에서 1:1 확인**했다(미검증 추측 없음).
2. **파라미터가 다른 카테고리와 다르다.** `bsns_year`·`reprt_code` 를 **안 쓴다.**
   전 엔드포인트 공통 = `corp_code` + `bgn_de` + `end_de` (4개 모두 필수, crtfc_key 포함).
3. **날짜 범위 상한이 없다 (실측).** `bgn_de=19990101&end_de=20260824` 한 콜로 전체 이력이 온다.
   → **연도 루프 불필요.** `irdsSttus` 처럼 매년 받아야 하는 문제가 없다. 종목당 1콜 = 전체 이력.
4. **데이터 하한은 대략 2015년 (실측).** 관측된 최소 rcept_no = `20150318…`(신한지주 코코본드).
   삼성전자 자기주식취득도 `20151029` 이 최초 — 삼성전자는 그 이전에도 자사주를 샀으므로
   이는 종목 특성이 아니라 **DS005 자체의 소급 한계**로 보인다. `fnlttSinglAcntAll` 의 FY2015 하한과 일치.
   (미확인: 2015년이 하드 경계인지 공식 문서로는 확인 못 함. 실측 최소치만 보고한다.)
5. **자연 PK = `rcept_no` 단독.** 데이터가 온 10개 엔드포인트 전부에서 중복 0 (15/15, 21/21, 8/8, 4/4 …) — 실제 중복검사 수행함.
6. **013(무자료)이 매우 흔하다.** 프로브한 24개 중 14개가 013. 이건 엔드포인트 결함이 아니라
   **이벤트가 실제로 희귀**하기 때문이다. 종목 단위로는 대부분 비어 있는 게 정상.

## ⚠ 수집 설계에 직결되는 함정: 정정공시가 별도 행으로 온다

**실측 증거 — `crDecsn` / KG모빌리티(구 쌍용자동차):**

| rcept_no | bddd(이사회결의일) | 감자비율 | 감자전 발행주식수 |
|---|---|---|---|
| `20220831000768` | 2022년 08월 31일 | 67.18 | 149,840,002 |
| `20220923000279` | 2022년 08월 31일 | 68.37 | 142,487,104 |

**같은 이사회결의일(bddd)인데 rcept_no 와 숫자가 다르다.** 뒤쪽이 정정공시다.
`rcept_no` 는 유일하지만 **경제적 이벤트 1건이 N행으로 존재**한다.

- 이벤트 스터디에서 그냥 전 행을 쓰면 **같은 감자를 두 번 카운트**한다.
- 최신값만 쓰면 **최초 공시 시점(=주가 반응 시점)을 잃는다.**
- → 저장은 전 행(`rcept_no` PK), 사용 시 `(corp_code, bddd)` 로 묶어
  **최초 rcept_no = 이벤트 발생시각**, **최대 rcept_no = 확정 수치**로 분리해야 한다.

**반례 주의 — 정정이 아닌 동일자 복수건도 있다.**
`cvbdIsDecsn`/신라젠: `20200423000193`(bd_tm=**31**회차) 과 `20200423000196`(bd_tm=**32**회차) 은
같은 날 발행한 **서로 다른 회차**다. 정정이 아니다.
→ `(corp_code, bddd)` 단독 묶음은 위험. 사채류는 **회차(`bd_tm`)를 반드시 키에 포함**해야 한다.

## 스키마 설계 권고

- 엔드포인트별 **개별 테이블**. 필드가 9~86개로 편차가 크고 의미가 전혀 달라 통합은 손해.
- 공통 PK: `rcept_no` (단독으로 유일 — 실측).
- 공통 인덱스: `(corp_code, bddd)` — 정정공시 묶음용. 사채류는 `(corp_code, bddd, bd_tm)`.
- 전 필드 **문자열 원본 보존** 후 파생 컬럼 생성. 날짜가 `"2016년 01월 28일"` 형식이고
  수치가 `"2,467,500,000,000"`, 결측이 `"-"` 다. `api.num()` 이 `"-"` → None 처리하므로 그대로 쓸 수 있다.
- `corp_cls` 로 유가/코스닥 분리 저장 불필요 — 컬럼으로 두고 필터.
