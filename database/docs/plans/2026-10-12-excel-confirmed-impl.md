## 3. 공통 진행 방식

- 묶음마다: 실패하는 대조 테스트 먼저 → 구현 → 대조 통과 → 전체 테스트(`uv run --project backend pytest database/tests -q`) → 서버 dry-run(발송 없이 임시 out-root, 원장 장부 3줄 유지) → 커밋.
- 구현은 하위 에이전트에 묶음 단위로 맡기고 매 묶음 뒤 명세 대조 · 코드 품질 리뷰 두 번(대조 기준 파일과 이 플랜을 그대로 넘김).
- 서버에서는 읽기만(원장 · equity · raw), 임시 폴더는 쓰고 지움.
