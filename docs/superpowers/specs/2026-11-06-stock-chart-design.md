- **차트**: SVG를 px 좌표로 그린다(ResizeObserver). 축·배지·라벨 글자 12px 이상 고정. 색 역할: 내 선 = 잉크 실선,

  자동 선은 생긴 날(확정일) 이전 구간을 옅게 그린다. 오른쪽 축 배지는 현재가와 **한 선**(고른 선, 없으면 포인터를 올린
  선)의 레벨만 단다 — 나머지 선은 선 위 라벨만 보인다(선마다 배지를 달면 축에 레벨 수십 개가 쌓인다). 배지가 겹치면 세로로
  밀어내고 가는 선으로 원래 가격을 가리킨다. 레벨 라벨은 가로로 가까운 라벨끼리 세로로 밀어내고, 그림 칸 밖으로 나가면
  안쪽으로 들인다(시작점이 왼쪽 밖이면 선이 칸에 들어오는 자리). 라벨 halo는 `--surface-panel`.
- **줌·이동(TradingView 관례)**: 휠 = 커서 자리 중심 확대·축소(봉 간격), 가로 스크롤·Shift+휠 = 이동, 선택 도구에서 빈 곳
  끌기 = 좌우 이동(손잡이를 잡으면 손잡이 끌기, 그리기 도구 중에는 끌기 이동 없음), 선택 도구에서 빈 곳 더블클릭 = 고른
  기간 버튼(없으면 기본 2년)의 기본 보기. 종목·주기를 바꾸면 날짜(앞 계열의 줌 구간)를 비우고 기간 버튼의 기본 보기로 연다.
  날짜 칸이 봉 없는 기간(상장 전 등)이면 빈 안내에 "고른 기간으로 돌아가기" 버튼을 둔다. 기본 보기는 기간의 마지막 봉을 오른쪽에 붙이고 최신 봉이면 미래 봉 여백(보이는 봉의 8%, 적어도 3봉)을
  둔다. 보이는 봉 칸은 10개 ~ 계열의 1.25배(봉이 적으면 기본 보기 폭 이상), 한쪽 빈칸은 보기의 절반까지이고 기본 보기도 이
  한도 안이다. 가격 축은 보이는 봉의 고가·저가에 맞춘다(가격
  축 끌기 세로 배율은 아직 없다). 차트(SVG)는 Tab 정지이고 +/=·− 확대·축소, ←/→ 이동, Home/0 되돌림이며 보이는 구간

## 3. 데이터 (원장 → 캔들)

- 종목: `price_adj_daily`의 전방 조정 OHLC(`adj_*`)를 그 티커의 마지막 상장 구간(`security_span`의 마지막 `span_seq`)
  첫날 이후로 읽는다 — 재상장(티커 재사용)은 새 구간이라 옛 종목 가격이 빠지고, 이전상장(코스닥→코스피 등)은 구간이
  이어져 `security.list_date`(새 시장 상장일)보다 앞 이력도 남는다. 구간이 없는 종목(ETF 등)은 하한 없이 읽는다.
  기준가·정지일은 `price_daily.price_kind == "reference"`로, 저녁 잠정 행은 `basis <> 'krx'`로 걸러낸다(조인). 전방 조정이라 새 기업행위가 생겨도 과거 값이 바뀌지 않는다.
- 지수: `index_daily`의 `open_idx/high_idx/low_idx/close_idx`.
- **표시 배율**: 화면 가격 = 저장 좌표 × `k`, `k = 마지막 실제 종가 ÷ 마지막 전방 조정 종가`(지수는 1). 선의 가격 좌표는
  전방 조정 공간에 저장하므로 새 분할이 생겨도 선과 캔들이 함께 움직인다. 사용자가 입력한 가격은 ÷k 해서 저장한다.
- 주봉·월봉: 같은 주(월~금)·같은 달의 일봉을 묶는다. 시가 = 첫 일봉 시가, 고가 = 최대, 저가 = 최소, 종가 = 마지막 종가.
  봉 날짜는 그 기간의 첫 거래일, 봉 끝은 마지막 거래일. 기준일이 기간 중간이면 그 봉은 **진행 중**이며 판정·확인 봉에
  쓰지 않는다(표시만).
  - 주는 ISO 주(월~일)라 연말에 걸친 주도 한 봉이다. 진행 중은 마지막 묶음만이고, 기준일이 그 기간의 마지막 평일(주 =
    금요일, 월 = 그 달 마지막 평일)보다 앞이면 진행 중이다. 그 평일이 휴장이면 다음 기간 봉이 생길 때까지 진행 중으로
    남는다(달력만 보는 보수 판정). 일봉은 진행 중이 없다. 일봉이 오름차순·중복 없음이 아니거나 기준일 뒤 일봉이 있으면
    거절한다(룩어헤드).
  - 기준일 `as_of` = **원장의 최신 확정 거래일**(달력 날짜도, 저녁 잠정 행만 있는 날도 아니다 — `price_daily`에
    `basis = 'krx'` 행이 있는 마지막 장, 종목·지수 공통). PR2가 원장에서 읽어 넘긴다. 그래서 금요일 데이터가 아직
    없는(목요일이 최신) 주는 진행 중이고, 시장은 금요일에 열렸는데 이 종목만 거래가 없었으면(정지) 그 주는 끝난 봉이다.
- 묶기·배율 규칙은 domain 순수 함수가 소유하고 어댑터는 일봉 행만 나른다.

## 4. 분석 규칙 (domain이 정본, frontend는 복제하지 않는다)

입력은 완성된 봉 배열(진행 중 봉 제외)과 파라미터다. 모든 값은 봉 t 시점까지의 정보로만 정한다.

### 4.1 ATR와 피벗
- ATR(14): True Range의 Wilder 평활. 첫 14봉은 그때까지 TR의 단순 평균이다(`TR_0 = H_0 − L_0`, 그래서 첫 봉부터 값이 있다).
- 피벗(스윙 민감도 k, 최소 확인 봉 R=2): 고점 후보 i는 그 뒤 더 높은 고가가 나오면 바뀐다. 확정 봉 t =
  `t ≥ i+R` 이고 `H_i − min(L_(i,t]) ≥ k·ATR_t` 인 첫 봉(저점은 대칭). 확정 뒤에는 반대 방향 추적을 (i, t] 의 극값에서
  다시 시작한다. 원장 전체 시계열에서 계산하고 화면 구간으로 자른다(시작 봉 의존 제거).
  - 첫 피벗 전에는 고점·저점 후보를 함께 추적하고, 같은 봉에서 둘 다 확정 조건을 채우면 고점을 먼저 본다. 후보는 더 높은
    고가(저점은 더 낮은 저가)만 바꾼다 — 같은 값이면 먼저 나온 봉이 남는다.
- 한 봉에서는 피벗이 많아야 하나 확정된다. ATR_t = 0인 봉(가격이 한 번도 움직이지 않은 계열)에서는 확정하지 않는다.
- 후보용 k = 1.0, 구조 판정용(큰 스윙) k = 2.0. 사용자가 바꿀 수 있다.

### 4.2 국면 판정 (채널 추천)
- S = `ln(C_끝/C_시작) / (s_r·√m)`, m = 봉 수 − 1, s_r = 봉별 로그수익률 표본 표준편차. 평균 로그수익률의 t값과 같은 식이라
  봉 수가 달라도 뜻이 같다(무작위 보행에서 |S|≥2 비율 ≈ 5%, 아래 시뮬레이션 확인).
- 구조: 큰 스윙 확정 피벗 중 구간 안에서 구간 끝까지 확정된 마지막 고점 2·저점 2 → HH·HL(상승) / LH·LL(하락) / 섞임 / 부족.
  고점이나 저점이 같은 값이면 HH도 LH도 아니라 섞임이다.
- 박스 비율 B = `(구간 최고가 − 최저가) / (ATR_끝 · √N)`.
- 판정(상호배타·완전):
  1. N < 20 → **판정 불가**(`too_few_bars`). 퇴화 입력 — 종가가 전부 같아 s_r = 0이거나 ATR_끝 = 0 → **판정 불가**
     (`degenerate`). 판정 불가면 S·B를 내보내지 않는다(±∞ 없음).
  2. |S| < 1 → B ≤ B* 이면 **박스권**(채널 대신 수평 구간 권장), 아니면 **방향 미확인**(구간을 나눠 보라)
  3. 1 ≤ |S| < 2 → **보류**
  4. |S| ≥ 2 → 구조가 같은 방향이면 **상승/하락**, 아니면 **보류**
- 판정 불가·보류에는 사유 코드가 붙는다: `too_few_bars`·`degenerate`, `weak_strength`(1 ≤ |S| < 2),
  `structure_mismatch`(|S| ≥ 2인데 구조가 다르거나 부족). 추천 채널 방향은 `RegimeJudgement.channel_direction` 하나가
  정한다(상승 → up, 하락 → down, 나머지는 추천 없음).
- **사용자 대면 문장의 owner = `domain/chart_analysis`**. 이 PR은 판정·사유 코드와 수치만 돌려주고, 문장은 PR2에서 이
  노드가 그 코드·수치로 완성한다. `application/stock_chart`는 그대로 실어 나르고 frontend는 표시만 한다(다시 조립하지
  않는다). application이 아니라 domain에 두는 이유: error-messages 규칙이 "문장의 owner는 그 진단을 만드는 모듈"이라고
  정하고, 홈 시장 요약 문장(`domain/market`의 `flow_summary`)이 같은 선례이며, 문장이 인용하는 임계(`FLAT_STRENGTH`·
  `TREND_STRENGTH`·`BOX_RATIO_MAX`)의 owner가 domain이라 application에 두면 임계를 옮겨 적거나 판정을 다시 하게 된다.
- **B\* = 0.73**. 무작위 보행 시뮬레이션(봉 하나 = 256단계 가우스 경로, 시가 = 직전 종가·갭 없음, 봉 σ 1%, ATR이 자리
  잡도록 앞 60봉, N봉 창은 끝에서 자름, N마다 20,000 경로, seed 20261106+N)의 박스권 비율(= |S| < 1 ∧ B ≤ B\*):

  정규화해서 어느 B\*든 N 사이 차이가 1%p 안이다 — "N마다 비슷하게"는 √N 정규화가 보장하고, 값은 무작위 보행의 박스권
  비율이 N=20·52·104 모두 12~15%(가운데 약 14%)가 되도록 골랐다. 방향 없는 무작위 보행(|S| < 1) 가운데 약 20%(B 분포의
  하위 10~25% 사이, 하위 25%가 0.76)만 박스권이라 부르는 보수적인 값이다.

    B\*에서 박스권이 적게 나온다(0.8에서 12% → 256단계에서 23%). 256단계에서 B\*를 다시 정했다.
  - 실제 종목은 갭 때문에 TR이 커서 같은 B\*에서 박스권이 이보다 조금 많이 나온다.
  - 표는 `backend/tests/domain/test_chart_analysis_regime_simulation.py`를 스크립트로 돌린 결과다(`uv run python
    tests/domain/test_chart_analysis_regime_simulation.py`, 약 1분). 모형(경로 생성)의 owner가 그 파일 하나라 표와 테스트가
    같은 모형을 쓴다. 테스트는 같은 256단계 모형을 N마다 500 경로로 줄여 판정 함수로 돌린다(약 1.5초) — 단계 수를 줄이면
    위 이유로 박스권 비율이 달라져 다른 모형을 검사하게 되므로 경로 수만 줄였다.
- 기본("오늘") 판정 구간 = 기준일에서 끝나는 고정 길이로, 주기별 자동 제안 칩의 가운데 값이다(`WindowPreset.default_bars`):
  일 60/**120**/250, 주 26/**52**/104, 월 12/**36**/60. 이 상수의 owner는 domain 하나다.
- 판정 구간 출처 `window_source`(domain `WindowSource`): 자동 제안 칩 길이 그대로면 `preset`, 사용자가 테두리를 끌거나
  날짜를 고치면 `user`.
- 시작·끝 봉이 확정 피벗 ±R봉 안이면 "극값에서 시작/끝 — 치우침" 경고(`starts_near_extreme`·`ends_near_extreme`).
  `window_source`와 별개 플래그다. 피벗은 후보용(k = 1.0) 중 구간 끝까지 확정된 것이다(끝 봉 경고는 끝에서 R봉 앞 극값이 바로 그날 확정될 때만 뜬다).

### 4.3 피보나치 채널 후보
- 방향 d∈{up, down}(판정 추천 또는 사용자가 직접 고름 — `chosen_by`: 추천을 따랐으면 `recommendation`, 바꿨으면
  `user_override`, 판정이 방향을 추천하지 않은 국면이면 null — domain `chosen_by()`·`ChosenBy`).
  기준선 = 같은 방향 확정 피벗 2개 (up: 높아지는 저점, down: 낮아지는 고점) `L(t) = p_a + m(t − i_a)`.
- 기하의 owner는 `ChannelGeometry`(기준선 `TrendLine(a, b)` + 폭 기준점 w → `price_at(index, level)`)다. 자동 후보와 수동으로 그은 채널이 같은 것을
  쓰고, 순위의 채널 밖 종가도 이 `price_at`의 레벨 0과 1 사이로 센다.
- 버림: 두 점 사이 가격 변화 `|m|·(i_b − i_a) < ATR_r`(사실상 수평), 뒤의 같은 쪽 확정 피벗이 기준선 너머로 0.25·ATR_r
  넘게 나감. "뒤"는 a 이후 전부(a와 b 사이 포함)다. ATR_r는 구간 끝 ATR이다.
- 폭: 그 뒤(a 이후) 반대쪽 확정 피벗 중 기준선에서 가장 먼 점 w. `d = L(i_w) − p_w`(up이면 `−(H_w − L(i_w))`로 음수,
  down이면 `L(i_w) − L_w`), 레벨 r의 가격 `C_r(t) = L(t) − r·d`. 기준선 바깥쪽에만 있는 반대 피벗은 폭이 될 수 없고, w가 없으면 그 쌍은 버린다.
- 순위: (n < 20봉 후보는 뒤) → 기준점~구간 끝 종가 중 채널 밖 비율 오름차순 → 폭/ATR 오름차순.
- 순위가 같으면 (a, b) 봉 순서다.
- 첫 점 지정: a를 고정하고 b·w만 찾는다. 첫 점이 구간 밖이면 `outside_window`, 그 방향의 확정 피벗이 아니면(구간 끝 뒤에
  확정된 것 포함) `not_a_pivot`으로 0개 + 이유. 첫 점이 맞아도 뒤에 둘째 점이 없으면 이유 없이 0개다.
- 생성 시점 = max(세 기준점 확정 봉). 그 앞은 옅게.

### 4.4 피보나치 되돌림
- 기준 스윙 선택지: 구간 최저↔최고(확정 피벗), 가장 최근 큰 스윙(2.0×ATR 마지막 피벗 2개), 가장 최근 확정 스윙
  (1.0×ATR 마지막 2개), 두 점 직접.
- 방향은 순서로: 먼저 점 = 1, 나중 점 = 0(TradingView 관례). `price(r) = P_0 + r·(P_1 − P_0)`. 레벨 가격의 owner는
  `RetracementGeometry`이고, 두 점 직접 지정도 이것을 바로 만든다.
- 구간 최저↔최고는 후보용(k = 1.0) 피벗에서 고르고(같은 값이면 먼저 나온 피벗), "가장 최근" 두 선택지도 구간 안(극값이 구간
  시작 이후, 구간 끝까지 확정)의 피벗만 본다. 고를 피벗이 모자라면 결과가 없다.
- 기본 레벨: 되돌림 0 · 0.236 · 0.382 · 0.5 · 0.618 · 0.786 · 1(`DEFAULT_FIB_LEVELS`), 채널은 여기에 확장 1.618을
  더한다(`DEFAULT_CHANNEL_LEVELS`, 6장 채널 표시). 선에 저장된 레벨이 있으면 그것을 쓰고, 그리기와 중첩이 같은 레벨을 쓴다.

### 4.5 수평 지지·저항 구간
- 분석 구간의 확정 피벗(k=1.0)을 로그 가격 순으로 훑어 **첫 점 대비** `ln(p/p_first) ≤ tol` 인 동안 묶는다(완전 연결 —
  구간 폭 ≤ tol). `tol = k_z · ATR_T / C_T`(T = 판정 구간 끝 봉, 기본 k_z = 0.5).
- 접촉 = 2봉 안에 붙은 피벗은 1회(봉 순서로 직전 피벗과 2봉 이하면 같은 접촉, 사슬로 이어진다). 최소 접촉 2.
- 생긴 날 = 구성 피벗이 모두 확정되고 `ln(hi/lo) ≤ k_z·ATR_t/C_t` 인 첫 봉 t. 그 뒤 재접촉만 지킴/뚫림으로 센다
  (닿기 전 종가 쪽으로 돌아가면 지킴, 반대쪽이면 뚫림). 화면 문구: "어떤 점을 묶을지는 판정 구간 끝 폭으로 고르고, 생긴 뒤에는
  유지된 것으로 본다".
  - 재접촉 1회 = 생긴 날 **다음 봉**부터 구간 [lo, hi]에 닿는(저가 ≤ hi ∧ 고가 ≥ lo) 연속 봉 묶음 하나. 묶음 직전 봉 종가의
    쪽(위·아래)과 묶음 다음 봉 종가의 쪽을 비교한다. 직전 종가가 구간 안이거나 판정 구간 끝까지 닿아 있으면 세지 않는다.
  - 판정 구간 끝 봉에서는 묶기 조건과 같은 식이라 생긴 날은 늘 구간 끝 이하다. 지킴·뚫림도 판정 구간 안에서만 센다.
- 구분: lo > 현재가 → 저항, hi < 현재가 → 지지, 그 밖 → 걸침(domain `zone_side`). 현재가는 판정 구간 끝 종가가 아니라
  응답 머리 `context.current_price`(기준일까지 원장 마지막 일봉 종가)다 — 판정 구간을 과거로 옮겨도 지금 가격으로 가른다(#699).
  화면의 현재가 점선·배지·"현재가 대비 %"도 같은 값을 쓴다(보이는 캔들 범위의 마지막 봉이 아니다). 결과는 위쪽 구간(hi
  내림차순)부터다.

### 4.6 중첩(컨플루언스)
- 입력: **보이는** 선만(내 선 + 자동 후보). 각 선은 종류(kind: 수평·되돌림·채널)와 가격 구간 [lo, hi](채널은 기준 봉
  레벨 가격, 되돌림은 레벨 가격). 중첩·"이번 주 레벨" 같은 현재 레벨의 **기준 봉 = 선을 만든 주기 계열의 마지막 완성
  봉**이다.
- 선 → 가격 구간 조립의 owner는 `bands_of(계열, 선, ref, levels)`다(선 = 채널·되돌림 기하, 수평선 가격, 수평 구간). 이
  함수가 두 규칙을 소유한다: 레벨 가격이 0 이하인 레벨(가파른 하락 채널의 아래 레벨 등)은 넣지 않고, 되돌림 레벨
  0·1(스윙 기준점 자체)도 넣지 않는다.
- 각 선을 ±tol(`DEFAULT_CONFLUENCE_TOLERANCE` = 0.5%) 넓힌다. tol은 0보다 커야 한다 — 0이면 레벨 선(점 구간)끼리는
  길이 0으로만 겹쳐 조용히 빠지므로 거절한다. 종류마다 합집합을 만든 뒤 가격축을 경계점으로 쪼개, **서로 다른 종류 2개 이상이 덮는
  구간**을 찾고 이어진 구간을 하나의 중첩으로 합친다. 구성 = 그 구간과 겹치는 선.
- 같은 종류(자동 수평 구간과 내 수평선)는 1종. 결과에는 "독립 증거가 아니다" 주의를 붙인다.
- 넓히기는 비율이다: `[lo·(1 − tol), hi·(1 + tol)]`. 한 점에서만 닿는 조각은 길이가 0이라 중첩이 아니다. 구성은 넓힌 구간이
  중첩 구간과 양의 길이로 겹치는 선이고, 결과는 낮은 가격부터다.

### 4.7 저장 구조 (RSI·국면 분류 연계용)
선 하나 = `kind(hline|fib_retracement|fib_channel) · timeframe(day|week|month) · source(manual|auto|auto_copied) ·
anchors[(bar_date, price)] · levels · extend_right · memo · locked · visible`, 자동이면 추가로 `algorithm@version · params ·
regime_window · regime(verdict, S, structure) · chosen_by(recommendation|user_override|null) · window_source(preset|user)`.
레벨 가격·중첩 같은 파생값은 저장하지 않는다(기준점에서 다시 계산). 저장은 연구 DB 판 12의 `chart_drawing` 표
(`research_sqlite/_schema.py`)이고 JSON 칸은 기준점·레벨·자동 파라미터 셋뿐이다.

- `source = auto` 선의 기준점은 옮길 수 없다(`chart.line.auto_anchors_fixed`) — 기준점이 자동 기록의 결과라 옮기면
  기록이 거짓이 된다. 고쳐 쓰려면 `auto_copied`로 저장한다. 메모·레벨·보이기·잠금·연장은 고칠 수 있다.
- 자동 선의 생긴 날(`created`)도 파생값이다. 저장한 판정 구간·민감도·도구 파라미터로 같은 찾기를 다시 돌려 기준점이
  같은 후보의 확정 봉을 응답에 싣는다(`application/stock_chart/_provenance.py`). 기준점을 옮긴 복사본과, 저장한
  `algorithm@version`이 지금 `ALGORITHM_VERSION`과 다른 기록은 null이다(다른 판의 규칙으로 다시 찾지 않는다). 저장할 때
  다른 버전의 자동 기록은 `chart.line.auto_record`로 거절하고, 국면(`regime`)·방향 출처(`chosen_by`)는 채널 기록에만 둔다.
- 선의 수정·삭제도 모드(연습 `practice:` 접두 / 실데이터)를 지킨다 — 다른 모드 대상의 선은 `chart.line.not_found`다.

- `kind`·`source`(`LineSource`)·`window_source`·`chosen_by` 어휘와 `algorithm@version` 값의 owner는 domain `_line_record`(facade
  `line_record`)다. `algorithm@version`에는 `ALGORITHM_VERSION`(지금 `chart_analysis@1`)을 그대로 저장하고, 판정 규칙·B\*·
  피벗·채널·수평 구간·중첩 규칙(기본 파라미터 포함)을 바꾸면 올린다. `test_chart_analysis_version.py`가 규칙 상수를 이
  값과 함께 고정해, 상수를 바꾸고 버전을 그대로 두면 깨진다.

**좌표 계약**
- 선은 만든 주기(`timeframe`)를 저장하고, 기하(채널 기울기·레벨 가격·되돌림)는 **그 주기 계열의 완성 봉 index**에서
  계산한다. 저장 날짜 `bar_date` = 그 주기 봉의 시작일(`Candle.start`, `ChartSeries.bar_date(i)`)이다.
- 저장 날짜 → index는 `ChartSeries.index_of(day)`: 그 날짜가 든 완성 봉(봉 사이 휴장일·주 중간 날짜는 그 기간의 봉이고,
  첫날이 휴장인 주·달 — 2024-02-12 월요일 휴장 주, 1/1·3/1·5/1 — 의 그 날짜도 `Candle.period_start`로 그 기간의 봉),
  첫 봉 전이거나 마지막 완성 봉의 끝 거래일 뒤(진행 중 봉 기간·미래 포함)면 None. 계열은 주기를 모르므로 마지막 완성
  봉만은 끝 거래일까지다 — 정지로 수요일에 끝난 마지막 주봉의 목·금은 None이다(저장 날짜는 늘 `Candle.start`라 저장된
  기준점 해석에는 영향이 없고, 좌표 입력 칸에서만 그 날짜를 고르지 못한다).
- 다른 주기 화면에 그릴 때는 기준점 날짜를 그 주기의 봉으로 옮겨 다시 계산하지 않는다. 화면은 원래 주기 계열로 계산한
  가격을 원래 주기 봉의 날짜에 놓고 날짜 축 위에서 잇는다(그래서 주기를 바꿔도 같은 선이다).

  지수명 정확 → 티커 정확 → 이름 정확 → 이름 포함). 지수 코드는 `<index_class>:<index_name>`이다(같은 이름의 업종
  지수가 코스피·코스닥에 하나씩 있다). 원장이 옛 구간에서 0으로 싣는 지수 시가·고가·저가는 값 없음으로 보고 봉에서 뺀다.
- mock 원천: 홈 시장과 달리 포트를 막지 않는다. 대상 코드는 모두 `practice:` 접두(`PRACTICE_CODE_PREFIX`)라 같은 연구
  DB에 저장한 연습 선이 실데이터 차트·중첩에 섞이지 않고, 서비스는 모드와 접두가 맞지 않는 대상을 모르는 대상으로 본다. `adapters/outbound/equity_mock/_chart.py`가 고정 seed 합성 일봉(지수
  하나·종목 둘, 2023-01-02 ~ 목요일 2025-10-30)을 주고 응답마다 `practice_data`·안내 문장을 싣는다 — 차트 흐름 e2e(PR3·4)가
  mock으로 돌기 때문이다. 005930은 분할을 흉내 내 k = 0.2다.
- 저장: 연구 DB(`research_sqlite`)에 표 추가(판 올림) — 새 DB 파일·환경 변수를 만들지 않는다.
- HTTP(`_chart_routes.py`, `/api/v1/stock-chart/*`): 종목 검색, 캔들, 국면 판정, 채널 후보, 되돌림 스윙, 수평 구간,
  중첩(POST), 선 CRUD. 요청·응답 가격은 모두 화면 가격이고 서버가 ÷k·×k 한다. 중첩의 저장 선은 서버가 `visible`인 것만
  고르고(보이기는 저장 칸이다), 요청에는 저장하지 않은 보이는 선(자동 후보)만 싣는다 — 저장한 후보는 요청에 다시 싣지
  않는다(실어도 ref = line_id인 요청 선은 빠진다). 요청 `include_mine`(기본 참)이 거짓이면 저장 선 중 내 선(source ≠ auto)을
  빼고 자동 선만 넣는다 — 중첩 패널의 "내 선도 넣기" 토글이 보이기 저장 칸을 바꾸지 않게 한다(PR4). 채널 첫 점 후보는
  `/channels` 응답 `anchor_choices`(domain `first_anchor_choices` — 그 방향의 확정 피벗, `find_channels`가 첫 점을 검사하는
  같은 목록)다. 화면이 보이는 규칙 문장은 domain `_wording`이 상수를 인용해 완성해 응답에 싣는다: regime `rules`·
  `pivot_rule`, zones `rules`, confluence `rules`(PR4). 저장 내용이 완전히 같은 자동 선(주기·종류·기준점·레벨·
  연장·메모·잠금·자동 기록 전부, 보이기만 다를 수 있다)을 다시 저장하면 새로 만들지 않고 있는 선을 주고, 숨겨 둔
  선이면 다시 보이게 한다 — 묶음 추가를 다시 보내도 같은 띠가 두 줄 생기지 않는다. 하나라도 다르면(레벨·조건을 바꿔
  다시 만든 선) 새 선이고, 손으로 그은 선·복사본은 늘 새 선이다. 분석 파라미터 범위는 domain 값 타입 하나가 검사해 `chart.params.invalid`로
  거절한다(HTTP 스키마에 같은 범위를 두지 않는다). 저장 띠(자동 수평 구간)는 기준점
  둘인 수평선(`hline`)이다. 거절은 404·422 `{code, message}`이고 요청 칸 검증 실패도 `chart.request_invalid`다.

## 6. 프런트 구조

**레벨 선을 그릴 점 계약**: 저장 선·자동 후보 응답은 레벨마다 두 점을 싣는다 — `start` = (기준 봉 날짜, 화면 가격),
`end` = (선을 만든 주기의 마지막 완성 봉 날짜, 화면 가격)이고 `end.price`가 그 봉의 레벨 가격(오른쪽 배지 값)이다. 기준
봉은 채널·되돌림은 첫 기준점, 수평선·띠는 그 기준점이다. frontend는 두 점을 날짜 축 위에서 잇고 `extend_right`이면
같은 기울기로 오른쪽에 연장만 하며, 레벨 가격·채널 기울기·÷k를 계산하지 않는다. 선을 저장할 때는 응답의 기준점
(`drawing.anchors`, 화면 좌표)과 자동 기록(`record`)을 그대로 보낸다.

그리는 동안도 frontend는 가격을 계산하지 않는다. 수동 그리기(끌기·마그넷 뒤 좌표)는 저장 전에 상태 없는
`POST /api/v1/stock-chart/lines/preview`(`previewChartLine`)를 부른다 — 요청은 저장 요청과 같은 초안(종목·주기·종류·화면
좌표 기준점·레벨), 응답은 봉 시작일로 맞춘 기준점과 `paths`이고 저장과 같은 규칙으로 거절한다(진행 중 봉
`chart.line.anchor_in_progress`, 계열 밖 `chart.line.anchor_outside_series`). 끄는 동안의 호출은 rAF/디바운스로 묶는다.
서버는 묶은 계열을 캐시해 미리보기가 원장을 다시 읽지 않는다. ×k로 낸 화면 가격은 마지막 자리(1ulp) 꼬리가 있을 수
있으니 화면은 호가 단위로 반올림해 표시한다(PR3 메모). 저장된 `source = auto` 선은 기준점을 옮길 수 없으니(4.7) 화면이
끌기 손잡이를 주지 않는다(PR3) — 옮기려면 `auto_copied`로 복사한다.

**채널 표시 방식(PR4가 따를 계약, 사용자 확인 사항)** — 근거: 디자인보드
https://claude.ai/artifact/9Bp8mU4PSWvnWLarnccunV 의 보드 "채널 표시".
- 기본 레벨 = 0 · 0.236 · 0.382 · 0.5 · 0.618 · 0.786 · 1 · 1.618(`DEFAULT_CHANNEL_LEVELS`), 2.618은 사용자가 고르는 선택
  레벨이다. 사용자가 레벨별로 켜고 끈다 — 켠 레벨 목록을 `GET /channels`·`/retracement`의 `levels`(되풀이 칸)로 보내면
  서버가 그 레벨들의 두 점을 준다(없으면 종류별 기본). 저장 선은 `levels` 칸에 그 목록을 저장한다.
- 각 레벨 라벨 "r (가격)"은 첫 기준점 봉 위치(`start`)에, 가격은 그 점의 화면 가격이다.
- 레벨 사이 음영: 0~1은 진하게, 1~1.618은 옅게.
- 오른쪽(미래 봉)으로 연장한다(`extend_right`, 끌 수 있다).
- 오른쪽 축에 이번 주(마지막 완성 봉) 레벨 가격 배지(`end.price`)를 달되 고른 선(없으면 포인터를 올린 선) 하나의 것만
  단다. 겹치면 세로로 밀어낸다. 다른 선은 레벨 라벨만 보인다.
- 레벨 0은 기준선이라 굵게 그린다. 생긴 날(`created`) 이전 구간은 옅게 그린다.
- 되돌림도 같은 라벨·음영 규칙(0~1)을 쓴다.
- 이 값들은 모두 서버 응답(레벨마다 두 점·가격)에서 오고 화면은 잇고 연장만 한다.

**자동 찾기 화면(PR4)**: 화면은 자동 찾기로 열리고 머리의 전환으로 수동 그리기에 들어간다(수동 중에는 자동 후보를 가린다).
자동 후보 칸은 저장한 자동 선을 만든 것마다 한 줄(수평 구간은 같은 기록의 띠 묶음 → 구간별 토글)로 보이고, 생성 패널은
응답 `drawing`을 미리보기로 그린 뒤 `drawing.anchors`·`record`를 그대로 저장한다. 채널 방향 출처(`chosen_by`)는 응답 기록이
정하고 화면은 다시 판정하지 않는다. 판정 구간 테두리 끌기는 완성 봉 index로 붙이고 요청에는 그 봉의 시작일을 싣는다.
새 판정·후보가 오기 전(앞 응답을 잠깐 보이는 동안)에는 추천 방향을 비우고 후보 고르기·추가를 막는다 —
앞 구간의 추천으로 새 구간 채널을 물으면 방향 출처가 "직접 고름"으로 기록된다. 근거 패널의 "그때" 판정은 저장 기록, "지금" 판정은 같은 주기의 기본 구간 `/regime` 응답이다. 묶음 지우기는 되돌리기 한
번에 함께 되살린다.

`pages/research-stock-chart` · `widgets/stock-chart`(차트 그리기·레이어 칸 조합) · `features/draw-chart-line`(수동 그리기·
마그넷·저장) · `features/navigate-chart`(줌·이동 입력과 보기 창 상태) · `features/find-chart-levels`(자동 생성 패널) ·
`entities/chart`(쿼리·좌표 변환·보기 창 계산·라벨 배치 표시 모델). 서버 상태는 query cache만, 도구·선택·보기 창·판정 구간
같은 UI 상태만 로컬.
