# 유저 스토리 하네스를 개발 기준선으로 쓴다

페르소나(정동민·한상목·김철수)와 유저 스토리는 `docs/product/user-stories/`가 소유한다. 형식·상태
값·태그 규칙의 설명은 그 폴더의 `README.md`가 정본이고, 이 규칙은 PR이 지켜야 할 의무만 적는다.

## 작성자

- 사용자가 보는 동작을 더하거나 바꾸는 PR은 같은 PR에서 관련 스토리를 갱신한다. 해당 스토리가
  없으면 페르소나 파일(`stories/<약자>.md`)에 새 스토리를 더한다. 번호는 다시 쓰지 않는다.
- 스토리 상태를 실제에 맞춘다. `예정`이던 스토리를 구현했으면 `구현됨-e2e`로 올리고 `담당 PR`과
  `e2e 담당`을 `없음`으로 바꾼다. 동작을 없앴으면 수용 기준을 고쳐 쓴다.
- `예정` 스토리를 새로 두거나 계획을 바꿀 때는 그 스토리의 e2e를 쓸 PR을 `e2e 담당`에 적는다. 그
  PR의 acceptance에 e2e가 없으면 계획 쪽에도 알린다.
- 수용 기준이 바뀐 스토리의 e2e를 더하거나 고치고 `@story`·`@US-*` 태그를 붙인다. 스토리 하나를
  위한 새 e2e는 `frontend/e2e/stories/`에 두고, 이미 같은 흐름을 도는 e2e가 있으면 복제하지 않고
  태그만 더한다.
- `uv run python -m quant_study_dev.user_story_trace --write`로 traceability 표를 다시 쓰고 검사를
  통과시킨다. 표를 손으로 고치지 않는다.
- PR 본문 테스트 계획의 "유저 스토리 하네스 갱신" 칸에 움직인 스토리 ID를 적는다. 사용자 동작이
  바뀌지 않는 PR(리팩터링·문서·backend 내부)은 "해당 없음"이라고 적고 체크한다.
- 계획 문서(`docs/planning/**`)가 PR ID를 바꾸거나 범위를 옮기면 그 PR이 스토리의 `담당 PR`도 고친다.
- 어느 계획에도 없는 스토리는 `미계획`으로 두고 "제품 결정 필요"와 사유를 적는다. 담당 PR을 임의로
  지어내지 않는다.

## 리뷰어

- 변경이 사용자 동작을 바꾸는데 스토리·e2e가 그대로면 blocking으로 본다.
- 스토리 e2e가 수용 기준을 실제로 확인하는지 본다. 태그만 붙고 기준의 화면 결과를 단언하지 않으면
  결함이다.
- `구현됨-e2e`로 올린 스토리의 e2e가 전체 e2e 게이트(`npm run test:e2e`)에서 실제로 돌았는지 PR
  본문의 게이트 결과로 확인한다. opt-in project(`real-equity`)의 테스트만으로 `구현됨-e2e`를 주장하지
  않는다.

## 금지

- traceability 표를 손으로 고치지 않는다. 스토리 파일과 e2e 태그가 정본이다.
- `test.describe`에 스토리 태그를 달지 않는다. 검사기가 거부한다.
- 스토리 태그가 있는 spec에서 `test.skip`·`test.fixme`·`test.fail`·`test.only`를 쓰지 않는다.
  opt-in spec에 스토리 태그를 달지 않는다. 검사기와 CI의 Playwright 목록 대조가 거부한다.
- 스토리 문구에 성별을 가정한 대명사를 쓰지 않는다. 이름이나 "이 사람"으로 쓴다.
