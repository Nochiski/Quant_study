# S01 후속 — 실원장 보존과 첫 연구 준비 판정

## 목적과 이번 범위

최종 목적은 감당 가능한 위험 안에서 비용 후 수익을 내는 자동매매다. 이번 단계는 확보한 원장을
원본과 분리해 보존하고, 현재 지원 범위로 첫 연구의 질문에 답할 수 있는지 확인한다. 바이트·행 수가
같다는 사실, 공개시점 계약의 구현, 원천 시점의 실제 정확성, 신호 예측력, 비용 후 계좌 수익은 서로
다른 증거다. 하나의 통과를 나머지 통과로 승격하지 않는다.

이번 범위는 **보존 → 연구 사전 품질 점검 → 첫 실행 사양 인계**다. 실제 팩터 IC·수익률·전략 성과를
계산하거나, 봉인 구간을 열거나, 전략을 채택하거나, 외부 계좌에 연결하지 않는다. 실원장 운영 결과는
저장소 밖의 로컬 증거로 보관하고, 이 문서에는 재현 절차와 판정 범위만 둔다.

## 질문과 불확실성

1. 받은 원장의 current BuildRecord와 파일이 별도 사본에서 동일하게 보존됐는가?
2. 지금 실행할 코드·계약·환경이 보존 출처와 맞고, 그 사본으로 실제 adapter를 열 수 있는가?
3. 필요한 필드·달력·상장구간·공개시점·가격 조정 근거가 첫 연구의 창과 모집단을 지원하는가?
4. 현재값 업종, 정정 전 재무 부재, 배당 총수익·상폐 회수금 부재가 질문의 답을 바꾸는가?
5. 결과를 보기 전에 입력·평가량·비교와 반복 열람 기록을 고정할 수 있는가?

30표 수신·manifest/파일/hash 확인·adapter metadata 읽기는 원장 확보의 증거다. 별도 연구 사본의
공개·재접속, 연구 목적에 맞는 품질 판정, 실제 연구 실행 여부는 각각 별도 결과로 기록한다.

2026-10-16 별도 사본의 `create → verify --repo-root → open --repo-root`가 모두 성공했다.
원장 판 `2164ba776cbd99f2`의 current 30표·261파티션을 보존했고 원본 MANIFEST 전후 동일·복사
inode 독립·pending 해제·adapter snapshot/필드 계약 동일·보존 catalog의 원본 경로 참조 없음도
확인했다. 이는 분리 보존·무결성·출처 검증의 결과다. 연구 목적별 품질 판정과 실제 IC/성과 실행은
별도이며 이 보존 성공에서 추론하지 않는다.

같은 날 독립 `verify --repo-root` 재검증과 기존 S01 database/backend 연결 회귀 **28 passed**를
확인했다. production source·CONTRACT_FILES·SoT·환경은 변경하지 않았다. 회귀는 보존/거절/adapter
연결 동작의 증거이며 실원장 전체 품질 인증을 뜻하지 않는다.

## S01 보존 당시(코드 `585f7c4d`) 판정

이 절은 코드 `585f7c4d`로 S01 보존·사전 점검을 마친 당시의 판정이다. 아래 전체 요청
MASKED 중단·첫 사양 미정·B 미구현은 당시 상태로 보존한다. 후속 개별 라벨 공백 계약과
첫 실자료 기술 확인 명세는 [S03 개별 조정 공백 사양](S03-adjustment-gaps.md)이 소유한다.
후속 실자료 기술 실행은 아직 하지 않았으며, 새 소스 판본의 별도 S01 사본과 결과 전 로컬
요청 JSON·hash·열람 기록을 준비한 뒤 실행할 예정이다.

당시 로컬 읽기 전용 SQL audit가 종료 코드 0으로 끝났고 실행 script 지문 일치·원본 MANIFEST 전후 동일·
검사 전후 S01 ready를 확인했다. 점검한 날짜·키·상장구간과 원주가/조정가 정합성에서는 위반을
발견하지 않았다. 거래 OHLC의 무효 행은 기존 bar owner가 모두 거절했고 기준가 행의 OHLC 결측은
기존 계약과 일치했다. 수익률·IC·팩터 값 분포는 계산하지 않았다. 이는 명시한 QC 범위의 결과이며
원천 공개시점 전체의 역사적 정확성·모든 EG/소비 계약 재검증·전략 수익성 인증은 아니다.

전체시장 QC 범위에는 MASKED 조정 공백이 있다. 아직 정하지 않은 첫 연구 전체의 불가능 판정으로
확대하지 않으며, 실제 요청의 후보·가격창에 포함되면 당시 S03 runner가 요청 전체를 중단했다.
producer profile/readiness와 consumer 노출 범위는 일치하는 개념이 아니며, 현재 업종은 실제
profile에서 `point_in_time=false`·`requires_confirmation=true`다. consumer 업종 미노출과도
구분한다. 배당 TR·상폐 회수금 부재는 이번 점검으로 해소되지 않았다.

다음 최소 작업은 두 경로로 나눈다. **A:** S03 사전 명세를 고정하고 기존 owner가 지원하는 범위에서
기술 확인·서술 진단을 준비한다. **B:** 더 넓은 모집단/기간 연구가 필요하면 당시 MASKED 전체 요청
중단을 개별 라벨의 정보창 통과 여부로 판단할 수 있도록 별도 설계·구현·검증한다. B는 이번 작업에서
구현하지 않았다. A에서도 성과 열람 뒤 공백 종목/기간을 골라 제외하지 않는다. 당시 실제 연구를
실행하지 않았으며 첫 연구 사양도 아직 미정이다.

## 최소 실행과 책임 경계

아래 표의 MASKED 요청 중단은 S01 보존 당시 기준이다. 현재 개별 라벨 판정은
[S03 개별 조정 공백 사양](S03-adjustment-gaps.md)을 따른다.

| 단계 | 기존 owner와 확인할 증거 | 멈출 조건 |
|---|---|---|
| 원본 분리 보존 | [S01 보존 계약](S01-snapshot.md)의 `equity.research_snapshot create`로 current와 참조 파티션·출처를 새 root에 복사 | 누락·해시 불일치·원본 경합·복사 실패·미완성 공개 |
| 실행 직전 재검증 | 같은 owner의 `verify/open --repo-root`, descriptor와 코드·계약·환경 출처 | pending·위치 이동·현재 코드/계약 불일치·검증 뒤 외부 변경 |
| 필드와 PIT 근거 | 원장 `dataset_profile`, 기존 `EquityDataPort`/`RawObservationPort`, [필드 계약](../../../database/docs/EQUITY_FIELD_MAP.md) §3과 [정본 대장](../../../.claude/rules/strategy-workbench-sot.md) | 필수 필드 unavailable·설명되지 않은 lag fallback·필요한 실제 공개시점 근거 부재 |
| 가격과 라벨 지원 | 원장 `price_adj_daily`·`v_adj_close`, 기존 bar 판정과 [S03 runner](S03-runner.md)의 label loader | 필수 조정가 부재·카탈로그 실패·요청 범위 MASKED·미지원 조정 경로 |
| 모집단과 상장구간 | 원장 유니버스·`security_span`, 기존 adapter와 S03 label loader | 당시 모집단을 재현할 수 없음·알 수 없는 종료 사유·수집 상한 불일치 |
| 기존 품질·소비 계약 | `equity.gates`와 `equity.contract`, [게이트 사양](../../../database/docs/EQUITY_GATES.md)·[워크플로우](../../../database/docs/EQUITY_WORKFLOW.md) | 해당 결론에 필요한 검사 FAIL. stage/fixture/baseline 부재면 그 재검증 미실행과 영향 범위를 명시 |
| 첫 연구 사양 | 아래 사양 기록을 작성한 뒤 기존 S03 CLI에 인계 | 해당 실행 목적에 필요한 질문·명세·판정/서술 범위·열람 기록 미정 |

이번 사전 점검은 기존 보존 CLI와 저장소 밖의 로컬 읽기 전용 SQL audit/receipt로 위 owner의
결과를 모은다. 새 production validator나 품질 owner를 추가하지 않는다. 신호·팩터 수식,
가격 조정 술어·결측 대체·PIT 랙·유니버스 선정·라벨 상태를 다시 구현하지 않는다. 원장을 재빌드하거나
보존 root 안에서 catalog/contract 메타를 쓰는 검사는 무결성 검증과 구분한다. 기존 `equity contract`는
메타 파일을 쓰므로 완성 보존본에 바로 실행해 descriptor를 바꾸지 않는다. 외부 stage·baseline을
요구하는 gate를 current-only 사본의 파일만으로 통과했다고 주장하지 않는다.

운영 재현 경로는 비민감 환경변수 예시로 전달한다. 실제 경로와 SQL/receipt는 저장소 밖 로컬
증거에 보관한다. 품질 점검 범위 `2020-01-02 ~ 2026-10-15`는 전체 지원기간의 결측·정합성
확인 범위이며, S03 신호·성과·IC 창을 정한 것이 아니다.

```sh
PYTHONPATH=database/src backend/.venv/bin/python -m equity.research_snapshot create \
  --source-root "$EQUITY_SOURCE_ROOT" --root "$RESEARCH_SNAPSHOT_ROOT" --repo-root "$PWD"
PYTHONPATH=database/src backend/.venv/bin/python -m equity.research_snapshot verify \
  --root "$RESEARCH_SNAPSHOT_ROOT" --repo-root "$PWD"
PYTHONPATH=database/src backend/.venv/bin/python -m equity.research_snapshot open \
  --root "$RESEARCH_SNAPSHOT_ROOT" --repo-root "$PWD"
```

환경변수는 사용자가 이미 확보한 원장과 새 별도 보존 위치를 가리킨다. SQL audit는 읽기 전용으로
manifest current가 가리키는 파티션과 보존 catalog를 읽고, 아래 점검 범위·명령·쿼리·종료 상태를
로컬 receipt에 남긴다. 입력 자체를 수정하거나 불합격 사본의 pending을 수동 해제하지 않는다.

## 반드시 남길 사전 점검 근거

- **입력/출처:** 운영 기록 ID, 검사 시각, 명령·종료 상태, ledger snapshot ID, descriptor·계약 지문,
  코드/환경 출처, 검사한 테이블/필드/기간, 검사하지 못한 범위와 사유. 경로·원문 진단·실제 값은 로컬
  증거에 두고 공개 인계에는 비민감 ID와 요약만 남긴다.
- **가격:** 조정가 테이블과 필드 가용성, 기존 view/adapter의 MASKED 여부, 정지·기준가·잠정/무효 bar
  판정, 원주가 불변·기업행동 근거. 현재 S03 runner는 요청 범위의 중간 MASKED가 하나라도 있으면
  요청 전체를 unsupported로 멈춘다. 전체시장 QC에서 공백이 발견됐다는 사실만으로 아직 정하지 않은
  첫 연구 전체를 불가능하다고 판정하지 않는다. 향후 후보·가격창의 공백 포함 여부를 owner로 확인한다.
  종목 삭제·원주가 fallback·0/전일가 채움으로 회피하거나 성과를 본 뒤 창을 줄여 선택하지 않는다.
- **필드 노출:** producer `dataset_profile`·`factor_readiness`의 ready/행 수와 consumer
  `EquityDuckdbAdapter.list_fields()`의 실제 노출은 구분한다. 원장 존재·consumer 연결 미노출·원장
  미수록을 따로 기록하고 producer ready를 consumer 사용 가능으로 해석하지 않는다.
- **PIT:** `available_date`/파생 공개일, as-of·권고 세션 랙, 가용성 근거의 관측/가정 구분, 원천 수집
  상한·coverage·필드별 누락 사유. 소비 코드가 미래값을 막는다는 사실만으로 원천 공개일 자체가
  역사적으로 정확하다고 인증하지 않는다. 정정 전 재무 부재 등 원장 한계도 질문별로 판단한다.
- **상장구간:** 원래 `first_session`·`last_session`·`end_reason`을 쿼리 종료일로 자르지 않는다.
  `coverage_gap`·`data_gap`·`delisted`·상장근거 없음의 의미는 S03 runner가 소유한다. 비교 불가
  종목을 당시 모집단 분모에서 조용히 빼거나, 수집 종료를 상폐로 해석하지 않는다.
- **업종:** `classification.sector`/`corp.induty_code`의 현재값은 PIT 업종 이력이 아니다. PIT 이력이
  없으면 과거 업종 중립화·업종 내 순위·업종별 과거 성과 연구는 진행하지 않는다. 업종을 쓰지 않는
  별도 질문으로 줄일 때도 결과 열람 전에 변경 사유를 기록한다. consumer에 업종 필드가
  연결되지 않은 사유와 원장의 현재값/non-PIT 한계는 별개이며 어느 쪽도 과거 그룹 전략 지원을 뜻하지 않는다.
- **회계 범위:** [S02](S02-accounting.md)의 배당일·TR·상폐 회수금 부재를 유지한다. 분할조정 종가
  라벨은 배당 포함 총수익도 실제 다음 시가 체결 손익도 아니다. 그 원천이 질문에 필수면 먼저 보완한다.

데이터 품질 검사 자체는 [홀드아웃 규칙](../../../.claude/rules/holdout-window.md)의 예외지만, 이를
구실로 2020-01-02 이전 팩터 값 분포·IC·수익률을 계산하지 않는다. 워밍업도 입력으로만 읽고 그
구간의 결과를 산출하지 않는다. 봉인 개봉은 이번 준비 판정에 포함하지 않는다.

## 첫 S03 실행 전에 고정할 기록

다음 필드를 실제 연구 요청과 별도의 변경·열람 이력에 남긴다. 아래는 필요한 항목의 계약이며,
구체적인 신호·날짜·경제효과/위험/통계 임계값을 이번 문서가 임의로 정하지 않는다.

| 묶음 | 결과 열람 전에 명시할 내용 |
|---|---|
| 질문과 반증 | 연구 ID·가설 판본·경제적 이유·미해결 불확실성·무엇이 답을 반박하는지·이번 결과로 가능한 결정 |
| 입력 | 보존 ledger/descriptor/계약/코드/환경 ID·필수 필드/한계 수용 근거·사전 점검 기록 ID |
| 창 | IS/OOS-검증의 역할·신호 start/end·워밍업·`evaluation_as_of`·`label_calendar_through`·측정 세션·봉인 제외 |
| 모집단 | 당시 유니버스 정책·진입/퇴출·재상장 ID·결측/미지원/상폐 처리·가격/유동성 제한과 그 owner |

S03의 Rank IC·coverage는 [순수 평가 계약](S03-signal-evaluation.md)을 그대로 쓰고, CLI 입력과

방향을 바꿨다면 탐색 선택으로 기록한다. 기술 확인이나 탐색적 IC·coverage 서술이 목적이면
창·신호·서술 범위·반복 열람 기록을 먼저 정하고,
경제적 채택·후보 선택·위험·통계 유의성 결론을 내리지 않는다고 명시할 수 있다. 이때 수익 임계값을
임의로 추가하지 않는다. 전략 채택·후보 선택까지 판단하려는 연구는 그 결정에 필요한 경제효과·위험
임계값과 통계 불확실성 방법을 결과 전에 정한다. 결과를 본 뒤 기준을 맞추지 않는다. 별도 계좌 성과
비교가 아직 미지원이면 그 후속 실행을 구현·검증하기 전까지 IC를 자동매매 채택 증거로 올리지 않는다.

## 진행·보류·기각 기준과 인계

- **진행:** 별도 사본의 공개·무결성·현재 실행 출처가 확인되고, 질문에 필요한 데이터/owner가 지원되며,
  남은 한계의 허용 이유와 해당 목적에 필요한 결과 전 사양·서술/판정 범위·열람 기록이 갖춰졌을 때
  S03 첫 실행 준비로 넘긴다.
  준비 판정은 실제 연구 실행 또는 채택을 뜻하지 않는다.
- **보류:** 해당 목적에 필요한 증거·원천/PIT/회계 계약·명세·판정 기준이 부족하면 빠진 근거와 다음 최소
  작업을 적고 그 근거를 필요로 하는 결론을 보류한다. 검사 의존 입력 부재는 해당 gate 재검증
  미실행으로 기록하며 모든 기술 확인·탐색 연구를 일괄 금지하는 조건으로 쓰지 않는다. 범위를 줄일 수
  있으면 변경을 먼저 기록하고 다시 판정한다.
- **기각:** 해시/출처 불일치·미완성 보존본은 연구 입력으로 거절한다. 미래 정보·현재 업종을 과거
  정보로 사용하는 설계, 미지원 가격 공백을 채우거나 상폐를 삭제해야 성립하는 질문은 현재 설계로
  진행하지 않는다. 이 단계의 기각은 데이터/설계 지원 판정이며 경제 가설의 성과 기각이 아니다.
