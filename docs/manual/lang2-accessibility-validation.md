# LANG2 노드 캔버스 접근성 검증

2026-10-13 마감 검증. 자동 접근성 표면 검사와 실제 스크린리더 음성 검증을 구분한다.

## 검증 경계

- `frontend/src/features/edit-strategy/__tests__/node-canvas.test.tsx`: 키보드 연결·취소, 출력 pressed와 연결 live status, 같은 진단 재노출, 지연 배치의 초점 보존, 문서/팩터 전환의 연결 폐기.
- `factor-graph-editor.test.tsx`: 인스펙터의 명시적 복귀 버튼이 현재 선택한 노드로 초점을 돌리는지 검사한다.
- `frontend/e2e/stories/node-canvas.spec.ts` (`@US-CS-07`): 실제 브라우저 원문 편집·undo, 노드/포트 이름, 연결 상태, 인스펙터 진입·복귀, 반복 오류 reveal, 1440/640/360px 수평 넘침·시각 캡처를 검사한다. 접근성 트리와 PNG는 Playwright 실행 결과에 첨부한다.
- 연결 상태는 현재 원문·문서·팩터 신원에 유효한 캔버스 배선 상태만 투영한다. 서버 실행 결과나 연결 성공 판정을 별도로 추론하지 않는다. 실제 입력 연결 정보는 포트 이름과 기존 원문 트랜잭션 피드백이 제공한다.

## 실제 음성 검증 상태: 미실행

현재 Linux 클라우드 환경에는 `orca`, `speech-dispatcher`, `espeak` 명령, `DISPLAY`/`WAYLAND_DISPLAY`, `/dev/snd`가 없다. 시스템 Chromium은 있지만 Playwright 접근성 트리만으로 실제 음성 순서·중복·누락을 증명할 수 없다. 이 작업에서 새 패키지 설치, 사용자 컴퓨터 전환, 음성 서비스 설정 변경은 하지 않았다. 아래 절차는 실행 기록이 아니라 남은 수동 수용 절차다.

## 재현 가능한 수동 절차

스크린리더가 이미 구성된 검증 환경에서 실행한다. OS/브라우저/스크린리더의 정확한 버전, 언어, 탐색/폼 모드를 기록하고 격리 테스트 DB·mock 데이터로 앱을 실행한다. 가능한 조합은 Windows NVDA + Chromium 또는 macOS VoiceOver + Safari다. 어느 한 조합의 결과를 다른 조합의 보장으로 쓰지 않는다.

1. 새 전략의 YAML에 공식 `quality_momentum.yaml` fixture를 넣고 검증 통과를 기다린 뒤 그래프의 고급 노드 캔버스를 연다. 탐색 모드에서 노드 편집 버튼의 순번·연산 이름, 출력 포트, 입력 포트의 연결된 원천 이름이 들리는지 기록한다. 내부 ID만으로 이름이 대체되면 실패다.
2. 필요하면 폼/상호작용 모드로 들어간다. 첫 노드에 초점을 두고 방향키로 둘째 노드로 이동한다. Enter로 인스펙터에 진입하면 선택한 노드 이름과 속성 그룹이 읽혀야 한다. Tab으로 속성을 탐색한 뒤 ‘선택한 노드로 돌아가기’를 실행하면 같은 노드 버튼에 초점이 돌아와야 한다.
3. 출력 포트에서 Enter를 누른다. 출력 선택 상태와 ‘연결할 입력 포트를 선택하세요’ 안내가 읽히는지 확인한다. Escape 후 선택 해제와 ‘진행 중인 연결 없음’이 전달돼야 한다. 이후 입력 포트를 눌러도 YAML은 바뀌지 않아야 한다. 취소 버튼으로도 반복한다.
4. 다른 출력→입력을 연결한다. 입력 포트의 연결 원천 이름과 기존 반영 피드백을 확인한다. YAML에서 실제 참조 변경을 확인하고 undo 한 번으로 이전 참조가 복원되는지 확인한다. 연결 대기 안내를 성공 안내로 오인하게 읽히면 실패로 기록한다.
5. YAML의 `window: 252`를 `window: 0`으로 바꾼다. 문제 목록에서 같은 오류를 두 번 선택하고 매번 해당 노드가 보이는지 확인한다. 노드 문제 배지로 인스펙터를 열면 오류 본문을 읽을 수 있어야 한다. 노드 복귀 뒤 같은 배지로 다시 들어가도 초점·오류 문맥이 유지돼야 한다.
6. 연결을 시작한 상태에서 팩터/문서를 바꾸거나 YAML로 갔다 돌아온다. 이전 출력 선택과 대기 안내가 남지 않고 다른 문서의 참조를 변경하지 않는지 확인한다.
7. 360px/640px에서 위 진입·복귀·오류·취소를 반복한다. 페이지 전체의 가로 넘침, 초점이 화면 밖에 숨는 현상, 확대 시 버튼/문구 중첩을 확인하고 캡처한다.

각 단계의 기대 낭독과 실제 낭독, 초점 대상, 통과/실패, 캡처 또는 음성 기록 위치를 남긴다. 음성 기록에는 테스트 fixture만 사용한다. 현재 이 문서에는 실제 낭독 통과 기록이 없다.
