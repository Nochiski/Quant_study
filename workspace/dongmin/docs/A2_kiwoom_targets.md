## 3. 계산 검산 — 어긋나는 곳 3건

### 3-1. [불일치] R6-5 `ka10014` 에만 폐지종목 프로브 1,494콜이 빠져 있다
- **상황**: 계획서는 `ka10060/ka10008/ka10014/ka20068` **4개 TR 전부**에 대해 폐지종목이 `rc=0`+0행임을 실측 확정하고, "폐지 1,494종목은 프로브 1콜씩만 태우고 `status='delisted_no_data'` 명시 기록"을 R6 공통 규칙으로 적었다(`COLLECT_PLAN.md` R6 본문, `f_source_map.md:387`).
- **인풋**: R6 표의 콜 수. R6-3 = 41×2,763+1,494, R6-4 = 41×2,763+1,494, R6-6 = 82×2,763+1,494 인데 **R6-5 = 5×2,763 = 13,815 으로 +1,494 가 없다**.
- **에러 위치**: `COLLECT_PLAN.md` §R6 표 R6-5 행(콜 13,815) 및 `f_source_map.md:416` 동일 값. `DATA_CATALOG.md:132` SH-01 도 "13,815 (5×2,763)" 로 같은 값.
- **위험성**: 규칙을 그대로 적용하면 **15,309콜**이고 R6 계는 471,539 → **473,033콜**이 된다. 차이는 0.3%로 일정에는 영향이 없으나, **폐지종목 프로브를 R6-5 에서 의도적으로 뺀 것인지 누락인지가 문서로 구분되지 않는다.** 실행 시 `ka10014` 만 폐지종목 shard 가 생성되지 않으면 2019-06 이후 폐지된 종목(연 90종목 × 7.2년 ≈ 650종목 추정)이 `delisted_no_data` 기록 없이 조용히 빠진다 — 나중에 "결측인지 원래 없는지" 판별 불가.

### 3-2. [설명 가능] 키움 계가 587,074(f_source_map) vs 586,316(COLLECT_PLAN) 로 758 다르다
구성이 바뀐 것이지 산술 오류가 아니다.
```

                    + ka10013 114,777 + ka10014 13,815 + ka20006(업종,선택) 868 = 587,074
COLLECT_PLAN §5-1 : 위에서 ka20006 업종지수 868 을 제거(KRX 정본으로 확정)

                    (= R6 코어 471,539 + 확장 R9-a ka10013 114,777)
```
검산: 587,074 − 868 + 28 + 82 = **586,316** ✓

### 3-3. [분모 차이] `ka10008` 비중 "38.8%" 와 "48.4%" 는 둘 다 맞다
