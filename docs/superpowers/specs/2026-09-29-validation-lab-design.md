## 1. 배경

백테스트 한 번의 성과는 과최적화·미래 참조·생존편향·비용 누락·숨은 베타·시도 횟수 때문에 쉽게 부풀려진다.
지금 앱에는 미래 참조 방지(T+1 시가 체결, `available_date`)와 PIT 유니버스는 있지만, 다음이 없다.

- 홀드아웃 봉인: 규칙 문서(PR #272)만 있고 코드에는 날짜 하한도 열람 기록도 없다.
- 시도 기록: 백테스트 목록이 프로세스 메모리(`application/backtest_run/_service.py`의 `_records`)라
  재시작하면 사라진다. 시도 수를 셀 근거가 없다.
- 워크포워드·파라미터 탐색·DSR·고원·팩터 회귀·용량 곡선: 로드맵 M6·M7에 계획 개념으로만 있다.
- 비용: 수수료·슬리피지가 매수·매도 같은 고정 bp다. 매도 거래세, 거래량에 따라 커지는 충격 비용, 평균
  거래대금 기준 참여 한도가 없다.

## 2. 목표

좋아 보이는 결과가 운인지, 과최적화인지, 비용·규모 앞에서 무너지는지를 사용자가 따로 챙기지 않아도 앱이
묻고 기록하게 한다. 세 페르소나 모두 같은 화면을 지나되 깊이만 다르다(디자인보드 "사람별 여정").

## 3. 결정

### D1. 연구 구간 잠금은 서버 정책이다

- 봉인 구간은 `2016-01-01 ~ 2019-12-31`이다. 저장소에서 아직 아무도 결과를 보지 않은 유일한 창이다.
- 연구용 측정은 `2020-01-02` 이후만 한다. 판정은 **측정 구간의 시작일 ≥ 2020-01-02** 하나다. 봉인 구간
  앞(2010~2015)도 측정하지 않는다(#272 규칙과 같다). `metric_windows`는 실행 서비스가 이미 실행 범위 안으로
  강제하므로 따로 검사하지 않는다.
- 워밍업 읽기(지표 계산에 필요한 과거 관측)는 측정이 아니므로 허용한다. 기존
  `RawObservationQuery.history_sessions_before_start` 경로를 그대로 쓴다.
- owner는 `domain/backtest/_research_window.py`의 상수와 판정 함수 하나다. `RunEnvironment.__post_init__`에는
  넣지 않는다. 엔진 직접 테스트·벤치 스크립트·은퇴 문서 업그레이드 응답(`environment_from_retired_settings`)이
  2020 이전 환경을 값으로 만들 수 있어야 하기 때문이다. 판정은 실행 관문 `require_environment`가 한다.
- 적용 경로: 백테스트 실행, 포트폴리오 미리보기, 추적 실행, 팩터 미리보기(`/api/v1/factors/preview`), equity
  패널·미리보기(`/api/v1/equity/panel/preview`, `/api/v1/equity/preview`). `/api/v1/equity/universe/preview`는
  구성 종목 이력만 보이고 성과·값을 측정하지 않으므로 뺀다.
- 진단: 실행 경로는 422 `backtest.run.research_window_violation`이다. 이 경로의 거절 문구 owner는 기존 관례대로
  frontend i18n `backtest.error.<code>`이고, 날짜를 frontend에 복제하지 않도록 422 detail이 봉인 구간과 연구
  하한 값을 싣고 i18n 문장은 자리표시자로 쓴다. 미리보기·추적도 같은 422 `backtest.run.research_window_violation`
  detail로 거절한다(#351 — 전에는 `portfolio.strategy.invalid` 안의 issue code `run_environment.research_window`로
  실었는데, 추적 화면이 그 거절을 일시 장애 문장으로 보이고 서버 사유를 잃었다). 세 경로 모두 날짜 값의
  owner는 `_research_window.py` 하나다.
- 봉인 구간을 여는 유일한 길은 D11의 홀드아웃 개봉 흐름이다. #272 규칙과의 관계는 D11이 적는다.

### D2. 전략 계열과 시도 키

**계열**(DSR의 시도 수 N을 세는 단위)은 `strategy_id`다. 모든 리비전과 모든 실행을 포함한다.

- 복사·분기(로드맵 M8, 아직 없음)가 생기면 새 전략이 부모 계열을 물려받는 `parent` 계약을 그때 함께 만든다.
- AI 제안 적용은 같은 `strategy_id`의 새 리비전이라 이미 같은 계열이다.
- 계열은 합치기만 할 수 있다. 쪼개기·초기화·시도 삭제는 없다.
- 판정은 계열 N으로 하고, 사용자 전체 N은 참고로만 보인다.
- 인라인 초안 실행: 요청이 편집 중인 전략의 `lineage_strategy_id`를 실으면 그 계열에 들어간다. 이 값은
  `strategy_source`처럼 출처 정보라 `run_fingerprint`에 넣지 않는다. 저장된 적 없는 새 전략의 초안 실행은
  계열 없음으로 원장에 남고 N에 들어가지 않으며, 그 결과에는 DSR을 계산하지 않는다(“저장한 리비전으로
  실행하면 계산”).

**시도 키**는 "새로 고를 거리가 생긴 실행"만 새 시도로 세기 위한 키다(제품 소유자 결정, 2026-09-29).

| 구분 | 무엇 |
|---|---|
| 키에 든다(바뀌면 새 시도) | 전략 의미 해시(아래), 해소된 파라미터 값(D4), 시장·빈도·유니버스, 시작일, 결측 처리, 체결 시점, 비용 모델 종류(거래세 방식·충격 모델·참여 기준) |
| 방향으로만 본다 | 수수료·슬리피지·거래세율·충격 계수는 낮출수록, 참여율은 높일수록 유리하다. 스키마 기본값보다 **유리한** 쪽이면 키에 값이 들어가고, 기본값이거나 **불리한** 쪽이면 "기본 이하"로 묶인다. custom 거래세율의 기준은 법정 세율표 최대값이다(스키마 기본값이 없다) |
| 키 밖(바뀌어도 같은 시도) | 종료일, 벤치마크, 연환산 거래일, OOS 시작일, 실행 core, 초기 자본, 데이터 스냅샷, 엔진·레지스트리 판본, 제목·설명·주석·서식, 파라미터 범위 정의(기본값이 같을 때), 그래프 노드 이름·선언 순서·팩터 id, 출력에 닿지 않는 노드(#335) |
| N에서 빠지는 실행 | 결과가 나오지 않은 실행(전략이 확정된 뒤의 거절, 시작 전 취소, 시스템 오류, 실험 안의 실패 조합), 추적·미리보기·AI 설명, 용량 스윕, 홀드아웃 개봉 |

- **전략 의미 해시**는 `spec_hash`에서 제목·설명·팩터 표시 이름·스키마 판본과 파라미터 범위 정의를 뺀 canonical
  payload의 해시다. 노드·팩터 id는 구조 번호로 바꾼다(#335). 이름만 바꾼 저장과 업그레이드만 한 리비전은 새로 고를 거리를 만들지 않는다. 파라미터 값은 따로 해소된 값으로 키에 든다. owner는
  `domain/strategy/_canonical.py`의 `strategy_spec_hash` 옆 함수 하나다(canonical 규칙을 두 벌 두지 않는다).
- **키 표기의 안정성**: 칸 값이 스키마 기본값이면 키 표기에서 뺀다. 그래서 RunEnvironment에 칸을 더해도 기존
  설정의 키는 바뀌지 않는다. 해소된 파라미터 값은 V1-05부터(파라미터 배선 전에도) 문서 기본값으로 키에 싣는다.
  "칸 추가 전후 같은 키" 테스트가 이를 지킨다. 분류표가 생긴 뒤 RunEnvironment에 칸을 더하는 PR은 같은 PR에서
  그 칸을 분류한다. 스키마 기본값을 바꾸는 것은 시도 키 변경으로 본다.
- 시도 키는 N 집계에만 쓴다. 재현·캐시·중복 실행 제거는 `run_fingerprint`가 맡는다(D6).
- RunEnvironment의 각 칸이 위 어느 구분인지는 `domain/backtest/_trial_key.py`의 분류표 하나가 소유한다.
  architecture 테스트가 `RunEnvironment`의 모든 필드가 정확히 한 번 분류됐는지 강제한다.
- **대표 샤프**: 한 시도 안에 재확인 실행이 여럿이면 샤프도 여럿이다. DSR에 쓰는 시도의 대표 샤프는 그 시도에서
  처음 완료된 실행의 전체 구간 **세션 단위(연율화 전)** 샤프이고, 원장에 지표 레지스트리 판본을 함께 적는다.
  실행마다 `annualization_days`가 달라도 DSR 입력이 흔들리지 않는다. 판본이 섞이면 DSR 옆에 경고를 보인다.
- **미리 계산**: 실행 전에 "이 실행이 새 시도인가, N이 얼마가 되나"를 답하는 API를 시도 원장 PR(V1-05)과 실험
  PR(V3-03)이 제공한다. frontend는 분류표를 복제하지 않고 이 응답을 보인다.
- 세지 않은 실행도 원장에 전부 남고, 같은 시도끼리 묶어 보인다. 원장에 남는 거절은 전략이 확정된 뒤의
  거절(봉인 겹침 등)뿐이다. 본문 파싱 실패처럼 계열을 정할 수 없는 거절은 남기지 않는다.

### D3. 실행 기록은 새 SQLite 파일에 영속한다

- `.local/research.sqlite3`(환경 변수 `STRATEGY_WORKBENCH_RESEARCH_DB_PATH`, 새 application_id)에 실행, 시도
  원장, 실험, trial, 봉인 원장을 둔다. 전략 DB의 불변 트리거와 섞지 않는다.
- SQLite 파일 claim·application_id·DDL manifest 대조는 이미 두 어댑터(`strategy_sqlite`, `assistant_sqlite`)에
  복제돼 있다. V1-03은 세 번째 복제 대신 공통 routine으로 뽑아 세 어댑터가 함께 쓰게 한다.
- 상태 전이만 저장하고, 진행 이벤트는 메모리 링에 둔다.
- 재시작 때 끝나지 않은 단일 실행은 `failed`로 닫는다(새 코드 `backtest.run.interrupted`). 실험의 trial은 D6이
  다시 대기시킨다.
- 결과 파일 `result.json`에 디코더를 둔다. 상태 응답의 `artifact_uri` 형식은 #277(이슈 큐 작업 흐름)의 결과를 따른다.

### D4. 파라미터 값은 해소된 값으로 배선한다

- 실행 요청(`BacktestRunSpec`)에 `parameter_values`(parameter_id → 값)를 더한다. `portfolio_design`이 문서
  기본값 대신 이 값을 쓴다. 저장 리비전의 provenance와 `spec_hash`는 그대로다.
- 허용값 판정(범위·선택지)은 `domain/strategy`의 파라미터 정의 옆 술어 하나가 소유한다. validator, 실행
  요청의 422, SearchSpec 격자가 같은 술어를 부른다. step은 격자 전개에만 쓴다.
- 해소된 값은 시도 키와 `run_fingerprint`에 들어간다. SoT 금지 절의 캐시 키 목록에 "해소된 파라미터 값"을
  더한다(V3-02).
- 한계: 그래프의 정수 창(`window`·`periods`·`lag`)은 노드 리터럴이라 아직 파라미터로 묶을 수 없다. 로드맵
  M6의 경로 기반 바인딩은 이 initiative의 non-goal이다.

### D5. 실험은 domain.experiment가 소유한다

- `SearchSpec`: 탐색할 파라미터와 값 목록(v1은 그리드만). 기반은 **저장된 리비전만**이다. 인라인 초안과 동결
  리비전은 실험 기반이 될 수 없다.
- `SplitSpec`: 롤링/앵커드, 학습 연수, 검증 연수, 엠바고 세션 수. 모든 창은 연구 구간 안에 있다.
- 창마다 파라미터를 고르는 기준: 학습 샤프 최대 또는 이웃 평균 샤프 최대(기본). 이웃은 격자에서 체비셰프
  거리 1인 칸(차원 d에서 최대 3^d − 1칸)이고, 경계에서는 있는 칸만 평균한다.
- trial = (실험, 해소된 파라미터, 창). 상태는 `QUEUED → RUNNING → COMPLETED | FAILED | CANCELLED`이다.
  실행에 배정된 뒤의 trial 상태는 그 실행의 `RunStatus`에서 파생하고 따로 저장하지 않는다. 실패한 trial은
  지우지 않고 원장에 남는다.
- 성적표는 검증 창들의 수익률만 이어 붙인 곡선이다.
- 실험 종류: 파라미터 탐색, 용량 스윕(초기 자본만 바꿈, N 제외).

### D6. 실험은 서버 대기열에서 비동기로 돈다

- 실행 접수와 슬롯 배정의 owner는 `application/backtest_run`의 스케줄러 하나다. #161 브랜치
  (`fix/backtest-run-concurrency`, 다른 작업 흐름 소유)의 FIFO 대기열·같은 입력 잇기를 토대로 확장한다.
- 전역 동시 실행 슬롯 수는 #161이 만든 상수(`MAX_CONCURRENT_RUNS`)를 기본값으로 하고 환경 변수
  `STRATEGY_WORKBENCH_RUN_SLOTS`로 덮어쓴다. V3-04가 그 상수와 SoT 행을 이 설정 하나로 대체한다. 슬롯이 2개
  이상일 때만 1개를 단일 실행 전용으로 비워 둔다(1개면 실험이 굶는다).
- 실험끼리는 우선순위 가중 라운드로빈으로 trial을 번갈아 배정한다. 뒤 실험도 굶지 않는다.
- **중복 실행 제거와 결과 공유는 `run_fingerprint`로 한다**(#161의 "같은 입력"과 같은 기준). 시도 키는 결과를
  바꾸는 칸(초기 자본·불리한 비용 등)을 일부러 빼므로 결과 공유 키로 쓰면 용량 스윕 곡선이 평평해진다. 시도
  키는 N 집계에서 같은 시도를 한 번만 세는 데만 쓴다.
- 재시작하면 실행 중이던 trial은 대기로 되돌려 이어서 돈다.
- 일시정지·재개·취소·우선순위 변경은 **실험 단위**다. 실험 상태로 표현하고 `RunStatus`에 값을 더하지 않는다
  (frontend의 `as const` 상태 맵(`backtest-run-page.tsx`, `backtests-page.tsx`)을 깨지 않기 위해).
- 브라우저는 SSE로 진행만 구독한다. 창을 닫아도 계속 돈다. e2e가 "실행 중 다시 열기·일시정지"를 재현하도록
  실행을 붙잡아 두는 테스트 훅을 V3-04가 둔다(mock 실행은 1초 안에 끝난다).
- 스레드 모델은 유지한다. 대기열이 늘 겹쳐 돌면 `_gc_policy`의 참조 카운트가 0으로 돌아오지 않아 전체 GC가
  꺼지므로, 스케줄러 PR이 GC 정책을 주기 기반으로 다시 설계한다. 프로세스 워커는 non-goal이다.
- `application/experiment_run`은 backtest_run을 직접 부르지 않는다. 자기 `ports/outgoing`에 trial 실행 포트를
  두고, bootstrap이 backtest_run 스케줄러를 감싸 주입한다(`assistant_chat`의 `BacktestResultPort` 선례). 새
  application → application 화살표와 경계 규칙 변경은 없다.

### D7. 비용 칸 다섯 개를 RunEnvironment에 더한다

| 필드 | 값 | 기본값 |
|---|---|---|
| `sell_tax` | `krx_statutory`(시장·날짜별 법정 세율) · `custom` · `none` | `krx_statutory` |
| `sell_tax_bps` | `custom`일 때 매도 금액 대비 bp | 없음 |
| `impact_model` | `fixed_bps`(지금의 슬리피지) · `sqrt`(√ 시장충격) | `fixed_bps` |
| `impact_coefficient` | `sqrt`의 계수 k | 설계 PR에서 문헌값으로 정한다 |
| `participation_basis` | `session_volume`(당일 거래량) · `adv20`(20일 평균 거래대금) | `session_volume` |

- 법정 세율표의 owner는 `domain/backtest/_krx_tax.py` 하나다. 날짜 구간·시장별 행과 근거 법령·시행일을 함께
  적는다. **2026년 세율은 구현 PR에서 공포 법령으로 다시 확인한다.**
- `environment_hash`는 표시만 되고 비교하는 곳이 없다. 칸을 더해 해시가 바뀌는 것을 그대로 두고 판본을 따로
  두지 않는다. 시도 키는 D2의 기본값 생략 규칙으로 안정성을 따로 지킨다.
- `RunManifest`의 평면 비용 필드 대조(`NUMERIC_ENVIRONMENT_FIELDS`)는 평면 호환 집합을 따로 고정해
  새 제약 행이 `AttributeError`를 내지 않게 한다.
- 두 엔진 코어(Python reference, Rust)에 매도 전용 비용, √ 충격, ADV 기준 참여 한도를 같은 의미로 넣고
  `tests/test_core_parity.py`로 동등성을 지킨다.
- ADV는 원화 거래대금이므로 주식 수 한도로 바꾸는 규칙(판단일 종가 기준)을 같은 PR에서 정한다. 첫 20세션의
  ADV를 위해 `BacktestDataQuery`에 워밍업 칸을 더한다.

### D8. 검증 통계의 자리

| 통계 | 단위 | owner |
|---|---|---|
| 샤프 표준오차 | 실행 | Metric Registry(#274 4/4가 추가) |
| PSR(기준 0) | 실행 | Metric Registry |
| DSR | 계열 | `domain/experiment`의 함수. N과 시도 대표 샤프의 분산은 시도 원장이 공급한다. 입력 단위는 일간 샤프·252일·원(비초과) 첨도 |
| 워크포워드 유지율 | 실험 | `domain/experiment` |
| 이웃 평균 | 실험 | `domain/experiment`(V3-01) |
| ±20% 민감도·봉우리 판정 | 실험 | `domain/experiment`(V4-03) |
| 팩터 회귀(α·t·β, HAC) | 실행 | 회귀 계산은 `domain/analytics`의 새 함수. 시장 팩터는 유니버스 시가총액 가중 수익률(지수 데이터 GAP-09 우회). 규모·가치·모멘텀 롱숏 수익률은 Factor Registry의 기존 `factor_id`와 기존 평가 경로를 재사용하고 새 팩터 정의를 만들지 않는다. 데이터를 읽는 application 노드와 포트는 V4-05가 정한다 |
| 알파 t 기준 | 계열 | `domain/experiment`의 상수 하나: 계열 N이 20 이상이면 3.0, 아니면 2.0(Harvey·Liu·Zhu 2016) |
| 용량 한계 금액 | 실험(용량 스윕) | `domain/experiment` |

- 종합 점수는 만들지 않는다. 항목별 원 수치·쉬운 뜻·기준을 나란히 보인다(`frontend-ui-quality.md`).

### D9. 후보 선택은 기록이다

- 사용자가 후보를 고르면 selection record(실험, strategy_id, 리비전, 해소된 파라미터, trial id, 이유, 시각)를
  남긴다. 후보를 새 전략으로 저장하는 기능은 전략 복사(M8)와 함께 한다.

### D10. 화면 배치와 lang2

- 결과 화면은 탭을 만들지 않고 맨 위에 검증 카드 하나를 넣는다. 기존 지표·차트·Manifest는 그대로다.
- 실험은 새 라우트 `/research/experiments`다. 내비의 비어 있던 "실험" 자리를 켠다.
- IDE에는 제목 옆 계열 시도 배지와 상단 바 "실험으로 보내기" 버튼만 붙인다(lang2 P4-04 뒤).
- 레시피 카드의 탐색 대상 토글은 lang2 P5-02 뒤.
- 히트맵은 DOM 그리드와 새 팔레트 토큰(`--heat-1 … --heat-7`, 라이트·다크)으로 그린다. 새 차트 의존성은 없다.
- 화면 PR(V5)은 각 화면의 backend PR 뒤에 시작한다. 남은 lang2는 IDE 가운데 영역만 바꾸므로 IDE에 붙는 V5-07만
  lang2 P4-04·P5-02 뒤다(2026-09-29 제품 소유자 확인).

### D11. 홀드아웃은 한 번만 연다

- 사양 동결(전략 리비전·해소된 파라미터·실행 설정 hash·selection record) → 판정 기준 사전 등록 → 확인 →
  개봉. 봉인 원장에 개봉 시각·사양 hash·결과를 남긴다.
- 개봉 뒤 같은 계열의 재실행은 홀드아웃이 아니라 일반 검증으로 분류된다. 봉인 구간은 "열람됨"으로 영구
  표시되고 되돌릴 수 없다.
- 봉인 겹침으로 서버가 거절한 **실행** 요청(백테스트 실행 경로)은 봉인 원장의 "차단한 시도"로 남는다.
  미리보기·추적·팩터·equity 경로의 거절은 원장에 남기지 않는다(그 노드들에 원장 포트를 늘리지 않는다). 봉인
  겹침 거절의 정본은 봉인 원장이고, 시도 원장은 그 기록을 "N 제외"로 조회해 보인다(두 번 쓰지 않는다).
- #272 규칙과의 관계: 앱 안의 실행·개봉은 이 봉인 원장이 정본이다. 앱 밖(노트북·스크립트)의 연구 절차는 #272
  규칙이 정본이다. #272가 머지되면 그 규칙에서 앱 개봉은 이 원장을 따른다는 문장을 더하는 후속을 연다.

## 6. 완료 정의

- 연구 구간 밖 측정 요청이 모든 경로에서 코드화된 422로 막힌다.
- 서버를 재시작해도 실행 목록·결과·시도 원장·실험 진행이 남는다.
- 결과 화면이 계열 시도 수·DSR·워크포워드 유지율·고원·팩터 회귀·용량 한계를 원 수치로 보인다.
- 여러 실험을 대기열에 넣고 창을 닫아도 서버에서 돌고, 끝나면 알림이 뜬다.
- 새 유저 스토리(US-DM-10·11, US-SM-12~15, US-CS-09~13)가 `구현됨-e2e`다.
- 봉인 구간은 사양 동결·기준 사전 등록을 거친 한 번의 개봉으로만 열린다.

## 7. 테스트 원칙

- 통계는 손계산 정답이 있는 작은 곡선으로 검증한다(산출물 단언 금지).
- 시도 키는 분류표의 칸마다 "바꾸면 새 시도인가"를 변주 테스트로 고정한다.
- 대기열은 굶주림 없음, 공정 분배, 중복 1회 실행, 재시작 복구, 일시정지 뒤 순서를 테스트한다.
- 엔진 비용은 두 코어 parity와 손계산 소형 체결로 검증한다.
- frontend 테스트 규칙의 실패·중단 trial, 취소, 부분 결과 표시를 화면 PR에서 덮는다.

## 8. 대안과 기각 사유

| 대안 | 기각 사유 |
|---|---|
| 분할·탐색을 RunEnvironment에 넣기 | 실행 설정 패널이 스키마를 그대로 그려 단일 실행 화면에 칸이 생기고 `environment_hash` 의미가 바뀐다 |
| 봉인을 화면 경고로만 | 사람 의지로 지켜지지 않고 API·재실행 경로가 샌다 |
| 결과 화면에 검증 탭 | 결과 화면은 스크롤 한 장이고 IDE의 "중간 결과" 탭과 이름이 겹친다 |
| 파라미터를 바꾼 파생 spec을 실행 | 저장 리비전 provenance 불변식이 깨져 새 provenance 종류와 계약 변경이 번진다 |
| 설정 지문이 다르면 무조건 새 시도 | 종료일 연장·벤치마크 변경·비용 스트레스 점검까지 세어 "기록하면 손해" 구조가 된다 |
| 사용자 전체 N으로 판정 | 무관한 전략이 분포를 섞고, 탐색을 앱 밖으로 밀어내 원장이 부정직해진다 |
