# 정동민 유저 스토리

퀀트는 잘 모르는 국내 주식 개인 투자자다([페르소나](../personas.md#정동민-dm)). 쉬운 말과 AI
도움으로 자기 투자 감을 규칙으로 바꾸고 결과를 이해하는 것이 이 사람의 여정이다.

### US-DM-01 AI 공급자를 한 번 연결해 둔다

> 정동민으로서 설정 화면에서 AI 공급자를 한 번만 연결해 두고 싶다. 그래야 전략 화면에서 모르는
> 것을 바로 물어볼 수 있다.

- 상태: `구현됨-e2e`
- 담당 PR: 없음
- e2e 담당: 없음
- 기능 영역: 설정 · AI 공급자
- e2e:
  - `frontend/e2e/assistant.workflow.spec.ts` :: 설정에서 공급자를 등록하면 활성이 되고 키는 꼬리 4자리만 남는다

수용 기준

- Given 등록된 공급자가 없는 설정 화면, When 표시 이름과 API 키를 넣고 "연결 테스트 후 저장"을
  누르면, Then 그 이름의 카드가 생기고 "활성" 배지가 붙는다.
- Given 방금 저장한 공급자, Then 카드에는 키의 끝 네 자리만 보이고 키 입력칸은 비어 있으며 화면
  어디에도 키 원문이 없다.
- Given 저장된 공급자 카드, When "연결 테스트"를 누르면, Then "연결 확인됨"이 보인다.

### US-DM-02 모르는 말을 전략 화면에서 바로 묻는다

> 정동민으로서 전략 화면을 떠나지 않고 "모멘텀 전략이 뭐야?" 같은 질문을 하고 싶다. 그래야 따로
> 검색하느라 흐름이 끊기지 않는다.

- 상태: `구현됨-e2e`
- 담당 PR: 없음
- e2e 담당: 없음
- 기능 영역: AI 어시스턴트 · 사이드바 대화
- e2e:
  - `frontend/e2e/assistant.workflow.spec.ts` :: 사이드바 질문에 답이 스트리밍되고 새로고침해도 이력과 진행 중 턴이 이어진다

수용 기준

- Given 공급자가 연결된 전략 화면, When "AI 어시스턴트"를 펼치고 질문을 보내면, Then 대화 내용에
  질문과 답이 차례로 나타나고 진행 상태가 "답변이 완료되었습니다."로 바뀐다.
- Given 답을 받는 중, When 화면을 새로고침하면, Then 사이드바가 열린 채로 돌아오고 받던 답이
  중복 없이 이어진다.
- Given 긴 답을 받는 중, When "중지"를 누르면, Then 입력칸이 다시 열리고 그 답 아래에 "요청을
  취소했습니다."가 남는다.

### US-DM-03 말로 한 아이디어를 AI가 전략으로 바꿔 주고 바로 백테스트한다

> 정동민으로서 빈 새 전략 화면에서 투자 아이디어를 말로 설명하고, AI가 만든 전략을 확인한 뒤 바로
> 돌려 보고 싶다. 그래야 YAML을 몰라도 내 감이 과거에 통했는지 알 수 있다.

- 상태: `구현됨-e2e`
- 담당 PR: 없음
- e2e 담당: 없음
- 기능 영역: AI 어시스턴트 · 새 전략 · 제안 적용 · 백테스트
- e2e:
  - `frontend/e2e/stories/dm.ai-new-strategy.spec.ts` :: US-DM-03 빈 새 전략에서 AI에게 아이디어를 말해 받은 전략을 적용하고 백테스트한다
  - `frontend/e2e/stories/dm.ai-new-strategy.spec.ts` :: US-DM-03 사이드바와 계약 서랍을 어느 입구로 펼쳐도 머리 줄이 펼친 자리에서 눌린다
  - `frontend/e2e/stories/dm.sidebar-scrollbar.spec.ts` :: US-DM-03 스크롤바가 폭을 차지하는 창에서도 사이드바가 붙었다 떴다 하지 않는다
  - `frontend/e2e/assistant.workflow.spec.ts` :: 제안 카드를 미리 보고 적용하고 실행 취소·다시 실행한 뒤 적용 후 백테스트가 실행 화면까지 간다

수용 기준

- Given 처음 여는 편집기(1280px 이상), Then AI 열이 본문 왼쪽에 열려 있고 입력칸 안내가 "생각을 말로 적어
  주세요"로 시작한다. 사용자가 AI 열을 접어 두면 그 선택이 저장돼 다음에도 접힌 채로 열린다(저장 기록에 AI 열
  값이 없을 때만 새 기본값 "열림"을 쓴다, RD-04-A). 1280px 미만에서는 왼쪽에서 나오는 서랍이다. AI 공급자가
  없으면 AI 열에 "연결된 AI 공급자가 없습니다"와 "설정 열기"가 보이고 편집은 그대로 된다.
- Given 빈 새 전략 화면(백테스트가 막혀 있다), When 사이드바에서 "최근 많이 오른 대형주를 사는 새
  전략"처럼 아이디어를 말하면, Then 전략 전체를 담은 제안 카드가 "검증 통과" 배지와 함께 뜬다.
- Given 그 카드와 비어 있는 실행 설정, When "적용 후 백테스트"를 누르면, Then 문서 상태가 "검증 통과"가
  되지만 백테스트는 시작하지 않고, 알림이 "백테스트를 시작하지 않았습니다" 뒤에 "실행 설정에서
  시작일·종료일·유니버스 칸을 채우세요."를 붙인다. 실행 설정은 전략 문서 밖이라 AI 적용이 채우지 않는다.
- 실행 설정 채우기: Given 그 상태, When 요약 띠의 "실행 설정 채우기"를 누르면, Then 실행 설정 패널이 열리고
  시작일 칸에 초점이 간다. 기간·유니버스를 정하면 "백테스트"가 열리고, 저장하지 않은 채로 누르면
  실행이 접수되고 목적지가 해당 결과 화면인 경우, 확인 창은 "실행이 접수됐습니다. 결과 화면으로 이동할까요?"라고
  말한다. "결과 보기"를 누르면 결과 화면까지 간다. 일반 편집 이탈의 변경 보존 경고는 그대로다.
- Given 사이드바를 연 1440px 편집 화면, Then 편집기 툴바의 실행 설정·검증·리비전 저장·백테스트, 보기 탭
  (Graph·Diff), 문서 상태와 "전략 편집"·"중간 결과" 작업공간 전환이 옆 칸이나 겹쳐 뜬 패널에 깔리지 않아 마우스로 누를 수 있다.
  편집기 칸이 최소 폭(480px)을 지키지 못하면 나중에 연 패널이 겹쳐 뜬다 — AI 열은 왼쪽 자기 자리에, 계약은
  오른쪽 자기 자리에 뜬다(#269, #290 리뷰 P2-1, RD-04-A). 전략 구조를 접어 사이드바를 계약 옆에 붙인 1440px과 1280px 기본 화면에서도
  같다 — 칸이 좁으면 툴바와 탭 줄이 다음 줄로 내려간다(#296).
- Given 겹쳐 뜨는 서랍(1440·1280px 사이드바, 1440px에서 사이드바를 붙인 뒤 연 계약, 1200px 좁은 화면의
  사이드바·계약), When 서랍을 펼치면(사이드바는 상단 바 토글·Alt+A·명령 팔레트 어느 쪽으로든), Then 페이지가
  굴러가지 않고 서랍은 상단 바·실행 설정 띠 아래 본문 높이에 떠서, 머리 줄의 제목과 닫기("사이드바 닫기"·
  "계약 접기")가 펼친 자리 그대로 상단 바에 깔리지 않고 눌린다(#325, #290 리뷰 r3 P2-1).
- Given 페이지 세로 스크롤바가 폭을 차지하는 창(Windows 기본)에서 사이드바를 붙이면 페이지가 길어져
  스크롤바가 생기는 크기, Then 사이드바는 한 자리에 머물고 붙었다 떴다를 되풀이하지 않는다(#290 리뷰
  P1-1).
- Given 저장한 전략의 사이드바, When 전략을 제안해 달라고 물으면, Then 제목·"검증 통과" 배지·출처
  링크가 있는 제안 카드가 뜬다. 출처 옆에는 링크가 실제로 가는 호스트가 보인다.
- Given 제안 카드, When "미리보기"를 누르면, Then 지금 문서와의 차이 표가 뜨고 취소하면 문서는 그대로다.
- Given 제안 카드, When "문서에 적용"을 누르면, Then "제안을 문서에 적용했습니다."가 보이고 문서
  상태가 "검증 통과"다. 제안이 바꾼 줄 말고는 문서가 그대로다.
- Given 적용해서 문서가 제안의 기준 원문과 달라진 상태, When "적용 후 백테스트"를 누르면, Then
  "문서가 바뀌었습니다" 확인을 거쳐 백테스트 실행 화면으로 가고 결과가 나온다.
- 비고: 대본 공급자의 "새 전략" 대본은 authoring schema를 따르는 본문을 가진다. schema 1.2(P2-03)부터
  본문에 기간·유니버스(`data`)와 수수료(`execution`) 섹션이 없고, 모멘텀은 수정주가 `price.adj_close`로
  잰다. `tests/application/test_scripted_idea_proposal.py`가 본문이 현재 schema로 compile되는지 고정한다.
- 비고: 백테스트·추적 전에 실행 설정 패널에서 기간과 유니버스를 정한다(US-DM-05).

### US-DM-04 백테스트 결과에서 핵심 숫자와 자산 곡선을 본다

> 정동민으로서 백테스트가 끝나면 긴 표보다 핵심 숫자 몇 개와 자산 곡선부터 보고 싶다. 그래야 이
> 규칙을 더 파볼지 빨리 정할 수 있다.

- 상태: `구현됨-e2e`
- 담당 PR: 없음
- e2e 담당: 없음
- 기능 영역: 백테스트 결과 · 실행 이력
- e2e:
  - `frontend/e2e/stories/dm.backtest-result.spec.ts` :: US-DM-04 저장한 전략을 백테스트하면 결과 한눈에·두 축 카드·자산 곡선이 보인다

수용 기준

- 실행 설정 채우기: Given 검증을 통과해 저장한 전략과 비어 있는 실행 설정, Then "백테스트"가 막혀 있고 요약
  띠가 "실행 설정에서 시작일·종료일·유니버스 칸을 채우세요."라고 말한다. When 띠의 "실행 설정 채우기"를 누르면, Then
  패널이 열리고 시작일 칸에 초점이 간다. 기간·유니버스를 정하면 "백테스트"가 열린다.
- 같은 상태(실행 설정만 빈 저장한 전략)에서 명시해서 연 "중간 결과" 작업공간도 막힌 이유를 "추적은 실행 설정 위에서
  돕니다."라는 한 문장으로만 말한다. "현재 실행 가능한 문서가 없습니다." 같은 문서 탓 문장은 함께 뜨지 않는다
  (이슈 #260).
- Given 기간·유니버스를 채운 뒤 초기 자본을 0으로 바꾼 상태, Then "백테스트"가 막히고 요약 띠가 "실행 설정의
  초기 자본 칸을 고치세요: 0보다 큰 숫자를 입력하세요."라고 말한다. When 띠의 "실행 설정 고치기"를 누르면,
  Then 패널이 열리고 초기 자본 칸에 초점이 간다. 값을 고치면 "백테스트"가 다시 열린다(이슈 #260).
- Given 검증을 통과해 저장하고 실행 설정을 채운 전략, When "백테스트"를 누르면, Then 실행 화면으로 가고
  실행 상태가 "완료"가 된다. 서버가 시작을 거절하면 툴바가 "백테스트 시작 실패: " 뒤에 거절 코드의
  한글 문장을 보이고, 서버 원문은 접힌 "서버 사유"에 둔다. 거절이 칸을 짚으면 "서버가 실행 설정의 초기 자본 칸
  값을 받지 않았습니다."처럼 그 칸 이름을 말한다(새 전략·저장한 전략 화면 모두). 영문 진단(`API request
  failed …`)은 보이지 않는다.
- Given 완료된 결과, Then "초기자본 기준 계좌 요약"에서 서버가 계산한 초기자본·최종 평가액·비용
  반영 후 손익·초기자본 대비 수익률을 읽는다. 초기자본은 날짜 없는 시작조건이고, 실제 첫 기록일·마지막
  기록일·기록 수와 마지막 현금은 별도로 보인다. 평가액이 모두 팔아 돌려받는 현금이 아니고 비용이 기반
  결과에 반영됐다는 서버 해석을 그대로 보인다. 아래 전체 구간(FULL)의 총수익률은 첫 계좌 기록에서 시작하므로 기준이 다름을
  말하고 기존 지표·차트·거래·재현성 정보는 계속 보인다.
- Given 계좌 요약을 계산할 기록이 없거나 입력값이 유효하지 않은 결과, Then 서버 상태와 사유를 보이고
  0원이나 가짜 차트 시작점을 만들지 않는다. 유효한 0원·음수는 결측으로 바꾸지 않는다. 계좌 요약 조회가
  실패해도 기존 결과는 보이고, 일시적 서버·연결 오류에만 "계좌 요약 다시 불러오기"를 보인다. 404·409·410은
  기존 오류 번역으로 안내하고 자동·수동 재시도를 하지 않는다. 브라우저 e2e는 보고서만 503으로 실패할 때
  원본 결과를 유지하고 실제 서버 값으로 다시 불러오는 복구 흐름과, 410일 때 원본 결과를 유지하면서 재시도가
  없는 흐름을 확인한다. 나머지 오류·빈 기록·실행 전환 경계는 frontend `backtest-account-report.test.tsx`가
  통신 경계에서 확인한다.
- Given 완료된 결과, When 목차에서 "초기자본 기준 계좌 요약"을 키보드로 선택하면, Then 요약으로
  초점이 이동한다. 360px 화면에서도 긴 금액과 재현성 식별자가 잘리지 않고 줄바꿈되며 계좌 요약이
  가로로 넘치지 않는다. 브라우저 e2e는 실제 mock backend 보고서 값과 표시값을 대조한다.
- Given 완료된 결과, Then 결과 화면은 결론부터 읽는 순서다: "결과 한눈에" → "운일까, 튼튼할까"(US-DM-10) →
  "자산 곡선과 낙폭" → "종목 선정과 손익 구조" → "월별 수익률" → 청산 거래·주문 상태 기록 → 용량 확인 →
  계좌 요약 → 원본 지표 표(Raw metric table) → "Manifest · 데이터 경고 · 재현성 정보". 머리말에는 "동일 설정
  재실행", "AI에게 결과 묻기"가 있고, 저장 리비전으로 돈 실행이면 그 리비전 편집기로 가는 "규칙 고치기"가
  있다(인라인 초안은 돌아갈 문서가 없어 두지 않는다).

### US-DM-05 기간·유니버스·수수료·슬리피지를 전략 밖 실행 설정에서 정한다

> 정동민으로서 테스트 기간과 종목 범위, 거래 비용을 화면의 실행 설정에서 고르고 싶다. 그래야 전략
> 글을 건드리지 않고 조건만 바꿔 다시 돌려 볼 수 있다.

- 상태: `구현됨-e2e`
- 담당 PR: 없음
- e2e 담당: 없음
- 기능 영역: 실행 설정(`RunEnvironment`) · 백테스트
- e2e:
  - `frontend/e2e/stories/dm.run-environment.spec.ts` :: US-DM-05 날짜 칸에 숫자를 이어 치거나 대시를 넣어 쳐도 그 날짜가 들어가고, 덜 친 날짜는 칸이 알려 준다
  - `frontend/e2e/stories/dm.run-environment.spec.ts` :: US-DM-05 실행 설정에서 기간만 바꿔 다시 돌려도 전략은 그대로이고 실행 기록에 바꾼 기간이 남는다
  - `frontend/e2e/stories/dm.layout-polish.spec.ts` :: US-DM-05 밝은·어두운 데스크톱과 좁은 화면에서 실행 설정을 읽고 키보드로 여닫는다

수용 기준

- Given 저장한 전략, When 실행 설정을 열면, Then 시장·빈도·체결 시점·수수료·참여율·슬리피지·결측
  처리가 서버가 준 기본값으로 채워져 있다. 서버가 기본값을 주지 않는 기간·유니버스는 이 브라우저에서
  처음 쓸 때 비어 있고, 정하기 전에는 백테스트가 막힌다.
- Given 실행 설정 패널, Then 기간·종목 범위를 먼저 채우고 비용·고급 실행은 기본 접힌 묶음으로 읽는다.
  접힌 묶음은 현재 조건과 오류를 요약하며, "실행 설정 고치기"가 비용·고급 칸을 가리키면 해당 묶음을
  자동으로 펼친 뒤 그 칸에 초점을 옮긴다. 모든 기본값·입력·검증 의미는 그대로다.
  묶음의 값이 모두 서버 기본값 그대로면 요약 줄에 "기본값" 배지가 붙고, 한 칸이라도 바꾸면 배지가 사라지고
  바뀐 값이 요약에 보인다. 벤치마크 칸 설명은 시장지수 추종 ETF를 기준으로 비교한다고 말한다(RD-05-A).
- Given 실행 설정에서 기간만 바꾼 상태, When 백테스트를 돌리면, Then 전략 문서는 바뀌지 않고
  결과 화면의 실행 기록에 바꾼 기간이 보인다(같은 strategy hash, 다른 실행 설정 hash).
- Given 전략 화면 상단, Then 지금 실행 설정의 요약 띠가 보인다. 모바일 기본 띠는 현재 준비 상태와
  채우기/고치기 행동에 집중하며, "전체 실행 조건"을 펼치면 기간·비용 등 전체 값과 "전략 문서 밖의 설정"임을 읽는다.
- Given 기간·유니버스를 정한 뒤 수수료를 -1로 바꾼 상태, Then 백테스트가 막히고 요약 띠가 "실행
  설정의 수수료 칸을 고치세요: 0bp 이상이어야 합니다."라고 말한다. When 띠의 "실행 설정 고치기"를
  누르면, Then 패널이 열리고 수수료 칸에 초점이 간다. 여러 칸이 틀리면 패널 순서의 첫 칸을 말하고
  나머지 개수를 붙인다.
- Given 실행 설정 패널, Then 매도 거래세율 칸은 매도 거래세가 "직접 입력"일 때만, 가격 충격 계수 칸은
  가격 충격 모델이 "√ 가격 충격"일 때만, 슬리피지 칸은 "고정 bp(슬리피지)"일 때만 켜진다. When 매도
  거래세를 "직접 입력"으로 바꾸고 세율 칸을 비워 두면, Then 백테스트가 막히고 요약 띠가 "실행 설정에서
  매도 거래세율 칸을 채우세요."라고 말한다. When 방식을 되돌리면, Then 세율 칸이 꺼지고 그 칸에 남은 값은
  실행에 쓰이지 않아 백테스트를 막지 않는다(#352).
- Given 비어 있는 시작일 칸, When 키보드로 `20210101`을 이어 치거나 `2021-01-01`을 치면, Then 칸에
  `2021-01-01`이 들어간다(연도 4자리 뒤에 월로 넘어간다). When 연도만 치고 칸을 떠나면, Then 칸은 비어
  있고 칸 아래에 "값을 정하세요." 대신 "연·월·일을 모두 올바르게 입력하세요. 예: 2021-01-01"이 뜬다
  (이슈 #264). 요약 띠도 "채우세요"가 아니라 "실행 설정의 종료일 칸을 고치세요: 연·월·일을 모두 올바르게
  입력하세요. …"로 같은 원인을 말한다(#266 리뷰 P3-1). 날짜 칸은 1900-01-01부터 9999-12-31까지 받는다. 선택 칸인 OOS 시작일은 비우면 OOS 없이

  포트폴리오 구성, 리스크 제약, 확인)가 보이고 1단계가 열려 있으며, "편집기에서 직접 쓰기"로 지금 편집기에
  바로 갈 수 있다. 단계는 스키마 `x-stage`가 붙은 최상위 섹션 순서이고 화면이 단계 목록을 따로 적지 않는다.
- When 알파 팩터 단계를 연다, Then 가격·재무·컨센서스·수급·공매도·신용·이벤트 분류 칩과 분류별 개수가 보이고,
  칩을 누르면 그 분류의 팩터만 남는다.
- Given 팩터가 "준비 중"(계산식 없음) 또는 "데이터 없음"이다, When 목록을 본다, Then "담기"가 꺼져 있고
  이유("계산식이 아직 없어 담을 수 없어요." 등)가 보인다. 이미 담은 팩터는 "이미 담았어요."로 막는다.
- When 팩터를 담는다, Then 오른쪽 "전략 문서 미리보기"의 `factors`에 항목이 생기고 바뀐 줄이 강조된다. 담긴
  값은 편집기 스니펫과 같은 카탈로그 preset이다.
- When 한 단계를 기본값 그대로 두고 넘어간다, Then 그 단계의 칸은 문서에 쓰이지 않는다.
- When 단계 목록을 본다, Then backend 오류 진단(칸·목록·단계 섹션·문서 전체)이 붙은 단계는 "오류 N"이다. 오류가
  없을 때 기본값 없는 필수 칸이 있는 단계는 그 칸을 모두 채우면, 필수 칸이 없는 단계는 값을 쓰거나 한 번
  지나가면(기본값을 받아들임) 체크와 "(완료)"로 보인다. 목록 아래에 "N / 6 단계 완료"(확인 단계 제외)가 보인다. 지금 단계 카드는 "N단계 / 7" 머리, 본문,
  "이전"·"다음: 다음 단계 이름" 바닥으로 나뉜다. 유니버스의 거르기 규칙은 규칙마다 머리 띠(이름·삭제)가 있고,
  오류가 있는 규칙은 머리 띠가 오류 톤이며, 목록 아래에 스키마 설명("모두 만족하는 종목만 남습니다.")이 보인다.
- Given AI 공급자가 연결돼 있다, When 안내를 연다, Then 오른쪽 칸은 "AI 도우미 | 전략 문서 미리보기" 탭이고
  AI 도우미가 먼저 열린다(없으면 미리보기가 먼저이고 AI 탭은 설정 링크를 보인다). 공급자 목록이 오기 전에는 탭을
  정하지 않고, 한 번 정한 기본 탭은 목록이 다시 읽혀도 바뀌지 않는다. URL `assist`에 적힌 탭이 언제나 먼저이고,
  탭을 바꿔도 치던 문장·대화가 남는다. 미리보기 탭에는 방금 바뀐 줄 수가 붙는다.
- When AI 도우미의 단계별 추천 질문을 누른다, Then 입력칸만 그 문장으로 채워지고 보내지지 않는다. 사용자가 쓴
  미전송 문장이 있으면 덮지 않고 줄을 바꿔 뒤에 잇고, 답변이 진행 중이면 추천 질문은 꺼진다. 단계를 옮기면
  고치지 않은 앞 단계 추천 질문은 입력칸에서 지워진다. When 제안을
  "문서에 적용"한다, Then 편집기와 같은 전체 문서 교체로 들어가 안내 칸과 단계 상태가 따라 바뀐다. 안내에는
  실행 설정이 없어 "적용 후 백테스트"는 없다.
- When 단계마다 처음 화면을 본다, Then 카드 문장 틀이 있는 핵심 칸만 보이고, 문장 틀이 없거나 기본으로 꺼진
  기능(점수 하한·레짐·유동성·보조 순위처럼 기본값이 없는 칸)은 "더 설정하기"에 접혀 있다. 이미 문서에 쓴 칸은
  접지 않는다.
- When 확인 단계를 본다, Then 전략 한 문장 요약, 문제 목록, 선정 미리보기, "저장하고 백테스트 준비"와
  "편집기에서 열기"가 보인다. When "편집기에서 열기"를 누르면, Then 같은 초안이 그래프 보기로 열리고, 안내에서
  만든 문서와 같은 내용을 편집기에서 직접 쓴 문서의 `spec_hash`가 같다.
- 비고: 안내의 모든 선택은 편집기와 같은 source 트랜잭션이라 "되돌리기" 한 번이 선택 하나를 취소한다. 안내용
  별도 상태나 직렬화 모델은 없다. 목록에 없는 팩터는 "항목 추가" 뒤 "레시피 열기"로 직접 만든다. 분류 칩·준비
  중 팩터·건너뛰기 무기록·접기는 frontend `document-routes.test.tsx`도 확인한다. 팩터 카탈로그를 주 진입
  경로에 쓰는 것은 2026-10-19 제품 결정이다(`docs/planning/strategy-language-2-0/PLAN.md` "현재 결정").

### US-DM-15 앱을 열면 이어서 할 일과 돌고 있는 일을 먼저 본다

> 정동민으로서 앱을 열었을 때 끝난 실험, 실패한 실행, 저장 안 한 초안과 지금 돌고 있는 작업을 먼저 보고 싶다.
> 그래야 어디서부터 이어 갈지 바로 정하고, 백테스트 손익을 실제 계좌 손익으로 착각하지 않는다.

- 상태: `구현됨-e2e`
- 담당 PR: 없음
- e2e 담당: 없음
- 기능 영역: 연구 홈 · 실험 목록 · 백테스트 이력 · 로컬 초안
- e2e:
  - `frontend/e2e/stories/dm.research-home.spec.ts` :: US-DM-15 연구 홈은 최근 결과와 작업 기록을 보이고 계좌 칸에는 숫자 없이 미연결만 말한다

수용 기준

- Given 완료됐지만 후보를 고르지 않은 실험이 있다, When 앱 첫 화면(`/`)을 열면, Then "오늘 이어서 할 일"에
  "후보 선택 대기"와 "후보 보기" 버튼이 보인다(RD-01-A).
- Given 최근 백테스트가 실패했다, When 홈을 열면, Then 실패한 단계와 쉬운 원인 한 줄, "원인 보기" 버튼이 보인다.
- Given 저장하지 않은 로컬 초안이 남아 있다, When 홈을 열면, Then "저장 안 됨" 항목과 "이어서 편집" 버튼이
  보이고, 누르면 그 초안의 편집기가 열려 복구 안내가 보인다.
- Given 할 일이 없다, When 홈을 열면, Then 제목이 "이어서 할 일이 없어요"로 바뀌고 최근 결과가 같은 화면에 보인다.
- When 홈을 열면, Then "계좌 손익" 카드에 "미연결" 배지와 "지금 보이는 손익은 모두 백테스트·모의 계산"이라는
  문장이 보이고 금액 숫자는 하나도 없다(RD-01-B).
- Given 실험·백테스트가 돌고 있다, When 홈을 열면, Then "진행 중"에 진행 막대와 단계, "동시 실행 슬롯 n / m"이
  보인다. 최근 완료한 백테스트는 "최근 결과" 표에 전략·버전과 총수익률·샤프·최대 낙폭으로 보인다(RD-01-C).
- When 홈을 열면, Then "작업 기록"에 리비전 저장·백테스트 종료·실험 시작·후보 선택이 최근부터 보이고 주문·체결
  운영 로그가 아니라는 문장이 함께 보인다(RD-01-D).
- Given 저장한 전략이 하나도 없다, When 홈을 열면, Then "첫 전략을 만들어 보세요"와 단계별 안내로 가는
  "새 전략 만들기" 버튼이 보인다.
- 비고: 할 일·결과·기록은 실험 목록 첫 쪽과 최근 단일 백테스트 20건, 최근 저장 전략 10개를 조합한다. 리비전 저장은
  전략 목록의 최신 저장 시각만 쓴다. 서버 초안은 목록 API가 없어 로컬 자동 보관 초안만 할 일에 든다. 벤치마크 대비
  열·데이터 경고 카드·실험 남은 시간은 결과·실험마다 요청이 필요해 이번 범위에서 뺐다. 옛 빌더 북마크
  (`/?step=…&run=…`)는 예전처럼 새 전략 편집기로 간다. 할 일·빈 화면 분기는 `src/app/__tests__/router.test.tsx`가 본다.
