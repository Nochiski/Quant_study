# Strategy Workbench UI 디자인 기준

2026-10-17 사용자 요청에 따른 UI/UX 재정비 기준이다. 제품의 행동·수용 기준은
[유저 스토리](../../docs/product/user-stories/README.md)가 소유하고, 이 파일은 화면의 위계·배치·
공통 요소 계약을 소유한다. 실제 CSS 변수와 테마 값은
[tokens.css](../../frontend/src/app/styles/tokens.css), 공통 요소 구현은
[primitives.css](../../frontend/src/shared/ui/primitives.css)가 소유한다. 별도 페이지별 규칙 문서를
추가하지 않고 이 기준 안에서 화면에 맞는 밀도를 선택한다.

## 의도

사용자가 지금 작업하는 대상, 다음 행동, 결과와 근거를 순서대로 읽게 한다. 제목 크기만 키우는
변경을 피하고, 전체 페이지의 시작선·폼의 기준선·접는 제어의 위치를 함께 맞춘다. 작성 도구는
편집 공간을 지키고, 결과 화면은 금액·기간·위험을 먼저 읽히게 한다. 템플릿을 첫 진입로로 강제하지
않으며 YAML과 그래프, AI를 같은 전략을 다루는 표현으로 유지한다.

이번 작업은 UI/UX까지다. 백엔드·API·계산 규칙·성과 값·원장의 의미·브로커 연결은 변경하지 않는다.
새 라이브러리나 외부 폰트를 추가하지 않는다.

## 스토리에서 정한 읽기 순서

| 사용자 흐름 | 근거 | 화면의 우선순위 |
|---|---|---|
| 아이디어를 전략으로 만들고 실행 조건을 채운다 | US-DM-03·05, US-SM-01·04 | 현재 문서/저장 상태 → 편집 → 기간·유니버스·비용 → 검증·저장·백테스트 |
| 원문과 계산 구조를 확인하며 편집한다 | US-SM-02·03, US-CS-01·02·03·07 | 선택한 경로/노드 → 편집 또는 중간 결과 작업공간 → 단위·범위·진단·중간값. 구조·계약은 기본 접힘이고, 명시한 탐색·검사 행동으로 연다. 보조 패널은 창 안에서 높이가 제한되며 현재 작업의 입력·결과 상태를 보존한다 |
| 결과가 어떤 조건에서 나온 것인지 판단한다 | US-DM-04, US-SM-05·14·15, US-CS-09 | 평가 방식·실제 기간 → 주요 금액/위험 → 곡선/전체 지표 → 체결·출처·경고 |
| 공급자를 연결하거나 설정을 바꾼다 | US-DM-01, US-SM-10 | 현재 연결 상태 → 필수 입력 → 확인 행동 → 고급 옵션·진단 |

낯선 금융 용어의 쉬운 설명, 오류의 원인과 다음 행동, 전체 원시 지표는 보존한다. 요약 점수 하나로
위험·비용·실행 조건을 숨기지 않는다. 실험의 창별 재시작 비교와 연속 계좌 결과는 제목·설명·영역을
분리하며 색만으로 평가 방식을 구분하지 않는다.

## 배치와 밀도

- **앱 셸:** 탐색과 화면 제목의 계층을 구분한다. 탐색은 안정된 아이콘 열과 문구 열을 쓰고,
  플랫폼마다 모양과 기준선이 달라지는 emoji·유니코드 장식 아이콘을 사용하지 않는다.
- **일반 페이지:** 단 하나의 `.page`가 좌우 여백을 소유한다. 기본 24px, 720px 이하 16px이다.
  헤더·패널·목록의 왼쪽 시작선은 같다. 일반 자료 화면은 최대 1280px, 설정·입력 중심 화면은
  최대 960px 안에서 읽는다. 패널마다 별도 외곽 여백을 다시 더하지 않는다.
- **편집 워크스페이스:** 창 높이 안에서 문서 제목·저장 상태·주 행동을 한 문맥으로 묶는다.
  문서 해시·스키마 등 상세 신원은 문서 정보에서 한 번 읽는다. 실행 요약은 기간·투자대상·핵심 비용과
  다음 행동에 집중하고 전체 조건은 명시해서 펼친다. YAML과 그래프 표현은 같은 원문·이력을 사용한다.
  편집과 중간 결과는 명시적인 작업공간 전환이며 전환해도 입력·선택·응답과 undo를 잃지 않는다.
  AI 작성 입력과 계약의 핵심 정보는 긴 페이지 아래로 밀리지 않고 가용 높이 안에서 읽는다.
  AI는 최초 열기 이후 같은 DOM 위치의 인스턴스를 유지하고 레일·서랍 배치만 바꾼다. 작업공간·화면 폭
  전환이 미전송 문장·수동 대화 선택·진행 중 대화의 소유자를 재마운트해서는 안 된다.
- **패널:** 기본 내부 여백은 20px, 밀집된 inspector·도구 패널은 16px이다. 큰 구획 사이는
  24px, 관련 요소 사이는 12px, 라벨과 입력 사이는 6px이다. 테두리를 두른 패널을 반복해서
  중첩하지 않는다. 기본 패널은 얕은 테두리로 나누고, 떠 있는 메뉴·팝오버에만 확실한 그림자를 쓴다.
- **중간 결과:** 작은 부록 패널을 폐기하고 주 작업공간의 가용 폭·높이를 사용한다. 저장된 과거
  분할 높이는 현재 작업공간 크기를 제한하지 않는다. 범위 입력은 라벨·컨트롤 기준선을 맞추고,
  출처·장문 경고는 요약 뒤에 원문 전체를 펼친다. 탭과 해석 가능한 결과 본문을 함께 읽는다.
  일반 노드 체인은 결과의 주 스크롤 안에서 읽으며, 대량 행·노드의 가상화는 보존한다.
  모바일은 범위 입력 후 결과를 우선하고 종목을 선택해 단계를 세로로 읽는다. 작은 칸에 모든 단계를
  가로로 압축하거나 손잡이 확대를 반복해야만 작업할 수 있는 전제를 두지 않는다.
- **작은 화면:** 도구 모음은 의미 있는 행동 묶음 단위로 줄바꿈한다. 입력은 부모 너비를 넘지
  않는다. 표·코드처럼 폭이 필요한 내용만 이름과 키보드 초점을 가진 내부 스크롤을 쓴다.

간격의 기본 배수는 4px이며 기존 `--space-1`~`--space-6`의 4/8/12/16/24/32px를 유지한다.
48px 큰 구획 간격을 추가하고 페이지·패널·폼에는 의미를 드러내는 별도 토큰을 사용한다.

## 글자 위계

파라미터 지도는 `--heat-1`~`--heat-7`을 사용해 같은 실험 전체의 서버 칸/고원 점수를 상대색으로 비교한다.
기본 고원 점수와 칸 점수 전환을 명시하고 페이지·고정값 변경으로 범례 범위를 바꾸지 않는다. 동일값은 한 색,
결측·실패/파산은 별도 상태·빗금으로 남긴다. 추천은 실선, 봉우리는 점선 윤곽과 문구로 구분하며 색 농도로
추천을 대신하지 않는다. 숫자는 각 테마 `--text`를 사용해 모든 단계에서 4.5:1 이상 읽히게 한다.
유효값 전체의 최솟값·최댓값은 기본 영역, 실제 7구간 경계는 native 접힘 범례에서 원수치로 읽는다.

번들된 Noto Sans KR Variable과 JetBrains Mono Variable을 유지한다. 본문에 모노스페이스를 쓰지
않고 식별자·코드·숫자 정렬에만 쓴다. 숫자는 tabular-nums로 자릿수의 흔들림을 줄인다.

| 역할 | 토큰 | 크기 | 굵기·행간 |
|---|---|---:|---|
| 일반 페이지 제목 | `--text-size-page-title` | 28px | 700 / 1.35 |
| 구획·카드 제목 | `--text-size-section-title` | 20px | 700 / 1.35 |
| 하위 구획 제목 | `--text-size-subsection` | 16px | 600 / 1.4 |
| 본문·일반 입력 값 | `--text-size-body` | 14px | 400 / 1.6 |
| 폼 라벨·압축 툴바 | `--text-size-label` | 13px | 500~600 / 1.45 |
| 부가 정보·밀집 표·키 힌트 | `--text-size-small` | 12px | 400~500 / 1.5 |

기존 `--text-size-title` 20px와 `--text-size-display` 28px는 호환성을 위해 남긴다. 한 legacy
토큰을 일괄 28px로 바꾸어 구획 제목까지 커지게 하지 않는다. 화면별 용례를 확인해 역할 토큰으로
이관한다. 800 굵기를 모든 제목·금액에 반복하지 않으며 `--font-weight-strong`은 700으로 정리한다.
12px 컨테이너 안에 `0.875em`을 다시 곱해 10.5px가 되는 구성은 피한다. 보조 정보도 명시 크기를 쓴다.

전역 h1~h6에 큰 크기나 외곽 여백을 강제하지 않는다. 페이지·구획·도구 패널의 문맥에 맞춰 정한다.

## 공통 컨트롤 계약

| 용도 | 높이 | 값 글자 | 적용 |
|---|---:|---:|---|
| 일반 폼·주 행동 | 40px | 14px | `--control-height`, `.ui-input`, `.ui-select`, 기본 `.ui-button` |
| inspector·편집 툴바 | 34px | 13px | 부모의 `--control-size: var(--control-height-compact)` |
| 표 안의 보조 행동 | 28px | 12px | `.ui-button--small`, `--control-height-dense` |

- 라벨은 입력 위에서 시작하고, 같은 행의 버튼과 입력은 입력의 외곽 높이에 맞춘다. 라벨·설명·오류
  글까지 포함한 전체 박스의 중앙에 버튼을 맞추지 않는다.
- `.ui-input`과 `.ui-select`는 opt-in 공통 클래스다. 기존 범위의 너비·표면·배치 책임은 화면에
  남는다. 모든 `input`이나 `select`에 appearance·고정 높이를 강제하지 않는다. 체크박스·라디오·
  range·여러 항목 선택 상자는 이 계약에 억지로 끼우지 않는다.
- 단일 `.ui-select`는 오른쪽 화살표를 위해 공간을 예약하고 표식의 끝 여백을 12px로 고정한다.
  native select·option과 키보드 조작은 유지한다. 선택 메뉴 자체를 JS로 다시 만들지 않는다.
- `.ui-disclosure > summary`는 고정된 표식 열을 쓰고 글자/배지와 간격을 둔다. 열림에 따라
  표식만 회전한다. `details`의 native 열린 상태·Enter/Space·접힌 내용 비노출을 유지한다.
  기존 접기 버튼은 `.ui-disclosure-toggle`과 `aria-expanded`, treeitem 안의 장식 span은
  `.ui-disclosure-caret`과 `data-open`·`data-empty`로 같은 슬롯을 재사용한다. 기존 클릭·키보드
  소유자는 그대로 두고 장식 span은 aria-hidden으로 읽기 순서에서 제외한다.
- 실행 설정은 기간·종목을 먼저 보여 주며 비용·고급 실행 묶음은 기본 접힘이다. 접힌 묶음에도
  현재 조건·오류를 요약하고, 오류 칸으로 이동할 때 해당 묶음을 펼친다.
- 실행 설정은 비모달이다. 초점이 설정 전체(details) 밖의 실제 요소로 이동하면 패널만 닫고
  외부 요소의 원래 초점을 유지한다. 내부 칸·닫기 단추·summary 사이 이동이나 이동 대상이 없는
  blur는 자동 닫기 대상이 아니다. Escape와 명시적 닫기 단추는 summary로 초점을 돌려준다.
- 마우스·키보드·터치에서 동일한 문구와 상태를 쓴다. focus-visible은 둘레를 분명히 표시한다.
  coarse pointer 환경의 주 입력·주 행동은 최소 44px를 고려하되 밀집 도구 버튼 전체를 강제로
  44px로 늘리지 않는다. 모바일 배치에서 행동 사이 간격을 확보한다.
- 입력과 보조 버튼의 기능 경계는 `--border-control`을 사용해 인접한 표면과 3:1 이상 구분한다.
  장식 패널의 `--border`·`--border-strong`을 폼 경계에 재사용하지 않는다. 잡아 움직이는 분할선의
  손잡이도 실제 배경과 구분되는 잉크를 쓴다.
- disabled는 실제 native disabled/aria-disabled 의미를 유지한다. 회색을 이유 안내 대신 쓰지 않는다.
- Windows forced-colors에서는 사용자 색과 native select 화살표를 복구하여 조작 표식을 잃지 않는다.

## 색과 요소의 무게

차분한 slate 중립 배경 위에 indigo를 주 행동·선택·초점에 사용한다. 수익·위험 상태의 녹색·주황·
빨강과 행동색을 구분한다. 밝은 테마와 어두운 테마는 동일한 역할 이름을 사용한다. 값의 정본은
`tokens.css`이며 이 문서에 색상표를 복사하지 않는다.

일반 안내는 본문/중립 표면으로, 경고와 오류만 상태색으로 강조한다. 패널 그림자·굵은 테두리·
대문자 kicker를 동시에 반복하여 모든 구역이 같은 강도로 보이게 하지 않는다. 설명이 긴 내용은
짧은 요약 뒤에 native disclosure로 이어 읽을 수 있게 한다.

탐색 아이콘은 하나의 SVG stroke 체계(16~18px, 동일 굵기)를 사용하고 문구와 수직 중앙을 맞춘다.
장식 아이콘은 aria-hidden, 아이콘만 있는 버튼은 접근 가능한 이름을 갖는다. 색과 아이콘만으로
상태를 전달하지 않는다.

## 구현과 QA 근거

디자인 탐색은 ui-ux-pro-max의 `--design-system`을 사용했다. 첫 금융 workspace 검색의
Enterprise Gateway·Contact Sales·OLED 전용 추천은 앱의 스토리와 맞지 않아 채택하지 않았다.
`data analytics dashboard` 재검색의 **Data-Dense Dashboard**, 양 테마 지원, 표·그리드 중심 위계
원칙만 참고했다. landing-page 패턴·폰트·색상표를 자동 적용하지 않고 위 스토리로 이 기준을 작성했다.

확인할 화면은 전략 목록/이력, 빈 문서와 YAML/그래프 편집, 실행 설정 열린 상태, 계약 inspector,
AI 공급자 설정, 백테스트 결과, 실험 상세다. 데스크톱·360px 모바일·다크 테마에서 제목 시작선,
라벨-컨트롤 정렬, select 화살표, disclosure 닫힘/열림과 초점, 긴 표의 내부 스크롤을 확인한다.
기존 repository E2E에서 캡처한 before/after를 사용하고 Mac 캡처를 Windows golden으로 덮어쓰지 않는다.

공통 토큰과 화면 적용을 마쳤고 대표 편집·설정·목록·결과·실험 화면의 전후 캡처를 검토했다.
실제 브라우저에서 설정 패널의 경계와 키보드 동작, 모바일 구조 패널의 일반 배치·초점 유지를
확인했다. 추가 디버거 containment 검사와 Windows 기준선의 최종 근거는
[시각 검증 기록](../../docs/planning/ui-layout-polish/visual-verification.md)을 따른다. 로컬 대표 흐름
통과를 Windows 시각 게이트 완료로 해석하지 않는다.

이번 사용자 요청은 UI/UX 작업에서 멈추는 것이다. 새 백엔드 변경·성과 검산·연구·브로커 연결을
추가하지 않으며 UI 품질 검사와 기존 릴리스 CI는 유지한다.

## 기존 동작 유지 범위

기존 스토리 동작·탐색 경로·native 입력·키보드 접근을 유지한다. 구조·계약·AI의 명시적 열기와
닫기는 현재 작업 문맥과 초점을 보존한다. YAML/그래프를 여는 명령·단축키는 편집 작업공간으로 복귀한다.
작은 화면의 구조 서랍에서 초점이 바깥의 실제 요소로 이동하면 서랍만 닫고 도착 초점을 유지한다.
명시적 닫기·Escape는 여는 버튼으로 돌아가며, 넓은 화면의 일반 배치에서는 초점 이탈로 닫지 않는다.
팔레트의 문서 심볼 명령은 원문 선택·편집 초점을 우선한다. 보조 영역이 떠 있는 좁은 화면에서는
구조·계약·AI를 닫고 원문으로 이동하며, 넓은 화면은 계약도 열어 함께 읽는다. 구조에서 명시해서
필드를 검사하는 행동은 계약을 여는 기존 정책을 유지한다.
브랜드 확장·새 차트·모바일 전용 탐색·맞춤 select 위젯은 이번 범위에 포함하지 않는다.


## 편집기 전수 점검의 경계

[편집기 사용성 검토](../../docs/planning/ui-layout-polish/editor-usability-review.md)는 실제 화면 관측,
소스 검토와 추가 설계 과제를 구분한다. 실제 사용자 시험 결과가 아니다. 새 구성의 네 화면 폭 mock
과업·상태 감사 10개와 여러 PNG의 직접 검토를 기록했지만 모든 표면의 사용성 통과를 뜻하지 않는다.
추가 네 화면 폭 오버레이 감사 4개와 PNG 직접 검토로 설정·문서 정보·출처·경고의 겹침과 원문 줄바꿈,
Tab 이탈 시 외부 초점 유지·닫힘을 확인했다. 레시피 전환의 새 화면은 소스·단위 검토와 구분하며
릴리스 E2E·Windows 아티팩트 확인이 남아 있다.
과거 대표 시각 검증은 새 작업공간 정책의 수용 근거를
대신하지 않는다.
