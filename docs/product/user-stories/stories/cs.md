# 김철수 유저 스토리

원천 데이터를 2차 가공해 자기 알파 팩터를 만드는 퀀트 투자자다([페르소나](../personas.md#김철수-cs)).
파생 팩터를 정의하고 결합하고, 계산이 맞는지 중간값으로 검증하는 것이 이 사람의 여정이다.

### US-CS-01 그래프 편집기에서 노드를 더하고 다시 이어 팩터 계산을 바꾼다

> 김철수로서 팩터 계산 그래프에 노드를 더하고 입력 연결을 바꾸고 싶다. 그래야 YAML을 손으로 들여
> 쓰지 않고 계산 구조를 바꿀 수 있다.

- 상태: `구현됨-e2e`
- 담당 PR: 없음
- e2e 담당: 없음
- 기능 영역: Graph 편집기 · 실행 계획 투영
- e2e:
  - `frontend/e2e/workbench.workflow.spec.ts` :: adds a node in the Graph editor, rewires an input, refreshes the plan and saves

수용 기준

- Given 저장한 전략의 Graph 탭, When 연산자 팔레트에서 "데이터 필드"를 고르면(노드 종류는 연산자를
  따라온다), Then 새 노드가 생겨 선택되고 "반영됨"이 보인다.
- Given 방금 더한 노드, When 툴바의 "실행 취소"를 누르면, Then Graph 탭에 머문 채 YAML이 노드 추가
  전으로 정확히 돌아가고, "다시 실행"으로 되살아난다.
- Given 새 노드, When 기존 노드의 입력을 새 노드로 바꾸면, Then "반영됨"이 보이고 문서가 다시
  "검증 통과"가 된다.
- Given 바꾼 문서, When 저장하면, Then 새 버전이 생기고 그래프 투영에 새 노드 카드가 보인다.
  "Form에서 열기"를 누르면 Form 편집 화면이 열린다.
- 비고: lang2 P1-04(연산자를 먼저 고른다)·P1-02(탭 밖 되돌리기 버튼)가 바꾼 흐름은 반영했다(2026-09-27,
  P1-06). P4-04(Form 탭 은퇴), P6-03(목록형 편집기 제거)이 이 수용 기준을 다시 바꾼다. 그 PR이 이
  스토리를 함께 고친다.
- 비고: 출력이 참/거짓인 팩터(예: 이평 돌파)는 compile이 1/0 점수로 바꾸는 단계를 붙인다(P2-07). 그래프
  투영과 실행 계획은 이 단계를 문서 노드와 구분해 "참/거짓을 1/0으로"라는 이름과 설명으로 보인다.
  브라우저 e2e는 이 표시를 단언하지 않고 frontend `compiled-promotion.test.tsx`가 본다.

### US-CS-02 두 원천 필드를 가공한 파생 팩터를 정의하고 기존 팩터와 결합한다

> 김철수로서 자본총계를 시가총액으로 나누고 횡단면 표준화한 값처럼, 원천 필드를 2차 가공한 내
> 팩터를 정의하고 모멘텀과 가중 결합하고 싶다. 그래야 공개 팩터를 넘어서는 내 알파를 검증할 수 있다.

- 상태: `구현됨-e2e`
- 담당 PR: 없음
- e2e 담당: 없음
- 기능 영역: 팩터 그래프(field·binary·cross_sectional) · 합성 점수 · 실행 계획 · 백테스트
- e2e:
  - `frontend/e2e/stories/cs.derived-factor.spec.ts` :: US-CS-02 두 원천 필드를 나눈 파생 팩터를 모멘텀과 결합해 계획·추적을 확인하고 백테스트한다

수용 기준

- Given 모멘텀 팩터 하나짜리 전략, When 자본총계(`financial.book_equity`) ÷ 시가총액
  (`price.market_cap`)을 횡단면 z-score로 바꾼 팩터를 비중 0.4로 더하면, Then 문서가 "검증 통과"다.
- Given 같은 문서에서 분모 필드 id를 틀리면(`price.market_capx`), Then 저장하기 전에 문서가 "검증
  오류"가 되고 문제 목록이 그 필드를 찾을 수 없다고 말한다.
- Given 저장한 문서, When 중간 결과에서 파생 팩터의 마지막 노드를 골라 종목 셋을 추적하면, Then 종목
  마다 합성 점수의 팩터 기여에 파생 팩터(비중 0.4)와 모멘텀(비중 0.6)이 숫자 기여도와 정상(ok) 상태로
  보인다.
- Given 같은 추적, Then 원시 데이터 탭에 두 원천 필드 값이 종목마다 숫자로 있고, 선택 노드 탭에
  표준화한 파생 팩터 값이 종목마다 숫자이며 상태가 ok다.
- Given 실행 계획 탭, Then 나눗셈 노드가 두 원천 필드 노드를 입력으로 받고 그 뒤에 횡단면 표준화
  단계가 있다.
- Given 같은 문서, When 백테스트를 누르면, Then 실행이 완료되고 결과가 보인다.
- 비고: 없는 필드를 분모로 쓴 문서는 전에는 compile 이 필드 계약 없이 검증해 "검증 통과"로 저장되고,
  중간 결과 추적·백테스트에서야 멈췄다. lang2 P2-07부터 compile 이 연결된 데이터의 필드 계약을 읽어
  저장 전에 `strategy.expression.field_missing`으로 막는다. e2e가 그 돌연변이(분모 `price.market_capx`)를
  먼저 넣어 "검증 오류"를 확인한 뒤 올바른 문서로 이어 간다.
- 비고: 실데이터에서 어댑터가 뺀 필드(카탈로그가 없거나 낡음, 원장 표 없음)는 문제 목록이 "찾을 수
  없다" 대신 원장 사유와 조치(카탈로그 재생성·원장 받기)를 말하고, 원장에 없는 필드는 원장이 싣지
  않는다고 말한다(#316). 문장은 필드 계약 포트의 `unavailable_factor_fields` 가 넘긴 사유를 domain
  `unavailable_field_message` 가 감싼 것이다. mock 은 빼는 필드가 없어 e2e 의 오타 문장은 그대로다.
- 비고: 백테스트·추적 전에 실행 설정 패널에서 기간과 유니버스를 정한다(US-DM-05).
- 비고: 모멘텀처럼 과거 세션 값을 읽는 연산에 원주가 `price.close`를 넣으면 문제 목록에 경고
  (`strategy.field.unadjusted_price`)가 뜨고 수정주가 `price.adj_close`를 쓰라고 말한다. 절대 가격
  수준을 일부러 비교하는 전략도 있어 저장·실행을 막지는 않는다(이슈 #214). 브라우저 e2e는 이 경고를
  단언하지 않고 backend compile 테스트가 본다.

### US-CS-03 중간값 추적과 실행 계획으로 계산과 공개 시점을 검증한다

> 김철수로서 종목별 노드 값, 합성 점수, 선택 여부, 원천 값의 공개일을 보고 싶다. 그래야 계산이
> 맞고 미래 데이터를 쓰지 않았다는 것을 확인할 수 있다.

- 상태: `구현됨-e2e`
- 담당 PR: 없음
- e2e 담당: 없음
- 기능 영역: 중간 결과(디버거 추적) · TargetTape · 실행 계획
- e2e:
  - `frontend/e2e/workbench.workflow.spec.ts` :: creates, recovers, validates, versions, traces and backtests
  - `frontend/e2e/stories/cs.derived-factor.spec.ts` :: US-CS-02 두 원천 필드를 나눈 파생 팩터를 모멘텀과 결합해 계획·추적을 확인하고 백테스트한다
  - `frontend/e2e/stories/cs.masked-trace.spec.ts` :: US-CS-03 원장이 가린 신용잔고 칸을 건넌 노드 값과 그 원시 셀을 원장이 가림으로 본다
  - `frontend/e2e/workbench.workflow.spec.ts` :: 레시피에서 추가·수정·이동·삭제를 되돌리고 좁은 화면과 뒤로가기를 유지한다
  - `frontend/e2e/stories/strategy-tie-breaker.spec.ts` :: 주 점수가 같을 때 선언한 보조 팩터와 방향으로 선정한다

수용 기준

- Given 저장하고 실행 설정(기간·유니버스)을 채운 전략, When 중간 결과에 종목 ID 셋과 노드를 넣고
  "추적 실행"을 누르면, Then 추적 재현 정보(전략 해시·데이터 스냅샷·기준일)가 보이고, 원천 값은 모두
  기준일 이전에 공개된 값이다.
- Given 같은 추적, Then 종목마다 순위·선택 여부·제외 사유·목표 비중이 보인다.
- Given 주 점수가 같은 전략, When 그래프에서 동점 해소 팩터·방향을 고르면, Then 보조 팩터는 alpha 합성에서 빠지고 같은 주 점수 안에서만 순서를 바꾼다. 잔여 결측은 유효값 뒤, 최종 동점은 기존 종목 ID 순서다. 방향을 바꾸면 이전 미리보기를 숨기고 새로고침한 결과를 표시한다.
- Given 같은 추적, Then 노드 값 상태·원시 셀 상태·팩터 기여 상태·제약 결과가 영문 코드가 아니라 한글
  문구("계산됨"·"관측값"·"반영됨"·"제약으로 조정됨" 등)로 보인다(이슈 #350).
- Given 원장이 가린 셀(예: 무상증자 척도 창의 신용잔고)이 값의 시점 구간에 드는 노드, When 그 기준일을
  추적하면, Then 입력이 값으로 보여도 그 노드의 상태가 "입력 없음"이 아니라 "원장이 가림"이고, 원시
  데이터의 가린 셀도 "원장이 가림"으로 보인다(이슈 #350).
- Given 실행 계획 탭, Then 노드마다 연산과 필요한 과거 세션 수(예: "252 세션"), 공개 시점 정책
  `available_date_lte_as_of`, 결측 정책이 보인다.
- Given 추적 결과가 보이는 상태, When 실행 설정의 칸 하나(기간·유니버스·수수료·체결 등)를 바꾸면, Then
  추적 재현 정보와 결과가 사라지고 "범위를 선택한 뒤 추적을 실행하세요."로 돌아간다. 옛 설정으로 계산한 값이
  새 설정의 결과처럼 남지 않는다(이슈 #351).
- Given 시작일을 연구 하한(2020-01-02) 앞으로 둔 실행 설정, When "추적 실행"을 누르면, Then "추적 실패: 시작일이
  연구 구간 밖입니다. 2016-01-01~2019-12-31은 홀드아웃으로 봉인돼 있고 …"처럼 백테스트 시작과 같은 문장이
  보이고 서버 원문은 접힌 "서버 사유"에 있다. "잠시 뒤 다시 추적하세요" 같은 일시 장애 문장은 보이지 않는다
  (이슈 #351).

- Given 그래프와 실행 설정, When 팩터·기준일을 골라 미리보기를 새로고침하면, Then 해당 날짜 유니버스의
  팩터 유효수·결측수·결측 처리·방향 기준 상위 5개가 선정 종목 표와 구분된다. 팩터를 바꾸면 기존 결과는 숨는다.
- 추가 e2e(P5-03, CI 검증 대기): `frontend/e2e/workbench.workflow.spec.ts` :: 레시피에서 추가·수정·이동·삭제를 되돌리고 좁은 화면과 뒤로가기를 유지한다

### US-CS-04 AI에게 팩터 자료 조사와 파라미터 조정안을 맡긴다

> 김철수로서 AI에게 최근 팩터 성과 자료를 찾게 하고, 창 길이 같은 파라미터 조정안을 받아 바로
> 돌려 보고 싶다. 그래야 조사와 실험 사이를 오가는 시간이 준다.

- 상태: `구현됨-e2e`
- 담당 PR: 없음
- e2e 담당: 없음
- 기능 영역: AI 어시스턴트 · 웹 검색 · 제안 적용 · 적용 후 백테스트
- e2e:
  - `frontend/e2e/assistant.workflow.spec.ts` :: 검색 출처를 링크로 보이고 검증에 실패한 턴은 실패 문구로 끝난다
  - `frontend/e2e/assistant.workflow.spec.ts` :: 팩터 그래프를 바꾸는 제안도 적용 후 백테스트가 팩터 계획 조회를 기다려 실행한다
  - `frontend/e2e/assistant.workflow.spec.ts` :: 검색 상한에 닿은 턴은 검색 칩 대신 안내 문구를 보이고 새로고침해도 같다

수용 기준

- Given 사이드바, When 자료를 검색해 달라고 하면, Then "웹 검색" 활동과 검색어, 출처 링크가 보이고
  링크마다 도착지 호스트가 보인다. 링크는 새 탭으로 열린다.
- Given 한 답변이 웹 검색 횟수 상한에 닿은 턴, Then 실제로 한 검색만 "웹 검색" 활동으로 보이고, 그
  아래에 "이 답변에서 쓸 수 있는 웹 검색 횟수를 모두 썼습니다. 지금까지 찾은 자료로 답합니다."가
  안내로 보인다. 새로고침해도 같다.
- Given 모델이 낸 전략이 서버 검증을 통과하지 못한 턴, Then 제안 카드는 뜨지 않고 "모델이 낸 전략이
  검증을 통과하지 못했습니다."로 끝나며 문서와 실행 버튼은 그대로다.
- Given 팩터 창을 줄인 제안 카드, When "적용 후 백테스트"를 누르면, Then 바뀐 창으로 팩터 계획을
  새로 조회한 뒤 실행이 시작되어 완료된다.

### US-CS-05 단위가 다른 팩터를 결합 전에 정규화한다

> 김철수로서 원 단위 금액 팩터와 비율 팩터를 섞을 때 결합 전에 순위나 z-score로 맞추고 싶다.
> 그래야 큰 단위 팩터가 합성 점수를 지배하지 않는다.

- 상태: `구현됨-e2e없음`
- 담당 PR: P5-03
- e2e 담당: P5-03
- 기능 영역: `signal.normalization` · 합성 점수
- e2e: 없음

수용 기준

- Given 팩터 둘짜리 전략, When 점수 정규화를 "순위로 맞춘 뒤 가중 합"(`rank`)이나 "표준점수로 맞춘 뒤
  가중 합"(`zscore`)으로 고르면, Then 추적 화면의 합성 점수가 정규화된 기여도의 가중합으로 보인다.
- Given 새 전략, Then 점수 정규화 기본값은 "순위로 맞춘 뒤 가중 합"이다. 1.1에서 올라온 문서는 "원시값
  그대로 가중 합"(`none`)으로 예전 결과를 그대로 낸다.
- Given 정규화를 "원시값 그대로 가중 합"으로 두고 단위가 다른 팩터를 섞은 문서, Then 단위가 다르다는
  경고가 뜬다(P2-07).
- 비고: backend 에는 `signal.normalization`(`none`·`rank`·`zscore`, 새 문서 기본값 `rank`)과 가중 합
  전의 횡단면 정규화가 있다(P2-04). 단위 경고도 backend 에 있다(P2-07): `none` 이고 합성에 들어가는
  팩터의 출력 단위가 둘 이상이면 문제 목록에 warning `strategy.signal.unit_mismatch` 가 뜬다. 그래프
  안에서 횡단면 순위·z-score 로 바꾼 팩터는 무차원이라 경고하지 않는다. 업그레이더는 1.1 문서에
  `none` 을 명시한다(P2-09). 화면(P3-01): Form 의 신호 결합 절이 문서에 적지 않아도 "점수 정규화"를
  기본값 "순위로 맞춘 뒤 가중 합"으로 보이고, 세 선택지를 원문 값이 아니라 이름("원시값 그대로 가중
  합(단위가 같을 때만)"·"표준점수로 맞춘 뒤 가중 합")으로 고르며 고른 값의 뜻을 한 줄로 보인다. 추적
  화면은 팩터별 기여도와 그 합인 합성 점수를 보인다. 수용 기준의 동작이 모두 main에 있지만 이를
  확인하는 스토리 태그 e2e가 없어 `구현됨-e2e없음`이다. 스토리 문장과 수용 기준은 편집 탭을 정하지
  않으므로 그래프 탭 조건은 판정에 넣지 않는다. 그래프 탭만으로 전략을 만드는 흐름은 US-DM-07이
  지킨다. e2e는 P5-03(아이디어 e2e)이 맡는다.

### US-CS-06 거래대금 상위 20% 같은 횡단면 필터와 변동성 역가중을 쓴다

> 김철수로서 "거래대금 상위 20%만" 같은 상대 조건으로 유니버스를 거르고, 변동성 팩터로 비중을
> 나누고 싶다. 그래야 유동성과 위험을 전략 안에서 다룰 수 있다.

- 상태: `구현됨-e2e없음`
- 담당 PR: P5-03
- e2e 담당: P5-03
- 기능 영역: 횡단면 eligibility · `risk.risk_factor_id` · 탈락 사유
- e2e: 없음

수용 기준

- Given 후보 100종목, When 거르기 규칙의 비교 방식을 "값이 큰 쪽 상위 비율 안에 드는"(`top_percent`)으로,
  기준값을 0.2로 두면, Then 추적 화면에서 20종목만 통과하고 나머지는 "상위 비율·개수 밖(순위로 잘림)"
  탈락 사유를 보인다.
- Given 알파 팩터와 변동성 팩터가 있는 전략, When 비중 산정을 "위험이 작을수록 크게"(`risk`)로 두고
  위험 팩터로 변동성 팩터를 고르면, Then 변동성 팩터는 합성 점수에서 빠지고 비중에만 쓰인다.
- Given 변동성 팩터를 빼면 알파 팩터가 하나도 남지 않는 문서, Then compile 오류가 난다.
- 비고: backend 에는 횡단면 eligibility(`top_percent`·`top_count`, 규칙마다 따로 센 모집단의 순위로
  자르는 2-pass)와 순위 탈락 사유 `eligibility_rank_cut` 이 있다(P2-05). 변동성 역가중도
  backend 에 있다(P2-06): `weighting: risk` 에서 `risk.risk_factor_id` 가 가리키는 팩터는 합성
  점수와 분모에서 빠지고(warning `strategy.risk.risk_factor_excluded`), 정규화 전 원시값의 역수로
  비중을 나눈다. 빼고 나서 알파가 없으면 compile error `strategy.signal.no_alpha_factor` 다.
  화면(P3-01): Form 의 거르기 규칙이 비교 방식을 이름("값이 큰 쪽 상위 비율 안에 드는" 등)으로 고르고
  기준값 설명이 비율·개수의 뜻을 말한다. 리스크 절의 "위험 팩터"는 문서의 팩터 id 중에서 고르며 편집기
  완성도 같은 후보를 "문서의 팩터"로 준다. 추적 화면은 순위로 잘린 종목의 사유를 "상위 비율·개수
  밖(순위로 잘림)"으로 보여 "거르기 조건 불통과"와 구분한다. 두 기능을 쓰는 완료 정의 문서는
  `ideas/top_trading_value.yaml`·`ideas/inverse_volatility.yaml` 이고 backend 에서 compile·미리보기까지
  통과한다(P2-08). 수용 기준의 동작이 모두 main에 있지만 이를 확인하는 스토리 태그 e2e가 없어
  `구현됨-e2e없음`이다. US-CS-05처럼 그래프 탭 조건은 판정에 넣지 않는다. e2e는 P5-03(아이디어 e2e)이
  맡는다.
