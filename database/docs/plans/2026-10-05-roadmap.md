## 3. 구조
| | 연구 DB (quant-ledger) | 모델 DB (신설) |
|---|---|---|
| 용도 | 백테스트·리서치 | 매일 점수·엑셀 |
| 범위 | 전 종목·전 이력·PIT | 모델이 쓰는 표만 |
| 언제 | 하루 1회(아침, 데일리를 막지 않음) | **저녁 1회 확정** · 다음 날 아침 KRX 로 검증만 |
| 수집 | 원장 하나를 공유 | ← 같음 |
| 규칙 | stage·equity 규칙 | **같은 규칙**(두 벌 금지), 느린 표는 연구 DB 판을 날짜로 고정해 참조 |
| 엑셀 | — | 저녁 확정 1회. 다음 날 KRX 와 다르면 정정판 + 원인, 같으면 무발송 |

**저녁 확정의 전제**: 저녁에 받는 키움 종가는 장후 체결가라 KRX 정규장 종가와 다르다(10-01 삼성전자 274,500 vs 276,000). 정규장 종가·기준가·거래대금을 저녁에 주는 원천(후보 KIS "주식현재가 일자별" `inquire_daily_price`, 키움 TR — 미확인)을 **프로브로 먼저 확인**한다. 확인 전까지는 지금처럼 다음 날 아침 확정.

## 4. 휴장 캘린더
**지금(10-05 확인)**
- quant-ledger 는 **원본 v3 의 KIS 휴장 캐시를 복사**해 쓴다(`scripts/sync_calendar.sh`, 06:00·18:05 체인 시작 때). 판정은 `src/daily/calendar.py`(주말 + 휴장 목록), 연도별 파일(`data/calendar/kis_holidays_<year>.json`).
- 2026 파일에 10-03·10-05·10-09·12-25·12-31 등 121건. 오늘(10-05 대체공휴일) 06:00·08:10 체인은 D=10-02(이미 완료)로 올바르게 건너뜀.
- 이미 있는 게이트: KRX 가 "휴장" 응답을 준 날이 달력상 거래일이면 즉시 중단(`ledger_health` `krx.holiday_misfire`, DEFECT-A-01 — KRX 빈 응답을 휴장 근거로 쓰지 않음).
- 갱신 원천은 v3 다: KIS `chk-holiday`(국내휴장일조회)를 연 단위로 페이지 수집해 검증(≥100건·전건 해당 연도·주말 포함)하는 v3 코드(`backend/clients/kis/holiday.py`)와 v3 크론(매월 1일 점검·12-30 이듬해 갱신·매일 체인의 calendar_refresh).

**위험**
1. v3 를 끄면 달력 갱신도 멈춘다(지금은 v3 에 의존).
2. 임시공휴일이 월중에 지정되면 다음 갱신(월 1회)까지 모른다 → 휴장일에 체인이 돌거나, 거래일을 건너뛸 수 있다.
3. 연도 경계: 이듬해 파일이 없으면 판정 불가(12-30 v3 갱신에 의존).
4. 달력이 둘이다: 앞날 판정용(KIS 캐시)과 연구 DB 의 `trading_calendar`(KRX 지수 날짜, 지난날). 서로 맞는지 보는 게이트가 한 방향(위 HALT)뿐이다.

**할 일(연구 DB 완성 H0-3 에 넣는다)**
- quant-ledger 가 **직접** KIS `chk-holiday` 로 갱신(v3 코드와 같은 방식·검증, 연 약 16콜): 매일 06:00 체인 시작 때 이번 달·다음 달 재확인, 12월 1일부터 이듬해 파일 선수집. v3 사본 동기화는 병행하다가 일치 30일 뒤 끈다.
- 게이트 추가: ① 반대 방향 — 달력상 휴장일에 KRX 시세가 들어오면 HALT ② 지난 거래일 집합 = `trading_calendar`(KRX 지수 날짜), 불일치 0 ③ 이듬해 파일이 12-15 까지 없으면 crit ④ 휴장 목록이 줄어들면(지정 취소 외) 경고.
- 모든 판정은 이 달력 하나로: 체인 실행 여부, `prev_trading_day`(모델 DB 가 가져올 판 날짜), 주간 엑셀의 "그 주 마지막 거래일", 모델 창 길이. 다른 곳에서 날짜를 따로 세지 않는다.

## 8. 검증 게이트 (핵심)
> 세부 정의(측정 방법·음성 대조·코드 위치)는 [`2026-10-05-gate-register.md`](2026-10-05-gate-register.md)(102개, 채택 보류)에 있고, 여기 31개만 채택한다. 전부 **미구현**이다. 이미 코드에 있는 것은 기존 게이트 묶음(ledger_health·stage C1~C6·equity EG·fi FG·모델 MG0~MG5)·`krx.holiday_misfire`·EG17 뿐이다.
> 대장 초안에 남은 문제 4건은 여기서 이렇게 정리했다.
> - 두 DB 대조 상대: 연구 DB 저녁 빌드가 아니라 다음 날 아침 연구 판(K2-7)이다. 그래서 저녁 빌드를 멈춰도 대조는 남는다.
> - KRX 값 재생(K2-5): 평소에는 불일치가 있을 때만 돌고(같으면 입력이 같으므로 생략), 매일 도는 것은 그림자 10일 동안뿐이다. 그래서 하루 예산(§5)을 넘지 않는다.
> - 단계 0 출구는 로드맵 기준(엑셀 매일 도착·프로브 판정) 그대로다.
> - 컷오버 비교 임계는 그림자 데이터로 정해 승인받는다(공통 4).

**공통 규칙**
1. 게이트가 실패하면 다음 단계로 가지 않는다. 고친 뒤 같은 게이트로 다시 잰다. 기준을 완화하려면 사유와 사용자 승인이 필요하다.
2. 판정자는 구현자와 다르다. 새 게이트는 결함을 일부러 넣었을 때 실패하는지(음성 대조)를 먼저 확인해야 인정한다.
3. 못 쟀거나·건너뛰었거나·입력이 없으면 통과가 아니라 실패다. "N거래일 연속" 창은 실패 1건이면 처음부터 다시 센다(거래일은 §4 달력으로 센다).
4. 근거 없는 수치 기준은 2주 동안 기록만 한다. 사용자 승인으로 등록한 뒤부터 판정한다.
5. 배포 뒤 실패하면 함께 되돌린다: 코드(직전 배포 rev)·기준 상수 파일(stage·equity baseline)·크론·판 포인터. 잘못 나간 엑셀은 정정판으로 바로잡는다.
6. 실패 알림은 `logs/notify.log` 에만 남긴다(텔레그램 금지). 매일 아침 점검해서 보고한다.
