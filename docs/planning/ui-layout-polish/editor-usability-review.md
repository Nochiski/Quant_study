# 편집기 전체 사용성 검토

2026-10-17 사용자가 중간 결과의 작은 작업 공간을 지적한 후 수행한 과업 중심 점검이다.
실제 사용자 시험이 아니다. 기존 스토리의 원문·계산·API·저장·실행 의미를 보존하며 화면 구성만 바꾼다.
디자인 정본은 [MASTER](../../../design-system/strategy-workbench/MASTER.md)이고 아래 표는 관측과 경계다.

감사 근거는 외부 `validation-evidence/editor-usability-20261017`의 PNG·치수·report.md다.
1440×900·1280×800·360×800에서 편집→오류 수정→범위 입력→모멘텀 노드 추적→연결값·원천셀·노드값→편집 복귀를 실행했다.
초기 실행 설정의 닫힌 사진은 열린 상태의 근거로 쓰지 않고 `10-run-environment-open` 보완 사진을 사용한다.
수동 최소 높이 사진은 복원된 저장 상태 검증이 아니다.

새 구성은 격리된 PIT mock 환경에서 1440×900·1280×800·960×720·360×800의 과업·상태 감사
10개가 통과했다. 루트가 원문·AI 작성칸/제안·계약·노드 속성·실행 설정·추적·복구/충돌/업그레이드의
여러 PNG를 직접 검토했다. 이는 실제 사용자 시험이나 실자료 검증이 아니다. 전체 단위·릴리스 CI의
최종 수치는 확정된 검증 기록에서 별도로 확인하며, 기존 매뉴얼 사진 전체를 새 배치로 재생성하지 않았다.

추가 오버레이 감사는 같은 네 화면 폭에서 4개가 통과했다(14.3초). 루트가 설정·문서 정보·출처·경고
PNG를 직접 확인했으며, 좁은 출처 원문의 줄바꿈·형제 영역 겹침과 Tab 이탈 시 외부 초점 유지·닫힘을
보완했다. 이 기록은 전체 단위 검사나 Windows 릴리스 E2E 완료를 뜻하지 않는다.

최종 로컬 검증은 frontend 단위 109개 파일·1,394개 통과·실패 0개이며
`frontend-unit.log`에 기록했다. frontend typecheck·E2E typecheck·lint와 backend/루트 ruff·pyright도
오류 없이 통과했고, 스토리 하네스는 40개 스토리·51개 태그 E2E를 확인했다.
이 수치는 로컬 검증 기록이다. 공식 Windows CI·머지 상태는 해당 PR의 checks·merge 기록에서
확인하며, 로컬 통과를 CI 완료나 머지 완료로 해석하지 않는다.

S6의 실행→나가기 경고는 실행 접수 여부와 목적지의 문구를 맞추며 실행 자체를 재설계하지 않는다.
서버 데이터·연구 수익 검증·브로커 연결은 범위 밖이다. 이전 작은 패널의 휠 동작은 정상인 경우가
있었지만 발견성과 실제 작업 공간이 부족했다. 단순 접근 가능성을 작업 가능성 통과로 해석하지 않는다.
