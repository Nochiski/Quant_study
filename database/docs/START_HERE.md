`wisereport.db` 안에:

| 묶음 | 표 | 채우는 것 | 상태 |
|---|---|---|---|
| **WISE 직접 수집** | `ws_raw`(엔드포인트 6종) | `daily_wise.sh` 06:00 KST | **매일 쌓인다** — 09-01~09-08 연속, 커버 804/2,564 |

**추정치는 4월부터 오늘 아침 크론까지 끊김 없이 있다.** 4~8월은 v3 미러(다른 크롤러, 다시 긁을 수
없음), 9/1 부터는 WISE 직접 수집. 4일 겹친다. 「시계열 연결」은 과장이었다 — DB 는 끊긴 적이 없다.

**영업이익·순이익도 매일 들어온다.** `stg_consensus_monthly`(cF5001/cF5002)에는 eps·revenue 뿐이지만
`stg_consensus_annual`(c1050001_data, `period_kind='E'`)에 op·ni 가 각 3,4xx 행 채워져 있고 매일
자란다. **equity 가 그 표를 아직 안 읽을 뿐이다** — G05·G06 의 재료가 동결된 것이 아니라 연결이

## 7. 작업 규칙 (짧게)

- **슬라이스 = 테이블 1~3개 + 브랜치 하나 + 검토 요청 하나.** 게이트 술어 ID 가 없으면 착수 금지.
- **재현 테스트 먼저.** 절단본(`database/tests/fixtures/stage_slice`)에 사례가 없으면
  합성 러너를 쓴다(`test_equity_s05_event.py::run_event_sql` · `s06_adj.py::run_adj_sql` 참고).
- **판본을 올리지 않고 산출을 바꾸면 EG5a 가 FAIL 하고 새 판이 폐기된다.** 올린 뒤 **두 번** 지어야
  재현성이 확인된다.
- **게이트가 실패하면 새 판을 버리고 기존 판이 남는다** — 서버 재빌드가 위험하지 않은 이유다.
- 상수는 코드가 아니라 `baseline.json`. 첫 빌드는 측정만 하고 사람 승인 뒤 2회차부터 적용.
- **판단이 필요하면 팩트를 더 실어라.** 라벨을 붙이고 근거를 basis 컬럼에 적고 임계는 소비자에게
  넘긴다. 이름에 해석을 얹지 않는다.
