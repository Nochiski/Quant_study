# v3 컷오버 트랙 — 통합 계획(정본)

> 결정은 [`DECISIONS.md`](../DECISIONS.md) N-42(사용자 답 6건)와 이 문서 §2 T-1~T-24(원칙으로 정한 것)에 있다. 화면용 요약은 claude.ai 아티팩트 'v3 컷오버 트랙'이다. 세션이 끊기거나 컴팩션이 와도 이 문서가 기준이다.

## 0. 목표와 일정
- **목표**: 원본 v3 의 키움·KIS·네이버 WiseReport 수집(무거운 크롤링)을 끄고, 장 마감 직후(15:41~) quant-ledger 혼자 모델 점수·엑셀을 내며, v3 소비자(브리핑·위키·uni·가설)는 quant-ledger 가 채운 v3 quant.db 를 읽는다. 연구 DB 는 아침 확정판을 유지한다.
- **범위 밖(사용자 10-10)**: v3 의 네이버 리서치 리포트(20:30)·뉴스 이벤트용 IR·뉴스·이벤트 크론은 그대로 둔다. v3 폴더 전체 이관은 나중 일이다.
- **일정(목표)**: 10-10~12 구현·재생 검증 → 10-13 main 병합 + 휴장 달력 배포 → 10-14 트랙 배포(장 마감 판 미발송 그림자) → 10-14~16 그림자 3거래일 → 10-16 저녁 사용자 실물 확인 → 10-19 원천 전환·컷오버 → 10-19~23 되돌리기 창 5거래일.
- **베이스 브랜치**: `track/cutover`(← `wip/merge-cal` = main 병합 + 휴장 달력). PR 은 베이스에서 딴 브랜치 `pr/<ID>` 로 만들고, 리뷰 통과 뒤 컨트롤러가 베이스에 `--no-ff` 머지한다. main 머지는 사용자가 정한다.

## 1. 작업 규칙(서브에이전트 공통)
1. **PR 하나 = 결정 하나.** 이 문서 §3 의 PR ID 하나만 한다. 범위 밖 리팩터·청소 금지(필요하면 보고에 '후속'으로).
2. **TDD**: 옛 코드에서 실패하는 재현·명세 테스트 → 구현 → 통과. 테스트는 real > fake > mock — 네트워크는 가짜, 데이터는 실제 모양의 소형 픽스처.
3. **테스트 실행**: 바꾼 영역의 테스트 파일만 돌린다(`<venv python> -m pytest database/tests/<file> -q`). 전체 스위트는 컨트롤러가 머지 묶음마다 돌린다. venv 는 공유라 설치·변경 금지.
4. **커밋**: 자기 워크트리의 `pr/<ID>` 브랜치에만 로컬 커밋(영문 메시지, 끝줄 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`). push·서버 접속·`.env`·토큰 파일 열기 금지. 서버가 필요한 검증은 '컨트롤러가 돌릴 명령'으로 보고한다.
5. **판본**: 규칙 파일(stage·equity SQL/rules, fi queries, model engines)을 바꾸면 그 층 RULES_VERSION 을 올리고 이력 주석에 한 줄(K1-13). 같은 층을 여러 PR 이 올리면 머지 때 컨트롤러가 번호를 정리한다.
6. **SoT·책임**: 같은 규칙은 한 곳에만(P4). 새로 쓰기 전에 같은 일을 하는 곳을 찾는다. 날짜 계산은 `daily.calendar`(달력 모듈) 하나로.
7. **원칙**: 모호하면 결측(P1) · 정지 조건은 이 문서·N-42 에 적힌 것만(P3) · 체인은 완료 감지로 잇고 고정 시각은 외부 공개 시각만(P9) · 텔레그램 로그 알림 금지(`scripts/notify.sh` 는 기록만, 모델 엑셀 배달은 별개).
8. **보안**: 저장소는 공개다. 서버 홈 경로·IP·계정명·토큰을 코드·문서·테스트에 쓰지 않는다(`~`·`$HOME` 표기).
9. **언어**: 새 주석·문서는 한글. 결함은 상황/인풋/위치/위험성 4요소.
10. **보고**: 바꾼 파일, 테스트 이름·결과, 판본 변경, 컨트롤러가 서버에서 돌릴 재생 명령, 후속·애매한 점(선택지 + 권고).

## 4. 검증 방식(N-42 Q1)
- 'N거래일 연속' 게이트는 **과거 재생 + 실운영 3거래일**로 바꾼다. 3일 창은 실패 1건이면 처음부터 다시 센다(공통 3).
