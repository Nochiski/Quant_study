# 편집기 전체 사용성 검토

2026-10-17 사용자가 중간 결과의 작은 작업 공간을 지적한 후 수행한 과업 중심 점검이다.
실제 사용자 시험이 아니다. 기존 스토리의 원문·계산·API·저장·실행 의미를 보존하며 화면 구성만 바꾼다.
디자인 정본은 [MASTER](../../../design-system/strategy-workbench/MASTER.md)이고 아래 표는 관측과 경계다.

감사 근거는 외부 `validation-evidence/editor-usability-20261017`의 PNG·치수·report.md다.
1440×900·1280×800·360×800에서 편집→오류 수정→범위 입력→모멘텀 노드 추적→연결값·원천셀·노드값→편집 복귀를 실행했다.
초기 실행 설정의 닫힌 사진은 열린 상태의 근거로 쓰지 않고 `10-run-environment-open` 보완 사진을 사용한다.
수동 최소 높이 사진은 복원된 저장 상태 검증이 아니다.

새 구성은 격리된 PIT mock 환경에서 1440×900·1280×800·960×720·360×800의 과업·상태 감사
10개가 통과했다. 루트가 원문·AI 작성칸/제안·계약·노드 속성·실행 설정·추적·복구/충돌/업그레이드의
여러 PNG를 직접 검토했다. 이는 실제 사용자 시험이나 실자료 검증이 아니며,
기존 매뉴얼 사진 전체를 새 배치로 재생성하지 않았다.

추가 오버레이 네 폭과 명령 팔레트 두 폭의 실제 감사 6개가 통과했다. 루트가 설정·문서 정보·출처·경고
PNG를 직접 확인했으며, 좁은 출처 원문의 줄바꿈·형제 영역 겹침과 Tab 이탈 시 외부 초점 유지·닫힘을
보완했다. 출처·경고의 외부 초점 자동 닫힘은 모바일 오버레이에만 적용한다. 데스크톱 일반 배치는
결과 탭을 누르는 중 위치가 이동하지 않도록 열린 상태를 유지한다.
이 기록은 전체 단위 검사나 Windows 릴리스 E2E 완료를 뜻하지 않는다.

최종 제품 소스를 포함한 전체 로컬 frontend 단위 검사는 109개 파일·1,407개 통과·실패 0개다
(`frontend-unit-final.log`, 81.93초). frontend typecheck·E2E typecheck·lint와 backend/루트
ruff·pyright도 오류 없이 통과했고, 스토리 하네스는 40개 스토리·51개 태그 E2E를 확인했다.
이는 로컬 검사이며 공식 Windows CI·머지 상태는 해당 PR의 checks·merge 기록에서 확인한다.
부분 회귀와 재실행 횟수를 전체 검사 수에 더하지 않는다.

후속 실제 결함은 별도로 기록한다. 1440px에서 AI의 미전송 문장과 수동 대화 선택이 추적 전환 후
소실되는 것을 실제 PNG·상태 JSON으로 확인했다. 같은 AI 인스턴스를 한 DOM 위치에 유지하고
CSS 배치만 바꾸도록 보완했으며, 대화·스트림·질의 상태를 다른 계층으로 옮기지 않았다. 모바일 구조
서랍에서도 양방향 Tab 이탈 뒤 배경 초점을 덮는 경로를 확인해, 외부 초점은 유지하면서 서랍만 닫는다.
보완 후 1440px·960px의 실제 작업공간 전환에서 미전송 문장·수동 대화 선택 보존을 재확인했다.

남은 표면 감사에서는 1440px·360px의 장문 진단 2개와 긴 실제 버전 비교 2개가 통과했다.
실제 휠·Tab 조작과 스크롤 치수를 기록하고, 버전 비교의 두 저장 원문은 기존 조회 API 응답과
정확히 대조했다. 루트가 PNG를 직접 확인해 진단 메시지의 전체 행 읽기와 비교 원문의 가로 읽기를
검토했다. 비교는 기존 비교 패널 범위이며 별도 비교 제품을 추가하지 않았다.

같은 두 폭의 자동완성은 실제 후보 팝업 치수·가림 여부, Escape 뒤 원문 보존, 재열기 후 Enter 선택과
정확한 최종 원문·검증 통과를 확인했다. `completion-key-stages.json`에는 목록 DOM·선택 후보·초점·키
단계가 남아 있다. 최종 Enter keydown은 재열린 목록 DOM 등장 후 각각 179.1ms·171.0ms였고,
직전까지 후보의 `aria-selected=true`와 원문을 유지했다. 초기 QA는 실패 당시 키 단계 기록이 없어
75ms 보호 시간만으로 원인을 단정하지 않는다. 최종 QA는 Control 단독 키 유지로 후보를 바꾸지 않고
입력을 안정화했으며, 제품의 Enter 선택 결함으로 기록하지 않는다.

`remaining-final.log`의 20개 중 최초 16개 통과·4개 실패 뒤, 같은 실패 4개를
`final-interaction`에서 재검증해 모두 통과했다(14.1초). 자동완성 두 폭, 실행 조건의 3개 보기 연속
전환, 날짜 입력 과업의 잔여 실패는 0개다. 위 표면별 통과는 이 감사와 겹치므로 합산하지 않는다.
증거는 외부 `after/remaining`, `after/overlays`의 PNG·치수·키 기록과 해당 실행 로그다.

서버 데이터·연구 수익 검증·브로커 연결은 범위 밖이다. 이전 작은 패널의 휠 동작은 정상인 경우가
있었지만 발견성과 실제 작업 공간이 부족했다. 단순 접근 가능성을 작업 가능성 통과로 해석하지 않는다.
