# KIS 관심종목 등록 상위 · HTS 조회 상위 스냅숏 수집기 (N-66)

대안데이터 묶음 1. 원장(2010~)에 없는 새 정보 계열(개인 관심 · 조회 집중)을 오늘부터 쌓는다. 두 TR 모두 응답에 날짜 칸이
없어 과거 값은 받을 수 없다 — 하루 늦을 때마다 그날 값은 영구 손실이다. 판정(새 정보인가 · 수익과 관계가 있는가)은
이 저장소 밖 연구 세션이 전진 관찰로 한다(첫 겹침 판정은 60거래일 뒤). 이 계획의 범위는 raw 수집까지다.

## 2. 무엇을 · 언제

| 항목 | 값 |
|---|---|
| 관심종목등록 상위 `FHPST01800000` | J(KRX)만 · 범위 0001 코스피 · 1001 코스닥 · 0000 전체 · 각 1위부터 30행(31위부터는 `OPSQ2001`) |
| HTS 조회 상위 `HHMCM000100C0` | 20행 · 다음 쪽 없음 |
| 슬롯 | 거래일 08:30 ~ 20:30 KST 30분 격자 25개 — 두 TR 같이(하루 100콜). 관심 건수는 장중에 안 바뀌고 한꺼번에 갱신되는데 갱신 시각을 몰라 같은 격자로 받는다(사용자 11-09) |
| 휴장일 | 돌지 않는다. 세션 예외일(수능일 등)은 슬롯 그대로 — 구간 이름은 읽을 때 `slot_kst` + 세션 예외표로 붙인다 |

## 3. 표 — `data/raw/kis_rank.db`

`kis.db` 가 아닌 이유: 그 파일은 06:00 체인이 원장 락을 쥐고 쓴다. 같은 파일에 쓰려면 원장 락을 기다려야 하고, 기다리면
슬롯 시각이 밀려 그날 값을 잃는다(장 마감 수집기와 같은 이유). 원장 raw 관례대로 응답 칸 이름을 그대로 두고 전부 TEXT 로
저장한다(형 변환 · 이름 바꾸기는 stage 몫). TR 하나에 표 하나.

| 표 | PK | 칸 |
|---|---|---|
| `kis_rank_runs` | (slot_kst, endpoint, scope) | started_utc · received_utc · n_calls · verdict(ok · shape · token · quota · fail) · msg_cd · n_rows · rows_json(ok 가 아니면 받은 행 원문) |
| `kis_top_interest` | (slot_kst, scope, pos) | 응답 칸 13개 그대로 + received_utc |
| `kis_hts_top_view` | (slot_kst, pos) | 응답 칸 2개 그대로 + received_utc |

- PIT: 쓸 수 있는 시각 = `received_utc`(받은 시각 — 값이 만들어진 시각이 아니다). stage 편입은 겹침 판정 뒤 별도 결정.
- 응답을 받은 (슬롯, TR, 범위)는 칸 이상이어도 다시 부르지 않는다 — 첫 관측을 늦은 값으로 바꾸거나 두 응답을 섞지 않는다.
  다시 부르는 것은 응답을 못 받은 칸(토큰 · 유량 · 호출 실패)뿐이다.
- 빠진 슬롯은 행으로 쓰지 않는다. 격자(코드 상수 `SLOTS`)와 runs 를 `summarize` 한 곳이 대조해 센다.
- 가격 · 거래량 칸은 참고용 — 정본은 KRX 다.

## 4. 경보

| 경우 | verdict | 래퍼 rc | notify |
|---|---|---|---|
| 정상(관심 30행 · HTS 20행 · 칸 집합 같음) | ok | 0 | 없음 |
| 행 수 다름 · 칸 빠짐 · 모르는 칸 | shape(받은 행 저장 · 원문 보관) | 2 | crit |
| 토큰 1회 재발급 뒤에도 만료(나머지 TR 은 부르지 않음) · 유량 · 호출 실패 | token · quota · fail | 5 | warn |
| 파이썬 예상 밖 예외 | — | 1 등 | crit |
| 격자 밖 · 휴장 · 앞 실행이 락을 쥠 | — | 3 | 없음 |

warn 을 1 이 아니라 5 로 둔 것은 파이썬이 예상 밖 예외로 죽을 때 1 을 내기 때문이다(예외가 warn 으로 묻히지 않게).
하루 요약(`watchdog.sh kis_rank`, 20:45 KST): TR 마다 ok 슬롯을 센다(관심은 범위 3개가 모두 ok 여야 그 슬롯이 ok).
25 중 23 미만 warn, 어느 TR 이든 0 이거나 원장 파일이 없으면 crit.

```cron

0,30 0-11 * * 1-5 cd ~/quant-ledger && /bin/bash scripts/kis_rank.sh >> logs/cron_kis_rank.log 2>&1
```

수집기는 격자 밖 시각에 불리면 rc 3 으로 아무것도 안 한다 — 크론 줄과 격자가 어긋나면 워치독이 빠진 슬롯으로 잡는다.

## 6. 테스트

KIS 고객 이용약관 제5조 ③(시세를 제3자에게 제공하지 않는다) 때문에 실제 응답을 저장소 fixture 로 쓰지 않는다. 칸 이름 ·
행 수만 같은 합성 응답(가짜 종목코드 · 값)을 테스트 안에서 만든다. 대역은 실물 sqlite · 실물 달력 객체 · `api.kis` 만 가짜.

| 파일 | 보장하는 행동 |
|---|---|
| `test_daily_kis_rank.py` | KST 격자 슬롯 판정(경계 · 전날 23:30 UTC → 다음 날 08:30 · 휴장) · 정상 저장과 received_utc · 받은 슬롯은 다시 안 부름 · 실패 칸만 다시 부름 · 칸 빠짐 · 29행 · 모르는 칸 → shape 이고 행 보존 · shape 슬롯 재실행이 응답을 섞지 않음 · 토큰 1회 재발급 / 끝내 만료면 멈춤 · 하루 요약 임계(23/25 · 범위 하나 실패 · 0 · 파일 없음) |

## 7. 배포 · 서버 확인

1. 낮 창(10:30~15:10)에 배포한다. 배포 전 체인 · 잠금이 비었는지 보고, 되돌릴 rev 를 적는다. 배포 뒤 해시를 대조한다.
2. 임시 폴더 실호출: `python -m daily.kis_rank --db "$(mktemp -d)/kis_rank.db"`(지금 슬롯 한 번 — 4콜). 행 수 · 칸을 본다.
   `api.kis` 는 `tr_cont` 머리를 보내지 않는다 — HTS 조회 상위가 20행을 주는지 여기서 확인한다.
3. 운영 DB 로 한 슬롯 손으로 → crontab 3줄 등록(전후 사본 · md5 · 줄 수) → 다음 슬롯이 크론으로 도는지 본다.
   토요일 백업이 원본 없음으로 crit 을 내지 않게 첫 슬롯이 `kis_rank.db` 를 만든 뒤에 끝낸다.
4. 되돌리기: crontab 3줄 주석 + 직전 rev. 쌓인 `kis_rank.db` 는 지우지 않는다(서버 데이터 삭제는 사용자 승인).
5. 다음 거래일: 슬롯 25 · 행 수(관심 3 × 30 · HTS 20 / 슬롯) · PK NULL 0.

## 8. 공개 저장소에 넣지 않는 것

키도 넣지 않는다.
