## 0. 한눈에

```
수집 원장 (KRX · 키움 · WISE · DART · KIS) — 한 번만 수집, 두 DB 가 공유
   │
   ├─▶ quant-ledger DB (연구·백테스트) : stage 68 → equity 30 전량, 아침 확정판 m_ (짝 플랜)
   │            │ 느린 표만 가져오기 (D 로 고른 판 id 를 고정·참조)
   │            ▼
   └─▶ 모델 DB : 모델 폐포의 빠른 표를 **같은 규칙으로 전량 재계산**(증분 아님) + 느린 표 가져오기
                 → 모델 입력 8표 (같은 계약 · 같은 queries.py, 저녁 분기 추가)
                 → 등록된 모델들 (main · compare) → 모델 이력 저장소 → 엑셀
                    저녁 잠정 (키움 T) · 아침 확정 (KRX T)
```

- **규칙은 한 벌.** 모델 DB 는 quant-ledger 와 같은 stage 규칙·equity SQL·queries.py 를 쓴다. 다른 점은 **무엇을 언제 짓느냐**뿐이다:
  모델 폐포의 빠른 표(가격·상장·지수·키움 수급·WISE 컨센서스·WISE 재무)는 매번 **전량** 다시 짓고, 느린 표(수정주가 계수·DART 재무·업종·법인 등)는 가져온다.
- 저녁 T 는 지금 규칙에 자리가 없다(달력·유니버스 격자에 T 가 없음 — TECH_DEBT B-7). 이것은 **공유 규칙을 확장**해서 푼다(§3-2) — 두 DB 가 함께 갖는다.
- 실측(10-02 서버): 모델 입력 빌드 3.5초, 모델 5개 7.5초. 모델 DB 소요는 **폐포 빠른 표의 전량 재계산 시간**이 정한다 — D2 첫 일은 이것을 재는 것.

## 2. 모델 유동성 설계 (D1)

지금은 TOML 한 장으로 끝나는 일이 "기존 엔진에서 가중치만 바꾼 새 버전" 하나뿐이다(감사 — 주 모델 상수 `build.py:48`, 모델 목록 하드코딩

| # | 장치 | 내용 |
|---|---|---|
| A | 생애주기 | TOML `status = draft / compare / main / retired`, `label`. main 정확히 1개. 기본 빌드 = main + compare, draft 는 `--specs` 로만. **`--primary` 인자는 main 이 아닌 값을 받으면 거절**(우회 금지). 퇴역 판 삭제는 `model gc --retired`(승인). 테스트는 레지스트리에서 목록 유도 |

### 3-1. 표 레시피 (D2 에서 폐포 그래프로 확정 — 지금은 조사 결과 기준)

2. **M-2** 가져올 판을 날짜로 고정, 날짜축 표는 묵으면 중지
3. **M-3** T 당일 기업행위 종목 그날 제외(저녁 30% 규칙 + DART 권리락·기준일 공시, 아침 KRX 기준가)
4. **M-4** compare 실패는 그 모델만 제외
5. **M-9** 빠른 표는 전량 재계산(D2 측정 뒤 확정) — 증분은 10-14 뒤 필요할 때만
6. **D2 서버 측정** 승인(격리 루트, 운영 무접촉) · 실적 시즌 DART 하루 지연 허용 여부
7. M-5~M-8 권고안 일괄 확인
