# 키움 없이 먼저 마무리할 검증 랩 작업

2026-10-18 사용자 요청은 키움 연결 없이 지금 완결할 수 있는 작업부터 끝내는 것이다.
남은 항목 전체를 한 번에 구현하거나, 화면·합성 테스트 통과를 자동매매 준비 완료로 간주하지 않는다.
이 문서는 순서·수용 기준과 부분 구현의 경계를 인계한다. **머지된 검증 화면과 남은 절차·연구를 구분하며,
키움 미연결이나 화면 테스트 통과를 전체 연구·자동매매 완료로 해석하지 않는다.**
상태·집계의 정본은 [PLAN](./PLAN.md), 계약은 [설계 D1~D11](../../superpowers/specs/2026-09-29-validation-lab-design.md)과
[WORKFLOW](./WORKFLOW.md)다. 기존 SoT·책임 경계를 바꾸지 않는다.

이는 검증 랩 28개 항목의 집계이고 전체 자동매매 완료율이 아니다. V6-01 core는 부분 구현이며 실제 개봉·UI가 남아

기능의 입력·판정은 기존 owner가 소유하고 화면은 응답을 읽는다. 합성 회귀, 격리 mock 과업·PNG 검토,
실자료 기술 QA, 전략 수익성 평가는 각각 다른 증거다. 실제로 실행한 기능별 실자료 범위만
[열람 기록](./REAL-DATA-CHECKS.md)에 남기며 다른 화면으로 통과를 옮기지 않는다.

## 순서와 완료 기준

### 1. V5-02: 마무리한 파라미터 추적·미리보기 일관성

- 목적: 사용자가 고른 파라미터와 미리보기·추적·실행이 서로 다른 설정을 읽는 일을 막는다.
- owner: 기존 portfolio/trace application 입력 계약·shared 생성 SDK·편집기 요청/context owner.
  파라미터 해소는 기존 domain owner를 재사용한다.
- 완료 기준: 같은 원문·설정·파라미터를 전달하며, 값 변경 때 query 신원이 바뀌고 이전 지연 응답이
  새 설정에 나타나지 않는다. 미지/잘못된 값의 기존 거절, 원문·실행 취소, 계열 시도 수 정책을 보존한다.
- 검증: 합성 domain/application/HTTP 경계, MSW 요청 payload·cache 전환, 실제 격리 편집기 동선.

### 2. V5-04: 파라미터 지도와 명시적 후보 선택

- 선행: 1번과 기존 V4-03·실험 API. 추천 양수 경계 수정 #545의 최종 통합도 확인한다.
- owner: `entities/experiment`의 서버 query와 선택 feature·실험 화면. 판정은 기존 `plateau_map`,
  선택 가능 여부와 선택 당시 N·DSR 기록은 `ExperimentRunService.select`가 소유한다.
- 완료 기준: 칸 비교에서 추천·봉우리·실패/파산·점수 없음·추천 없음의 이유를 구분한다. 선택 이유를
  기록하고 해당 후보 결과로 이동한다. 완료 전 선택은 기존 서버 거절을 따르며 과거 선택 스냅숏을 고치지 않는다.
- 검증: 양수 추천과 0 이하 추천 없음의 독립 fixture, 완료 전/실패 칸 거절, 키보드 선택과 좁은 화면 비교.
  추천·민감도 수식을 화면에서 다시 계산하지 않는다. 워크포워드 자동 창 선택 정책도 바꾸지 않는다.

### 3. V5-06: 금액별 비용과 팩터 회귀 읽기

서로 독립 검증할 수 있도록 두 화면 패킷으로 나눈다.

- **용량(US-CS-11)**: 기존 capacity preview/create/report를 재사용한다. backend/커널이 기록한
  금액별 비용 후 샤프·참여율·충격·반올림·세션 미체결·한계 금액과 부재 이유를 읽게 한다.
  기반 실행 사전 조건, 계열 N·대표 샤프 불변, 진행/취소/실패와 legacy 값 부재를 검증한다.
- **회귀(US-CS-12)**: 기존 비동기 조회 계약과 머지된 #546의 활성 접수 1개 상한을 소비한다. `computing`의 제한된 재조회, 계산 실패 후 명시적 복구,
  데이터 판 불일치, 404/409/410, 실행 전환 시 이전 결과 차단을 다룬다. 알파·t·β·관측 수·빠진 구간·판본과
  조회 시점 계열의 t 기준을 표시하며 다시 계산하지 않는다.
- owner: 기존 analytics/capacity domain·application API는 계산을, 생성 SDK·entity query와 화면 feature는
  조회/표시를 맡는다. 회귀 cache는 파생 메모리 값이며 결과·시도 원장을 쓰지 않는다.
- 검증: 유효 숫자 경로와 부족/실패 경로를 각각 합성 입력으로 검증한다. 기본 mock 3종목의 회귀는 관측 부족이므로
  그 결과를 숫자 경로의 증거로 대신하지 않는다. 서로 다른 키의 회귀 요청이 만드는 대기 작업 수·수명도 검토한다.

### 4. V5-07: IDE에서 기존 연구 동선 연결

- 선행: 위 계약과 기존 V5-03, lang2 P4-04·P5-02의 실제 통합 상태 확인.

### 5. V6-01/02: 개봉 절차의 합성 모의 구현

- 실제 봉인 구간 개봉은 **허용하지 않는다**. 현재 연구 하한 관문을 일반 실행·미리보기·추적에서 완화하지 않는다.
  [홀드아웃 규칙](../../../.claude/rules/holdout-window.md)의 별도 연구 승인·실행 절차도 이 문서로 대체하지 않는다.
- 부분 구현: [V6-01 core 계약](./V6-01-preregistration-simulation.md)에 따라 동결 신원·기준 등록, SQLite의
  단일 simulation claim·멱등성, 중단·결과 손실 시 소모 유지를 구현해 #547로 core만 머지됐다. 실제 개봉 권한·원천 연결·
  HTTP/bootstrap·화면은 남아 있다. 합성 모의 DB를 실제 봉인창의 미사용 증거로 쓰지 않는다.
- owner: 순수 동결·등록·전이 정책은 domain, 작업 제어는 application, 개봉 원장은 기존 연구/봉인 기록 owner,
  후속 화면은 동결 → 기준 등록 → 확인 → 결과의 4단계로 설계한다. 실제 실행 adapter는 별도 권한 경계다.
- 완료 기준: fake 데이터·실행 adapter만으로 한 번의 열람 상태가 영속되고 되돌려지지 않으며, 개봉 뒤 재실행 분류와
  N 제외를 증명한다. 확인 단계에 검증 카드의 주의 항목을 보인다. 실제 원천을 여는 경로는 계속 차단한다.
- 검증: 합성 동시 요청·중단 복구·변조/신원 불일치·중복 개봉 거절·4단계 E2E.
  이 검증을 실제 홀드아웃 개봉 또는 홀드아웃 성과 판정 완료로 기록하지 않는다.

## 공통 검증과 의도적 제외

- 각 패킷은 계약/owner 확인 → 구현 → 관련 단위·통합·실제 사용자 경로 → 독립 리뷰 → 최종 head CI 순서로 닫는다.
  통과한 테스트 수는 실제 사용성·수익성의 대체 지표가 아니다. 상태·스토리 완료는 근거 확인 뒤 별도로 갱신한다.
- 기능별 실자료 기술 QA는 [REAL-DATA-CHECKS](./REAL-DATA-CHECKS.md)를 따른다. 별도 runtime DB/포트에서
  **2020-01-02 이후만** 사용하고 snapshot·소스 신원·설정·관측 결과·소요와 한계를 남긴다. 원천·S01 보존본을
  갱신하지 않는다. 현재 읽기 감사는 실제 원장을 열거나 추가 QA를 수행한 것이 아니다.
- 기술 QA의 계산 완료·화면 표시·성능 개선과 전략의 비용 후 수익성 판정은 다르다. 열람한 자료에 맞춰
  전략·기준을 바꾸면 탐색 사실을 기록하며, 합성 결과를 실자료 근거로 제시하지 않는다.
- 키움·실브로커·외부 계좌·주문 전송, 실제 봉인 개봉, 고급 시각 표현과 새 탐색 알고리즘은 제외한다.
  S01 재현성/판본 보존과 S05 오프라인 멱등·대사·복구는 실계좌 연결 전의 별도 게이트로 유지한다.

## 키움 연결이 필요한 작업과 별도 수익성 평가

S06의 실제 모의계좌 주문·체결·취소·조회·재접속 확인, S07 운영 축의 실제 집행 대사에는 외부 브로커 연결이
필요하다. 공급자 문서 조사·오프라인 안전 설계는 먼저 할 수 있지만 fake의 동작을 공급자의 보장으로 쓰지 않는다.
S08 제한 실거래는 연구·모의·운영 증거 뒤 사용자가 자본·손실예산·주문 범위를 별도로 정해야 한다.
근거는 [S05 오프라인 계약](../research-to-trading/S05-offline-execution.md)과
[연구→실행 S06~S08](../research-to-trading/README.md#s06--외부-모의-브로커-계약-확인)이다.

실자료 수익성 연구는 사용자의 기존 결정에 따라 **2026-10-19 주간 예정**이며 이번 기능 구현·기술 QA와 별도다.
S03 신호 예측력과 S04 초기자본 기준 비용 후 계좌 성과를 나눠 보고, 데이터·회계 제약·시도 이력·스트레스·판정 기준을
결과 전에 기록한다. PSR/DSR·기술 QA·모의 절차 PASS 하나로 전략 채택이나 실제 수익을 보장하지 않는다.
