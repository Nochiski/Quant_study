## 0. 한 장 요약

1. **DART 문서화 엔드포인트는 정확히 85개다.** 6개 카테고리 가이드 페이지에서 전부 목록 확보 — 추측으로 채운 항목 없음.
   우리가 알던 것은 **8개**. 즉 **77개(90.6%)가 계획 밖에 있었다.**
2. **가장 값싼 신규 자산은 DS005(주요사항보고서 36종)와 DS006(증권신고서 6종)이다.**
   두 카테고리는 **날짜 범위 상한이 없어 `corp_code` 당 1콜로 전체 이력**이 온다(실측). 엔드포인트 1개 전수 = 3,341콜 = **0.17일**.
   반면 DS002(정기보고서 30종)는 `corp × year` 축이라 엔드포인트 1개 전수 = 26,220콜 = **1.34일** — 8배 비싸다.
3. **소멸성 자산이 하나 있다: `elestock.json`(임원·주요주주 소유보고).** `majorstock` 과 함께 **최근 약 2년 롤링만** 준다(실측 정정 — 기존 기록 "전체 이력"은 오류). 지금 안 받으면 API 로는 영구 취득 불가.
4. **채택 결정: 신규 21개 엔드포인트 + 스키마 수정 2건. 신규 콜 183,317 (+9.40일).**
   **거부: 신규 56개 + 기존 계획 항목 2건.**
5. **판정 — 이 증분은 전체 일정을 하루도 늘리지 않는다.** DART 는 무료·독립 채널이고 `COLLECT_PLAN.md:10` 이 확정한 병목은 **키움 23.6일**이다.
   DART 총액이 **23.6일을 넘지 않는 한 wall-clock 증가는 0**이다. 확정안은 20.01일(운영여유 포함 22.6일) — 임계 안쪽이다.
   이 한 줄이 "그만큼의 가치가 있는가"에 대한 답이다: **가치 판단이 아니라 산술 판단이다. 공짜다.**

## 2. 계획에 없었는데 받아야 할 것 (우선순위 순)

**콜 산식의 기저 모수** (전부 `DART_DESIGN.md §2` 실측값에 정렬)
- `N` = KRX 보통주 주권 **3,341종목**(폐지 포함, DART 매칭률 100% 실측)
- `CY` = 상장구간 게이팅 corp-year, FY2015~2025 = **26,220**
- 1콜 1 corp_code 강제 (`DART_DESIGN.md` J4 — 콤마 다중은 silent 부분반환 실측)
- 일 가용 **19,500콜** (20,000 − 카엘 ~300 − 마진 200)
- DS005·DS006·DS004 는 **1콜 = 전이력**이므로 콜 수 = `N`. 밴드 상단은 `CORPCODE.xml` 의 `stock_code` 보유 3,959 (+18.5%) — 2010 이전 폐지 법인까지 포함할 경우.

"쓸 데가 없다"가 아니라 **왜 없는지**를 적는다.

### 3-1. `fnlttSinglAcnt` (단일 주요계정) — 정보 지배당함

### 3-2. `fnlttSinglIndx` (단일 재무비율) — 3중 결격

### 3-3. `detScritsIsuAcmslt` (채무증권 발행실적) — 순정보 0, 파싱 비용 최대

→ 저장·정규화 비용이 최대인데 순증 정보가 0. **거부.**

### 3-4. 보수 6종 (`hmvAuditIndvdlBySttus`·`indvdlByPay`·각 V2·`unrstExctvMendngSttus`·`drctrAdt…`) — 관측 단위가 종목이 아니다

개인별 보수는 **개인 단위 관측**이라 종목 팩터로 환원할 방법이 없다(개인 → 종목 집계는 이미 `hmvAuditAllSttus` 총액이 하는 일). 총액 계열(`hmvAuditAllSttus`, 유형별, 주총승인) 역시 "경영진 보수/영업이익" 이라는 가설이 문헌적으로 얇고, 삼성전자 실측에서 **`se='계'` 행에만 금액이 있고 나머지 3행은 `-`** 라 유형별 분해가 대개 불가능하다. `CY × 6 = 157,320콜(8.1일)`을 사전 가설 없이 태우는 것은 데이터 마이닝이다.

**단, V2 013 원인 규명 4콜은 별도로 남긴다** — Ver 2.0(apiId 2026001/2026002)은 2026년 신설이고, V2 전환이 다른 API 로 확산되면 우리 수집기가 조용히 빈 응답을 받게 된다. 이건 팩터 목적이 아니라 **파이프라인 방어** 목적이다.

### 3-5. `stkdpRs` (증권예탁증권) — 모집단이 비어 있다

2회 프로브 모두 013 + `list.json(pblntf_detail_ty='C005')` 교차 확인 **0건**. 한국 상장사가 DR 신고서를 거의 내지 않는다. "표본이 나빴다"가 아니라 **사건 자체가 없다.**

### 3-6. 해외상장 4종 (`ovLstDecsn`·`ovDlstDecsn`·`ovLst`·`ovDlst`) — 유니버스와 무관

우리 백테스트 유니버스는 **KRX 상장 보통주**다. 해외 시장 상장·폐지는 KRX 유니버스 편입·이탈에 영향을 주지 않는다. 이벤트 스터디 대상으로도 국내 주가 반응이 크지 않은 범주다. `4 × N = 13,364콜` 절약.

### 3-7. `document.xml` (공시 원문 ZIP) — 대체재가 이미 있고, 남는 부분은 파이프라인이 없다 【보류, 거부 아님】

DS001 조사는 이걸 "큰 미수집 자산"으로 제안했다. 그 근거는 **① 감사의견 ② 계속기업 불확실성 ③ 주석 전문** 세 가지였다. 검토 결과:

- **① 감사의견은 대체재가 있다.** `accnutAdtorNmNdAdtOpinion`(§N8)이 `adt_opinion`·`emphs_matter`·`core_adt_matter` 를 **정형 필드로, 1콜에 3개 연도** 준다. 8,740콜 vs `document.xml` 30,800콜(사업보고서 전수) — **3.5배 싸고 파싱이 0**이다.
- **② 계속기업 불확실성**은 `accnutAdtorNmNdAdtOpinion.emphs_matter`(강조사항)에 상당 부분 들어온다. 완전하진 않으나 1차 스크리닝은 된다.
- **③ 주석 전문**만이 고유 자산이다. 그런데 이걸 팩터로 쓰려면 **한국어 회계 텍스트 NLP 파이프라인**이 필요하고 우리에겐 없다. 파이프라인 없이 **4~60GB**(사업보고서 3년 파일럿 4~7GB, 전수+분반기 40~60GB)를 받아두는 것은 저장 비용만 발생시킨다.

→ **Phase D 보류.** 착수 조건을 명시한다: "주석 텍스트를 소비할 파서가 존재할 때, 사업보고서(A001) 최근 3년 파일럿 8,400콜부터."

**구현 시 반드시 반영(실측)**: 성공=ZIP(`PK\x03\x04`), 실패=XML 인데 **확장자가 둘 다 `.xml`** 이다. `api.dart()` 가 bytes 를 그대로 주므로 호출부에서 `raw[:2]==b'PK'` 스니핑을 안 하면 **200바이트 오류 XML 을 문서로 저장한다(silent corrupt)**. 없는 접수번호는 `014` 가 아니라 **`013`**.

### 3-8. `fnlttXbrl` (XBRL 원본 ZIP) — `document.xml` 과 목적 중복이며 열위

주석·세그먼트 확보라는 목적이 `document.xml` 과 같다. `document.xml` 은 **감사보고서·연결감사보고서까지 포함**(ZIP 엔트리 3개 실측)해 상위호환이고, `fnlttXbrl` 은 저장 추정 **24GB** + `corp_code` 로 못 부르고 `list.json` 으로 `rcept_no` 를 먼저 뽑아야 한다. 상위호환이 보류된 이상 하위호환은 자동 보류.

### 3-9. `wdCocobdIsDecsn` (상각형 조건부자본증권) — 대상이 금융지주뿐

실측 21행 전부 신한지주. 코코본드는 은행지주 자본규제 상품이라 발행 주체가 금융지주 10여 개로 고정된다. 우리 팩터 유니버스에서 금융지주는 이미 재무제표 기반 팩터가 대부분 정의되지 않는 예외 그룹이다. `N × 1 = 3,341콜` 을 10여 종목을 위해 쓰지 않는다.

### 3-10. `last_reprt_at='Y'` 파라미터 — **PIT 연구에 해롭다** 【기존 계획에서 명시 제거】

최종보고서만 남기고 **정정 전 원본을 지운다**. 우리는 "발표 당시 시장이 본 값"으로 백테스트해야 하므로 정정 전 원본이 데이터이지 노이즈가 아니다. 이 파라미터를 켜면 **정정으로 개선된 숫자가 발표일에 있었던 것처럼 되어 look-ahead bias 를 직접 주입**한다. 코드에서 사용 금지로 못박는다.

### 3-11. 나머지 DS002 10종 / DS005 미프로브 2종 — 사전 가설 없음

`hyslrChgSttus`·`exctvSttus`·`adtServcCnclsSttus`·`accnutAdtorNonAdtServcCnclsSttus`·`outcmpnyDrctrNdChangeSttus`·`pssrpCptalUseDtls`·`prvsrpCptalUseDtls`·`srtpdPsndbtNrdmpBlce`·`cndlCaplScritsNrdmpBlce`, DS005 `stkrtbdInhDecsn`/`TrfDecsn`.

### 5-3. 이벤트 중복 처리 — 정정공시 (DS005·DS006 공통)

`rcept_no` 는 유일하지만 **경제적 이벤트 1건이 N행**이다.

- **실측 증거**: `crDecsn`/KG모빌리티 — `20220831000768`(감자비율 67.18, 149,840,002주)과 `20220923000279`(68.37, 142,487,104주)이 **같은 `bddd`(2022-08-31)**. 뒤가 정정이다.
- 전 행을 쓰면 같은 감자를 두 번 센다. 최신값만 쓰면 **주가 반응 시점(최초 공시일)을 잃는다.**
- **처리 규칙**: 저장은 전 행(`rcept_no` PK). 사용 시 `(corp_code, bddd)` 로 묶어 **최초 `rcept_no` = 이벤트 발생시각**, **최대 `rcept_no` = 확정 수치**로 분리.
- **반례 주의**: `cvbdIsDecsn`/신라젠 `20200423000193`(bd_tm=31회차)과 `20200423000196`(32회차)은 **정정이 아닌 동일자 별건**이다. → **사채류는 `(corp_code, bddd, bd_tm)`** 로 묶어야 한다.

### 5-4. 구현 필수 반영 사항 (전부 실측)

**A. 파서 구조**
1. **DS006 응답은 `list` 가 아니라 `group`**: `{"status","message","group":[{"title","list"}]}`. 평면 파서를 재사용하면 `status=000 / rows=0` 으로 **조용히 0행**을 읽는다(1차 프로브가 실제로 6개 중 4개를 오판). `013` 과 구분 불가.
2. **`document.xml` 성공/실패를 확장자로 판별 불가**: 성공=ZIP(`PK\x03\x04`), 실패=오류 XML. 호출부에서 `raw[:2]==b'PK'` 스니핑 필수.
3. **DS005·DS006 에 페이지네이션 필드가 없다**(실측). 관측 최대 22행. **대량 이력 종목에서 잘림 여부 미확인** → 백필 시 행수 상한 근처 값을 모니터링.
4. **DS002 도 페이징 파라미터가 없다.** 1,588행도 한 번에 온다 → timeout 여유는 두되, 잘림은 페이징으로 해결 불가.

**B. status 해석**
5. **`status=000` ≠ 데이터 있음.** DS002 미상환잔액 5종은 해당 없어도 3행을 `-` 로 채워 000 을 준다. `hyslrChgSttus` 도 "변동 없음"을 전 필드 `-` 1행으로 준다.
6. **없는 접수번호는 `014` 가 아니라 `013`**(`document.xml`).
7. **DS004 두 API 는 `status=000` 으로 롤링 컷을 숨긴다.** 2024-08 이전을 "이벤트 없음"으로 오독하지 않도록 원장에 `collected_at` 과 `min_rcept_dt` 를 기록.
8. **`bdRs` 는 실제 신고서를 누락한다**(DEFECT-DS006-01). `list.json(C002)` 을 정답지로 두고 커버리지율을 원장에 기록.
9. **`elestock` 은 실제 공시의 엄격한 부분집합** — 완전 슬라이스에서 11건 중 9건(18% 누락) 실측. 완전성이 필요하면 `list.json(pblntf_ty='D')` 교차검증.

**C. 필드 오염**
10. **`rm` 은 enum 이 아니다.** 실측 분포 `''`×82 `공`×11 `유`×5 `정`×1 **`공정`×1**. → `instr(rm,'정')`, 등호 비교 금지.
11. **개행 포함 필드**: `bsns_year`(`"제56기\n(당기)"`), `tm`(`"317-\n1"` — **`bdRs` 4그룹 전부의 PK 구성요소**), `se_nm`, `inv_prm`, `core_adt_matter`, `report_resn`. **정규화 없이 적재하면 조인이 끊기고 UPSERT 가 중복을 쌓는다.**
12. **우측 공백 패딩**: `report_nm`(`중대재해발생(종속회사의주요경영사항)              `), `isu_exctv_ofcps` 22건. `rstrip()` 필수.
13. **`adtServcCnclsSttus` 의 `(당기)/(전기)` 라벨은 틀렸다** — 실측 `제56기(당기)`/`제55기(당기)`/`제54기(전기)`. 라벨로 연도를 결정하면 **두 행이 같은 연도로 붕괴**. "제NN기" 기수 숫자만 신뢰.
14. **`idx_val` 은 값이 없을 때 키 자체가 응답에서 빠진다**(null 아님). `r['idx_val']` → KeyError. `.get()` 필수. 추가로 Excel 오버플로 문자열 `#########` 유입 실측.
15. **`idx_cl_code='M240000'`(활동성) 응답에 `M451000 배당성향`이 섞여 온다.** 분류는 `idx_cl_code` 가 아니라 `idx_code` 접두사로 판정.
16. **`list.corp_name`(`삼성전자`) ≠ `company.corp_name`(`삼성전자(주)`).** 이름 조인 금지, `corp_code` 로만.
17. **`elestock.rcept_dt` 가 `rcept_no` 접수일과 불일치 18/3,398건** (예 `20240920000459`/`rcept_dt=2024-09-23`). 전부 `rcept_dt` 가 뒤 → as-of 를 `rcept_no[:8]` 로 잡으면 **최대 3일 look-ahead**. **`rcept_dt` 를 써야 한다.**
18. **`stock_code` 필드가 DS004 응답에 없다.** `corpCode.xml` 조인 필수.
19. **`ceo_nm` 복수 대표는 쉼표 구분 1문자열**(`전영현, 노태문`), `jurir_no` 하이픈 없음.
20. **1999년 문서는 스키마 세대가 다르다**(`dart4.xsd` 없음, `<PERIOD>` 존재, `<FORMULA-VERSION><MAJOR>1`). `document.xml` 착수 시 파서 분기 필요.

**D. 데이터 하한 (실측)**
21. 연간재무 **FY2015** / 분기재무 **FY2016**(005930 단일 근거, 프로브 30콜로 재확인 예정) / DS005 **≈2015**(관측 최소 `20150318`) / DS006 **2015**(가이드 명시) / `fnlttSinglIndx` **FY2023 Q3** / DS004 **롤링 2년**.
