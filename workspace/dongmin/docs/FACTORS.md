> DART EPS는 가중평균 유통주식수로 나누고, 카엘(네이버) EPS는 계산 기준이 다를 수 있다.

> **경계 연도(2021/2022)에 가짜 점프**가 생긴다. 합치기 전에 중첩 구간(2022~2025)을 대조할 것.

### 추정치 리비전 (애널리스트 컨센서스)

실현 실적이 아니라 **애널리스트 추정치가 어느 방향으로 움직이는가**를 보는 축이다.
한국 시장에서 실증이 두터운 팩터군이고, 위 성장 팩터(실적 기반)와 정보가 겹치지 않는다.

| ID | 팩터 | 계산식 | 원재료 | 사용 가능 시점 |
|---|---|---|---|---|
| G05 | **영업이익 추정치 리비전** | `(op(t) / op(t−1M)) − 1` | 카엘 `consensus_revision_daily.op` | **2027년 이후** |
| G06 | **순이익 추정치 리비전** | `(ni(t) / ni(t−1M)) − 1` | 동일 `.ni` | 동일 |
| G07 | 매출 추정치 리비전 | `(revenue(t) / revenue(t−1M)) − 1` | 동일 `.revenue` | 동일 |
| G08 | 투자의견 리비전 | `opinion(t) − opinion(t−1M)` | 동일 `.opinion` | 동일 |

**실측 예시** — 삼성전자 `target_period=2026/12`

```
op   1주전 3,909,276   1개월 3,911,296   3개월 3,516,597   1년 387,968
ni   1주전 3,189,808   1개월 3,197,005   3개월 2,874,804   1년 359,941
                                      ↑ 3개월 대비 영업이익 추정치 +11.2%
```

> **왜 지금은 못 쓰나 — 두 테이블의 성격이 다르다**
>
> - **`consensus_revision_compare`**: 종목당 1행. **오늘 시점의 스냅샷이고 매일 덮어쓴다.**
>   `op_1m` 같은 컬럼이 있어서 리비전을 바로 볼 수 있지만, **과거 시점으로 되돌아갈 수 없다.**
>   백테스트에 쓰면 전 기간에 오늘 값을 적용하게 되어 look-ahead가 된다.
> - **`consensus_revision_daily`**: 일별 시계열. **2026-04-03부터 4.5개월치**뿐이다.
>   이게 쌓이면 G05~G08이 가능해진다. **하루 650~666종목씩 계속 축적 중이다.**
>
> 커버리지도 **787종목**으로 제한된다 — 애널리스트가 커버하는 종목만 존재한다.
> 전체 유니버스의 약 30%이고, 소형주는 구조적으로 빠진다.
>
> **결론: 지금 백필 계획에 영향을 주지 않는다. 데이터가 저절로 쌓이므로 기다리면 된다.**
> 다만 `consensus_revision_daily`가 **끊기지 않는 것이 중요하다** — 놓친 날은 복구할 수 없다.

## 8. 업종별 처리 — 금융업

**원장은 손대지 않는다. 변환은 통합층에서 한다.** 아래는 통합층 규칙이다.

### 왜 필요한가 — 금융업은 매출액이 없다

DART 실측(FY2025 사업보고서, 핵심 8항목을 표준태그 완전일치로 탐색):

```
                매출액 매출총이익 영업이익 순이익 자산 부채 자본 영업CF   판정
KB금융 (은행)      X     X      O     O    O   O   O    O    6/8
삼성화재 (보험)     X     X      O     O    O   O   O    O    6/8
키움증권          O     X      O     O    O   O   O    O    7/8
영원무역·한섬·삼성   O     O      O     O    O   O   O    O    8/8
```

은행·보험은 **팔 물건이 없어서** 매출액·매출원가 개념이 성립하지 않는다.
`ifrs-full_Revenue`(IFRS 15, 고객과의 계약)가 아니라 이자수익은 IFRS 9, 보험료는 IFRS 17 영역이라
**애초에 다른 태그 체계**를 쓴다. DART 자신도 `fnlttCmpnyIndx`에서 금융업에는
매출 기반 지표(매출총이익률·순이익률·판관비율)를 **전부 공란**으로 준다.

### 원장에 쌓이는 것 (변환 없음)

```
KB금융      이자수익 291,561억 · 이자비용 160,830억 · 순이자손익 130,731억
            수수료수익 57,735억 · 순수수료손익 40,983억 · 보험수익 123,765억
삼성화재     보험영업수익 195,300억 · 투자영업수익 52,485억 · 투자손익 11,761억
키움증권     영업수익 171,217억 (ifrs-full_Revenue) · 수수료수익 13,820억
삼성전자     매출액 3,357,050억 · 매출원가 2,022,355억
```

회사마다 다른 계정이 다른 이름으로 들어가는 것이 정상이고, 그게 원장의 계약이다.

### 통합층 변환 규칙

| 섹터 | `revenue_krw` 채우는 법 | `revenue_basis` |
|---|---|---|
| 일반 (제조·유통·서비스) | `ifrs-full_Revenue` / `ifrs_Revenue` | `standard` |
| **증권** | 동일 — 영업수익이 표준태그로 온다 | `standard` |
| **금융(은행지주)** | 이자수익 + 수수료수익 + 기타영업수익 + 보험수익 | `banking_gross` |
| **보험** | 보험영업수익 + 투자영업수익 | `insurance_gross` |
| (대안) 전 금융업 | 카엘 `consensus_annual.revenue` 차용 | `consensus` |

**`revenue_basis` 컬럼이 반드시 있어야 한다.** 없으면 나중에 "KB금융 매출 81조가 무엇이었나"를 알 수 없다.
`fs_div_used`를 남기는 것과 같은 이유다.

### 총액이냐 순액이냐 — 총액이 실무 표준

같은 회사에 세 값이 존재한다. 실측:

```
KB금융 FY2025
  순액 (순이자손익 + 순수수료손익 + …)     189,719억   회계적으로 깔끔하나 시장이 안 쓴다
  이자수익만 (키움 ka10001 sale_amt)      291,561억
  영업수익 총액 (컨센서스 revenue)         812,307억   ← 실무 표준
```

순액을 매출로 쓰면 **영업이익률이 44.9%**가 되어 제조업과 비교가 불가능해진다.
총액 기준이면 **10.5%**로 같은 눈금에 놓인다. 컨센서스 실측에서 금융업이 전부 8~11%에 모이는 것이 근거다.

```
005930 삼성전자 13.1%   000660 SK하이닉스 48.6%
105560 KB금융  10.5%   086790 하나금융 7.8%   055550 신한지주 10.9%
000810 삼성화재 10.7%   005830 DB손보  10.3%   039490 키움증권 8.7%
```

### 영업이익 아래로는 DART 와 컨센서스가 완전히 일치한다

```
KB금융 FY2025      DART        컨센서스     판정
  영업이익        85,177억     85,177억    완전 일치
  당기순이익       58,332억     58,332억    완전 일치
  EPS            15,410원     15,116원    1.9% 차이 (주식수 기준 차이)
```

**갈리는 것은 매출액 한 항목뿐이다.** 나머지 팩터는 금융업에서도 정상 계산된다 —
PBR · PER · PCR · ROE · ROA · 발생액 · FCF · 부채비율 · 자산성장률.
못 만드는 것은 **PSR(V03)과 영업이익률(Q03)** 둘뿐이고, 그마저 위 규칙으로 대체된다.

### 은행 합산식은 아직 확정 못 한다

컨센서스 81.2조는 **지주 연결 손익계산서 안에 없다.** 연결은 내부거래를 상계한 순액 성격으로 표시하는데,
애널리스트는 자회사 영업수익을 총액 합산한다. 즉 **집계 층위가 다르다.**
은행 8~10개사로 표본을 늘려야 규칙이 나온다. **원장에 원문이 다 들어가 있으면 나중에 어느 쪽이든 만들 수 있다.**

### ⚠ 선행 조건 — 섹터 시계열이 없다

위 규칙은 전부 "이 종목이 어느 섹터인가"를 안다는 전제 위에 있다. 그런데:

```
KRX 원장 SECT_TP_NM        942종목 전부 공백 (실측)
카엘 stocks.sector          금융 108 · 증권 18 · 보험 12 = 138종목
                           단 현재 스냅샷이라 과거 시점 업종을 모른다
```

금융권이 **종목 5.4% · 시총 12.7%**라 무시할 수 없고, 업종이 바뀐 종목이 있으면 백테스트가 어긋난다.
**WICS 섹터 5,174콜(미착수)이 이 문제를 푸는 항목**이며, 통합층 구현의 선행 조건이다.
