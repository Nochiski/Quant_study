> 원장(raw) → **stage** → 통합층(equity.db) 3층 중 가운데 층의 계약.
> 2026-08-28 저술. 근거는 전부 서버 원장 실측(`?mode=ro`)이며, 출처 없는 서술은 두지 않는다.
>
> 관련: 원장 수집은 `COLLECT_PLAN.md`·`DART_DESIGN.md`, 소스 목록은 `DATA_CATALOG.md`,
> 팩터 정의는 `FACTORS.md`, 폐지종목 감사는 `archive/SOURCE_AUDIT.md`.
>
> **2026-09-02 v2.2 주석**: 결정·규칙의 정본은 `STAGE_DESIGN.md` v2.2 다. 아래 규칙 문장 중 개정된 것은
> ~~취소선~~ + `[→ DESIGN …]` 로 표시했고 원문은 지우지 않았다(기록 원칙 2). 수치는 08-27~28 측정치이며
> 게이트에 들어가는 값은 빌드 시점 `baseline.json` 재측정이 정본이다.

## 0. 이 문서가 존재하는 이유

2026-08-26~28 사이 조사에서 **"확정"으로 보고했던 판단 다수가 한 사례를 일반화한 것**임이
적대적 검토로 드러났다. 그 과정에서 나온 실측치가 대화에만 남아 있어, 세션이 끊기면
소실된다. 이 문서는 **무엇이 실측으로 닫혔고 무엇이 아직 열려 있는지**를 분리해 기록한다.

기록 원칙 세 가지:

1. **실측 근거 없는 문장을 쓰지 않는다.** 표본 크기와 쿼리 조건을 함께 남긴다.
2. **깨진 주장을 지우지 않는다.** 왜 틀렸는지 남겨야 같은 착오가 반복되지 않는다.
3. **숫자는 회귀 고정 대상이다.** 줄어도 늘어도 실패로 잡는다(§6).

## 1. 층별 책임 경계

dbt staging layer 규약을 따른다 — 허용 변환은 rename · type cast · 단위 스케일링 ·
categorize **네 가지뿐**이고, **조인과 집계는 금지**다.
(출처: [dbt — How we structure: Staging](https://docs.getdbt.com/best-practices/how-we-structure/2-staging))

| 층 | 하는 일 | 하지 않는 일 |
|---|---|---|
| **원장** | API 응답 원문 보존. append-only | 값 변형 일체 |
| **stage** | 타입 캐스팅 · 단위 정규화 · 결측 판정 · 중복 제거 · **관측 가능 시각 부여** | 소스 간 조인 · 파생 계산 · 유니버스 필터 · **정책 버퍼** |
| **통합층** | 크로스소스 조인 · 3분류 결측 판정 · 파생(조정계수·유니버스) · 인덱스 | — |

**stage = 사실, 통합층 = 정책.** `available_at`을 예로 들면, "KRX 데이터가 T+1 08:00에
처음 관측된다"는 사실이므로 stage가 기록하고, "여기에 하루 버퍼를 더 둘까"는 정책이므로
통합층이 정한다.

### 1-1. `available_at`을 stage에 두는 근거

1. 유도에 필요한 원장 컬럼이 stage 이후 사라진다 — KIS는 `stlm_date`, DART는 `rcept_no`,
   KRX는 소스 밖의 `krx_timing` 프로브가 근거다.
2. 규칙이 소스마다 다르다. 통합층 한 곳에서 분기하면 소스가 늘 때마다 통합층을 고쳐야 한다.
3. 근거의 신뢰도가 소스마다 달라 `available_at_basis` 컬럼으로 사후 감사가 필요하다.

## 2. 실측으로 닫힌 사실

### 2-1. 가격 정본은 KRX다

| 대조 | 행수 | 결과 |
|---|---:|---|
| 키움 `abs(close_pric)` ↔ KRX `TDD_CLSPRC` | 7,537,984 | **불일치 0 (100.0000%)** |
| 키움 raw `close_pric` ↔ KRX | 7,537,984 | 일치 51.60% |
| KIS `kis_credit_balance` ↔ KRX 종가 | 8,937,323 | **불일치 40.4%** |
| KIS ↔ KRX 거래량 (`deal_date` 조인) | 578,106 (2024~) | **불일치 0** |

- KRX는 **무수정 원주가**다. 2018-05-04 삼성전자 50:1 분할이 소급 조정 없이 그대로 있다
  (2,650,000 → 51,900). 한 번 수집하면 값이 영원히 변하지 않으므로 재현 가능하다.
- KIS는 **수정주가**이며 조회 시점에 의존한다. 재수집하면 같은 `(종목,날짜)`에 다른 값이 온다.
- 4개 백테스트 스택(CRSP · Zipline · LEAN · Sharadar)이 전부 **원주가를 원장에 두고
  조정은 별도 테이블**로 둔다. 우리 구조가 표준과 일치한다.

**KIS 가격 컬럼은 stage에 넣되 가격 축으로 쓰지 않는다.** `price_basis` + `price_matches_krx`
플래그로 표시하고, 팩터 계산은 KRX만 쓴다. 부수적으로 `KIS ÷ KRX`가 그 종목의 조정계수라
검증축이 된다.

### 2-2. 키움 수급은 정규장 기준이다

| 대조 (20260820) | 종목 | 거래량 불일치 |
|---|---:|---:|
| `ka10014` 공매도 ↔ KRX | 736 | 0 |
| `ka10008` 외국인 ↔ KRX | 804 | 0 |
| `ka10060` 수급 ↔ KRX | 804 | 0 |
| `ka10014` ↔ KRX (2018-04-24) | 540 | 0 |

NXT 시장(~20:00)을 고려할 필요가 없다. `venue_scope='KRX'`가 맞다.

> **단, 전 구간은 아니다.** 별도 조사에서 `ka10008 ↔ KRX` 거래량 불일치 **1,024행**이
> 확인됐다(2010:10 · 2011:4 · 2012:376 · 2015:634). 2015-07-20 하루에 634종목이 동시에
> 어긋난다. 원인 미규명 — §5 미결로 이관.

### 2-3. 부호 처리는 컬럼별로 갈린다

키움 가격 컬럼의 `+`/`-`는 **전일 대비 방향 표시자**이지 값의 부호가 아니다.

```
005930 20260824  close_pric = -262500   pred_pre = -19000
                 전일 281,500 − 19,000 = 262,500   ← abs() 가 맞다
```

| 처리 | 대상 | 근거 |
|---|---|---|
| **abs() 필수** | `ka10008.close_pric` · `ka10060.cur_prc` · `ka10014.close_pric` | KRX 대조 abs 100% / raw 51.6% |
| **`+` 스트립만** | `ka10008.wght` · `limit_exh_rt` · `ka10014.trde_wght` | 음수가 3/3/0행뿐 |
| **abs() 절대 금지** | `pred_pre` · `flu_rt` · `chg_qty` · `frgnr_limit_irds` · `dbrt_trde_irds` · `ka10060` 투자자 13컬럼 · `poss_stkcnt` · `kis_loan_trans.rmnd_stcn` · `whol_loan_gvrt` | 항등식이 부호로 성립 |

**항등식 실측**: `dbrt_trde_irds = 체결 − 상환` **100.000%**, `chg_qty = poss_stkcnt − LAG`
99.918%, `frgnr_limit_irds` 99.999%.

**abs() 금지가 중요한 이유** — `ka10008.poss_stkcnt` 음수 3행(전부 2010-05-12)은 소스 결함이다.
그 행의 `wght = -900.00`인데, abs()를 걸면 **보유비중 900%** 라는 그럴듯한 값으로 승격되어
결함이 영구 은폐된다. 같은 부류: `kis_loan_trans.rmnd_stcn` 음수 2,691행,
`whol_loan_gvrt` 음수 539행.

### 2-4. 단위는 컬럼마다 다르다

원장 한 곳에 원 · 주 · 천원 · 백만원 4스케일이 컬럼명 힌트 없이 섞여 있다.

| 컬럼 | 원장 단위 | stage 변환 |
|---|---|---|
| `ka10060` 투자자 13컬럼 | 백만원 | ×1,000,000 → `_krw` |
| `ka20068.remn_amt` | 백만원 | ×1,000,000 → `_krw` |
| `ka10014.shrts_trde_prica` | 천원 | ×1,000 → `_krw` |
| `kis_short_sale.*_pbmn` | 원 | 그대로 |
| `kis_investor_flow.acml_tr_pbmn` | **원** (명세는 백만원이라 주장 — 명세 오류) | 그대로 |
| `kis_investor_flow.*_ntby_tr_pbmn` | 백만원 | ×1,000,000 |
| `kis_loan_trans.rmnd_amt` | 백만원 | ×1,000,000 |
| `kis_credit_balance.*_amt` | **만원**(취득금액 기준 — 09-09 I4 확정) | **규칙 미반영**: 현행 `stg_credit_daily` 는 `unit=unknown`·접미사 없음으로 원값 적재, equity `credit_daily.amt_basis='unknown'`. ×10,000 → `_krw` 파생은 stage 규칙 판본 변경 후속 `[→ I4 · DESIGN §4·§5]` |
| KRX 금액 컬럼 전부 | 원 | 그대로 |

**저가주 판별로 독립 검증했다** — 에이엔피(274원, 거래대금 1,064백만원)의 개인 순매수
`ind_invsr=101`이 "주"라면 101주(거래량의 0.003%)로 불가능하고, 백만원이면 9.5%로 자연스럽다.

**KIS `credit`의 금액 컬럼은 어떤 10의 거듭제곱과도 맞지 않는다** (`stcn × 종가 / amt` 평균
11,596, 범위 10,612~13,949). 주수(`_stcn`)만 쓰고 금액은 보류한다.

### 2-5. 명세가 틀린 컬럼

| 컬럼 | 명세 | 실제 | 확인 |
|---|---|---|---|
| `ka10060.acc_trde_prica` | "누적거래대금 / 백만원" | **거래량(주)** | KRX `ACC_TRDVOL`과 804/804 일치 · `ka10008.trde_qty`와 7,617,255/7,617,255 일치 |

이름과 명세를 믿고 `×1e6`을 적용하면 **100만배 뻥튀기**되어 유동성 필터·회전율·거래대금
가중이 전부 무의미해진다. **거래량으로 매핑하거나 폐기하고 KRX를 쓴다.**

### 2-6. 수집 산물이라 쓸 수 없는 컬럼

백필 페이징 경계에서 리셋되는 컬럼들이다. 값이 종목 사실이 아니라 **우리 수집 방식의 자국**이다.

| 컬럼 | 증상 | 규모 |
|---|---|---|
| `ka10014.ovr_shrts_qty` | 372행 창 경계마다 0에서 재시작 | 감소점 9,370개 전부 인덱스 371 · 창 밖 **3,086,373행 (77.71%)** |
| `kis_short_sale.acml_*` 6컬럼 | 요청 창 첫 행에서 리셋 | 010620 실측: `20100302` 누적 249,747 → `20100303` 1,863 |

`next_cursor`가 100% NULL이라 원장만으로 seam 복원이 불가능하다. **stage에 `valid` 플래그를
달아 넘기되, 누적이 필요하면 당일값으로 직접 계산한다.**

### 2-7. DART 기간 축은 명세로 확정됐다

공식 명세 원문:
> `thstrm_amount` — ※ 분/반기 보고서이면서 **(포괄)손익계산서일 경우 [3개월] 금액**

삼성전자 FY2024 매출 검산(원 단위로 정확히 닫힌다):

```
11013 (1Q)   당기  71.9조   누계  71.9조
11012 (반기) 당기  74.1조   누계 146.0조   ← 71.9 + 74.1 = 146.0 ✓
11014 (3Q)   당기  79.1조   누계 225.1조   ← 146.0 + 79.1 = 225.1 ✓
11011 (연간) 당기 300.9조
```

**`11012`의 당기값은 반기(6개월)가 아니라 2분기 3개월이다.** `build_panel.py`의
`IS_MONTHS = {11012: 3}`이 맞다. CF는 `thstrm_amount` 자체가 연초누계이며 `add_amount`가
오지 않는다(11.87 → 28.76 → 50.96 → 72.98조 단조증가).

### 2-8. `credit`의 시점 키는 `deal_date`다

| 조인 키 | 조인 행 | 종가 일치 | 거래량 일치 |
|---|---:|---:|---:|
| **`deal_date`** | 8,937,323 | 59.62% | **100.0%** |
| `stlm_date` | 8,930,276 | 2.93% | — |

**행이 기술하는 날은 `deal_date`다.** 같은 행의 OHLCV가 KRX와 완전 일치한다.
`stlm_date`로 키를 바꾸면 시세 5컬럼이 2~12일 미래로 밀린다.

`stlm_date` 자체는 깨끗하다 — NULL 0 · 빈값 0 · `LENGTH≠8` 0 · **8,970,999행 전건이
`stlm_date > deal_date`**. lag는 2일(55.7%) · 4일(36.0%) 지배, 최대 12일.
`(ticker, stlm_date)` 고유 수 = `(ticker, deal_date)` 고유 수라 단사(injective)다.

**규칙: 키는 `deal_date`, `available_at`은 `stlm_date`에서 유도.**

### 2-9. 무거래일에 종가는 살린다

```
TDD_CLSPRC = 0 인 행: 0 / 3,771,174   ← 종가는 항상 값이 있다
O / H / L 이 0인 행: 321,069 (stk 93,821 + ksq 189,236 + ETF 38,012)
그중 거래량 > 0 인 예외: 127행
```

종가는 stale copy가 아니라 **기준가**다:

```
고려개발(004200)
  20160309  종가 4,500  거래량 0  주식수 20,000,000
  20160310  종가 9,000  거래량 0  주식수  8,215,000   ← 감자
```

close를 NULL로 만들면 이 자본변동이 사라지고, `MKTCAP = 종가 × 주식수` 항등식
(9,201,516행 전건 성립)도 깨진다.

**규칙: O/H/L만 NULL, `close_krw`는 보존 + ~~`price_basis`로~~ 체결가/기준가 구분.** `[→ DESIGN v2.2 §1: KRX 는 별도 컬럼 없이 volume=0 으로 판독. price_basis_* 는 KIS 컬럼 단위 라벨]`

### 2-10. 결측 표현은 컬럼마다 다르다

전역 규칙 하나로 처리할 수 없다. 같은 행 안에서도 갈린다:

```
kis_investor_flow  019440 / 20110531
  stck_clpr = ''      acml_vol = ''       ← 빈 문자열
  prsn_ntby_qty='0'   frgn_ntby_qty='0'   ← 리터럴 0
```

| 원장 | 결측 표현 | 규모 |
|---|---|---|
| DART `dart_fin_raw` | `''` | 847,490행 (5.8%) |
| DART 보조원장 | `'-'` | `dart_tesstk.trmend_qy` 192,253행 (80.8%) |
| KIS 전 테이블 | `'0'` (NULL·빈값 0건) | `investor_flow.acml_vol` 13.9% |
| KIS `investor_flow` 가격 | `''` 1,835행 + `'0'` 96행 | 한 컬럼에 두 표현 공존 |
| KRX 주식 | `'0'` | O/H/L 321,069행 |
| KRX 지수 | `''` | `코스피 (외국주포함)` 종가 4,094일 전건 |
| KRX `PARVAL` | `무액면` 73,615 · `.25` 등 소수 24,381 · `'0'` 7,574 | 비수치 105,570행 |

**`'0'`의 진위는 KRX 대조로 판별된다** — `kis_investor_flow.acml_vol='0'` 129,084건 중
KRX가 거래를 인정하는 건 59건(0.07%)뿐이다. 반면 `kis_loan_trans.stck_prpr='0.00'` 281건은
진짜 결측이다(KRX는 그날 2,900만주 거래 기록). **테이블별로 판정해야 한다.**

### 2-11. 캐스팅 손실이 진행 중이다

```
소수점 값 3,578행 (100% 주당지표)  →  int(float()) 로 0이 되는 행 1,210행
```

`'0.01'` → 0, `'-0.04'` → 0. **부호까지 사라진다.** 292개사의 EPS·PER이 0 또는 무한대가 된다.

```
2^53 초과 값 366~380행   최대 842,787,340,982,000,000 (8.4e17)
                         float64 경유 시 최소 128 단위로 반올림
콤마 포함 값             dart_fin_raw 0건 · 보조원장 84~96%
                         CAST('153,797,130') = 153   ← 1/1,000,000 축소
정수 나눗셈              499,999,999,999 / 100000000 = 4999 (build_views.py)
```

### 2-12. 중복은 요청 창 겹침의 부산물이다

| 테이블 | 전체 | 자연키 유일 | 중복 | 값 충돌 |
|---|---:|---:|---:|---:|
| `kis_credit_balance` | 8,970,999 | 8,404,204 | **566,795 (6.32%)** | **0** |
| `kis_investor_flow` | 1,001,370 | — | 52,347 (5.23%) | **0** |
| `kis_short_sale` | 939,610 | 939,610 | 0 | — |

### 3-2. "조정계수는 하나면 된다" — 둘로 갈린다

CRSP는 `CFACPR`(가격) / `CFACSHR`(주식수)를 분리한다.

| 기업행위 | price_factor | share_factor | 시총 |
|---|---|---|---|
| 액면분할 · 무상증자 · 주식배당 | = share | = price | 불변 |
| **유상증자 · 유상감자 · 인적분할 · 합병** | **≠ share** | | 변동 |

파일럿의 `adj_factor_x` 단일 컬럼으로는 후자를 **원리적으로 표현할 수 없다.**
인적분할 000070에서 −10.03% / −20.73% / −45.73% 세 값이 나온 것이 이 때문이다.

### 3-6. "v1 테이블 유실 22,410건" — 194건이다

`dart_elestock_v1` ↔ `dart_elestock` 격차의 대부분은 **진행 중인 백필의 커버리지 차이**다
(신 테이블 1,333/2,309사). 처리 완료 corp_code 한정 대조에서는 v1 20,911 vs 신 20,909로
거의 같고, 값이 다른 13건은 전부 `corp_name` 변경이다(수량·지분율 불일치 0).

**진짜 영구 유실은 롤링 윈도우 밖 194행** — API가 약 2년 창만 주는데 v1은 2024-08-26부터,
신 테이블은 2024-08-28부터다(elestock 127 + majorstock 67). 재수집 불가.

### 3-7. "교차검증축이 독립적이다" — 순환이다

KRX · 키움 · KIS 세 소스가 **독립 원천이라는 논증이 없다.** 한국 증권사 API는 KRX 시세
재배포다. 일치는 "이 필드를 아무도 만지지 않았다"만 증명하고, **원천 자체의 오류는 어떤
일치로도 검출되지 않는다.**

`archive/SOURCE_AUDIT.md:133`의 "원주가는 KRX와 완전 일치하므로 교차검증축으로 바로 쓸 수 있다"는
검증 대상과의 일치를 근거로 검증자 자격을 주는 순환이다. 이 축은 정의상 KRX 오류를 탐지할 수
없다.
