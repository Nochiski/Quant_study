## 4. 우리 계획에 없는데 받아야 할 것 — 우선순위

### P1. `xbrlTaxonomy.json` 전 21개 `sj_div` — **21콜, 1회성**
- 왜: `fnlttSinglAcntAll` 의 `account_id` ↔ 한글/영문 표준라벨 ↔ IFRS 조문 매핑 마스터. 종목별 `account_nm` 표기 흔들림을 표준코드로 정규화하는 유일한 공식 소스
- 규모: BS1 이 519행이므로 21개 합계 대략 5,000~10,000행 (**미확인** — BS1 만 실측)
- 갱신: **불필요.** `bsns_de` 전부 20180701 인 정적 마스터. 한 번 받고 끝
- 비용 대비 효과가 압도적. **가장 먼저 받아라**
- 구현 주의: `ifrs_` vs `ifrs-full_` 접두사 정규화

### P2. `fnlttCmpnyIndx.json` 검산 세트 — **약 1,232콜, 1회성**
- 왜: 우리 재무비율 계산식의 정답지. 정의 불일치(ROE 평균자본 등)를 조기에 잡는다
- 콜 수 산출: 상장사 ~2,800 ÷ 100사/콜 = 28콜 × `idx_cl_code` 4개 = 112콜/기간. FY2023 Q3 ~ FY2026 Q1 = 11개 기간 → **1,232콜**
- 단, 100사/콜은 **미확인**. 실제로는 먼저 100사 1콜을 프로브해 상한을 확정할 것 (오류 021 확인)
- 전량이 필요한 건 아니다. **KOSPI200 등 200종목 × 4코드 × 11기간 = 88콜**로 축소하면 검산 목적은 충분히 달성
- 주의: `idx_val` 은 **값이 없을 때 키 자체가 응답에서 빠진다.** `r['idx_val']` 은 KeyError → 반드시 `r.get('idx_val')`

### P3. `fnlttMultiAcnt.json` 커버리지 프로브 — **약 308콜, 1회성**
- 왜: `fnlttSinglAcntAll` 을 종목×연도로 돌리기 전에 "그 기간에 자료가 있는 종목"을 미리 걸러 013 헛콜을 제거
- 콜 수: 28콜/기간 × 11년(FY2015~FY2025 연간) = **308콜**로 2,800종목 × 11년 = 30,800 조합의 유무를 판정
- 절감 효과가 확실하지 않으면 생략 가능. 폐지·신규상장이 많은 구간에서만 이득

### P4. `fnlttXbrl.xml` — **보류(수집하지 않음)**
- 왜 보류: `fnlttSinglAcntAll` 이 파싱된 139계정을 이미 준다. 저장 24GB, 파싱 비용 큼
- **언제 필요해지나:** 주석(footnote), 사업부문 세그먼트, 계정 간 계산관계(`_cal.xml`) 가 필요해질 때. 그때는 이것이 유일한 소스
- 선행조건: `list.json` 으로 `rcept_no` 를 먼저 확보해야 함 (corp_code 로는 못 부른다)

### 받지 않아도 되는 것

## 5. 데이터 결함 (수집 코드에 반드시 반영)

### DEFECT-D3-001: `fnlttSinglAcnt`/`fnlttMultiAcnt` 의 당기순이익 행이 중복되어 PK 를 깬다
- **상황**: `fnlttSinglAcnt`(또는 `fnlttMultiAcnt`) 응답을 `(fs_div, sj_div, account_nm)` 유니크로 적재하는 경우
- **인풋**:
  1. `api.dart('fnlttSinglAcnt.json', corp_code='00126380', bsns_year='2025', reprt_code='11011')`
  2. 반환 30행을 `(fs_div, sj_div, account_nm)` 로 그룹
- **에러 위치**: DART 응답 자체. `account_nm='당기순이익(손실)'` 행이 `fs_div` 별로 **2행씩**, 총 4행 존재. 두 행은 `ord` 만 다르다(FY2015 CFS 기준 `ord=29` / `ord=61`). 손익계산서와 포괄손익계산서 양쪽에서 추출되는데 `sj_div` 는 둘 다 `IS`, `sj_nm` 도 둘 다 `손익계산서`로 동일해 구분 불가
- **위험성**: UNIQUE 제약이 있으면 적재 실패, 없으면 **당기순이익이 2배로 집계되거나 임의의 한 행이 silent 하게 덮어써진다.** 순이익률·ROE·PER 등 순이익 기반 팩터 전체가 오염. 다행히 실측 두 행의 `thstrm_amount` 는 값이 같았으나(19,060,144,000,000 동일) **모든 종목·연도에서 같다는 보장은 없다(미확인)**
- **대응**: PK 에 `ord` 포함, 또는 `(fs_div, account_nm)` 그룹 내 값 일치 검증 후 dedup. 값이 다르면 적재 중단

### DEFECT-D3-002: `idx_val` 키가 응답에서 통째로 사라진다
- **상황**: `fnlttSinglIndx`/`fnlttCmpnyIndx` 응답을 DataFrame/dict 로 적재
- **인풋**: `api.dart('fnlttSinglIndx.json', corp_code='00126380', bsns_year='2025', reprt_code='11011', idx_cl_code='M210000')` → 15행 중 `M211100 세전계속사업이익률` 등 5행
- **에러 위치**: DART 응답. 값이 없는 행은 `idx_val: null` 이 아니라 **키 자체가 없다.** 실측: 첫 행 `list(L[0].keys())` 는 9개 필드 중 `idx_val` 이 빠진 8개
- **위험성**: `r['idx_val']` → `KeyError` 로 수집 중단, 또는 `pd.DataFrame(list)` 시 행마다 컬럼 수가 달라 열 정렬이 어긋난다. 삼성중공업은 15행 중 6행이 이 상태(결측률 40%)
- **대응**: 반드시 `r.get('idx_val')`. 스키마를 9개 필드로 고정해 채우기

### DEFECT-D3-003: `idx_val` 에 Excel 오버플로 문자열 `#########` 이 실려 온다
- **상황**: 지표값을 float 로 캐스팅
- **인풋**: `fnlttSinglIndx`, 삼성전자 FY2025 11011, `idx_cl_code='M240000'`, `idx_code='M242000'`(자본금회전율)
- **에러 위치**: DART 응답 `idx_val = "#########"`. DART 내부 산출이 Excel 을 경유하면서 열 폭 초과 표시가 그대로 API 로 새어 나온 것
- **위험성**: `float()` 예외로 배치 중단, 또는 예외를 삼키면 **결측으로 위장**된다. `api.num()` 은 이 값에 `[num] 파싱 실패 → None` 을 찍고 None 을 돌려주므로(로그는 남는다) 최소한 조용히 죽지는 않는다. 다만 "값이 원래 없음"과 "값이 오염됨"이 DB 에서 동일하게 NULL 이 된다
- **대응**: `idx_val` 원문을 raw 컬럼에 보존하고, 숫자 캐스팅 실패는 별도 플래그로 구분

### DEFECT-D3-004: `idx_cl_code` 와 `idx_code` 의 분류가 어긋나는 행이 있다
- **상황**: `idx_cl_code` 로 지표 분류를 판정
- **인풋**: `fnlttSinglIndx`, `idx_cl_code='M240000'`(활동성) 요청
- **에러 위치**: 응답 11행 중 마지막 행이 `idx_code='M451000'`, `idx_nm='배당성향(%)'`. 분류코드 접두(M24)와 지표코드 접두(M45)가 불일치
- **위험성**: `idx_cl_code` 를 분류 축으로 삼아 피벗하면 배당성향이 활동성지표로 잘못 분류된다. 또 `M45xxxx` 계열이 배당성향 말고 더 있는지는 **미확인** — 4개 `idx_cl_code` 응답의 합집합이 DART 지표 전체라는 보장이 없다
- **대응**: `idx_code` 를 PK 로 쓰고, 분류는 `idx_code` 접두사로 별도 판정
