# ELK 배치 스파이크 — P6-01

2026-10-02 클라우드 Linux, Node24.19.0, elkjs0.12.0, 저장소 Vite8.2.2.
재현: `cd frontend && node scripts/measure-graph-layout.mjs`.
스크립트는 설치된 정본 패키지만 읽으며 파일·서버·사용자 문서를 쓰지 않는다.

## 번들 측정

Vite production build를 메모리에서 수행했다. 비동기 API import와 `?url` worker asset을
분리하며, 아래는 **제품 번들 증가량이 아닌 스파이크 출력 크기**다.

| 출력 | raw bytes | gzip bytes |
|---|---:|---:|
| 스파이크 진입 + Vite preload | 2,401 | 1,263 |
| elk-api | 4,450 | 1,771 |
| worker URL 모듈 | 64 | 84 |
| elk-worker.min 자산 | 1,595,334 | 466,809 |

실제 브라우저 Worker 실행·취소는 이 Node 스파이크가 확인하지 않는다. Node bundled의
`terminateWorker()`는 가짜 worker에 `terminate`가 없어 TypeError가 났다. Node 측정에서는
생성하지 않은 Worker를 종료하지 않으며, 제품은 actual Worker factory를 쓰고 P6-02에서
종료·stale 가드를 검증한다. 브라우저 fallback으로 Node bundled를 사용하지 않는다.

## 배치 측정

200×96 노드, 서쪽 입력/동쪽 출력 포트, layered/RIGHT, 체인·이진 분기·두 입력이 합류하는 DAG 모양.
각 크기·모양의 첫 배치 뒤 같은 인스턴스에서 20회 반복. 시간은 layout promise 완료까지다.
모든 노드 좌표가 유한하고 각 edge에 배선 section이 있으며 입력 원본이 불변임을 확인한다.
첫 행만 프로세스 첫 배치이며 나머지 행의 첫 실행은 이미 초기화된 엔진이다.

| 노드 | 모양 | 해당 사례 첫 실행(ms) | 반복 p50(ms) | 반복 p95(ms) |
|---:|---|---:|---:|---:|
| 10 | 체인 | 149.22 | 16.71 | 22.04 |
| 10 | 분기 | 30.23 | 15.86 | 19.25 |
| 10 | 합류 DAG | 27.94 | 13.99 | 26.44 |
| 50 | 체인 | 29.28 | 27.51 | 32.30 |
| 50 | 분기 | 23.66 | 24.63 | 33.07 |
| 50 | 합류 DAG | 58.06 | 40.09 | 47.61 |
| 200 | 체인 | 86.13 | 93.90 | 170.90 |
| 200 | 분기 | 177.60 | 90.34 | 263.93 |
| 200 | 합류 DAG | 151.52 | 149.17 | 252.15 |

이 수치는 한 환경의 관측이며 성능 통과 임계값이 아니다. import·worker 시작·메시지 복사·DOM
페인트는 포함하지 않는다. 큰 그래프의 main-thread 동기 배치는 피하고, P6-02에서는 실제
worker 최초/반복 배치와 사용자가 편집하는 동안의 응답성을 공식 브라우저 CI에서 측정한다.
