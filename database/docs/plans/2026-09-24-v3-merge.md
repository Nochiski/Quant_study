# v3 멀티팩터 파이프라인 → quant-ledger 통합 플랜 (2026-09-24, 승인 09-24)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. **§1-2 의 결정 D-1~D-7 이 승인되기 전에는 어떤 태스크도 시작하지 않는다.**

**Goal:** kael-system-v3 의 *수집*(daily_pipeline 4단계·adj_prices)을 죽이고, 5팩터 모델(v3 z-score)·v2(percentrank)·앞으로의 모델을 quant-ledger `database/` 안의 **모델 층**(`src/model/`)이 equity 판을 읽어 매일 두 번(잠정·확정) 계산한다. v3 의 후단(엑셀·텔레그램·국면 리포트·브리핑·리서치센터·가설·unitelegram·위키)은 **호환 계층**(v3 `quant.db` 스키마의 표를 우리가 채움)으로 그대로 살린 뒤 하나씩 옮긴다. 단계마다 §2 게이트를 통과해야 다음으로 간다.

**Architecture:** 원장 6 DB → stage 67 → equity 30 + 매크로 9(현행) → **model 층**(레지스트리·입력 빌더·엔진·판/manifest/게이트) → **deliver**(`latest_scores_<basis>.json`) → **compat**(v3 `quant.db` 9표 upsert) → v3 후단 잡(`daily_post`). 모델은 파일 규약(`data/model/<model_id>/v=<build>/` + MANIFEST)과 게이트를 equity 표와 똑같이 갖는다. 컷오버는 플랜 v2 §6 규약(병행 5거래일 → 크론 그 줄만 제거 → 문제 시 복원)을 따른다.

**Tech Stack:** Python 3.11 · duckdb(equity 카탈로그 `read_only=True`) · sqlite3(호환 계층·원장) · bash(체인) · pytest(`uv run --project backend pytest database/tests -q`, CI 와 동일) · 배포 `scripts/deploy.sh --apply --allow-branch feat/v3-merge`. v3 엔진은 표준 라이브러리 + openpyxl 뿐(pandas·numpy 없음)이라 우리 런타임(pandas 없음)으로 이식 가능.

**참조:** 재료 문서 `docs/handoff/2026-09-24-v3-merge-context.md`(v3·우리 현황·미결) · 플랜 v2 `docs/plans/2026-09-11-daily-incremental-v2.md` §6(잡별 교체)·D.2(DB 동결) · Kael-alpha 인계 `~/orca/projects/Kael-alpha/handoff/2026-09-10-evening-scoring-pipeline/HANDOFF.md` §2-5(인계 계약)·§3-1(확장성 5원칙)·V2-8(manifest) · `docs/DECISIONS_PENDING.md` 결정 11 · `docs/TECH_DEBT.md` B-22·B-23·B-24 · v3 코드(읽기 전용) `~/kael-system-v3/{scripts/job_runner.py, backend/scoring/, backend/db/schema.py, config.yaml}`. 조사 근거는 §8.

## 3. 목표 구조

```
data/raw(6 DB) → data/stage(67) → data/equity(30)+equity.duckdb(매크로 9)
                                        │
                                        ▼  src/model  (as_of=D, basis∈{evening,morning})
                     registry.yaml ─▶ inputs.py ─▶ engines/<engine>.py ─▶ build.py
                                        │                                  │
                                        │            data/model/<model_id>/v=<build>/part0.parquet
                                        │            + MANIFEST.json + manifest.json(V2-8) + gates
                                        ▼
                     data/deliver/latest_scores_<basis>.json (+history)
                                        │
                                        ▼  src/compat/quant_db.py (한시 계층 — 표마다 만료 조건)
                     M1~M3: data/compat/quant.db   /   M4~: ~/kael-system-v3/data/quant.db 제자리 upsert
                                        │
                                        ▼  v3 daily_post(저녁): export_scores → insight → wiki
                                        ▼  v3 07:00 브리핑 · 리서치센터 · 가설 · unitelegram(rsync)
```

확장 장치(Kael-alpha 인계 §3-1 5원칙을 구현으로):
1. **레지스트리** `config/models/<model_id>.yaml`: `model_id`·`version`·`engine`(dotted path)·`basis: [evening, morning]`·`inputs`(이름 → 입력 빌더 함수·윈도우)·`params`(가중치 등)·`output_schema`·`enabled`. 등록된 모델은 **전부 매일 두 판** 돈다. 새 모델 = YAML 1개 + 엔진 모듈 1개.
2. **입력 계약** `src/model/inputs.py`: 엔진은 sqlite·parquet 을 모른다. `InputFrames`(prices·adj_prices·flows·mktcap·universe·consensus_revision·fin_summary·consensus_annual)를 equity 카탈로그 매크로(`v_adj_price_fwd(as_of)` 등)와 표에서 만든다. **B-24 규칙은 여기 한 곳**(evening: 시총 = T-1 KRX 주식수 × T 키움 종가, `mktcap_basis='evening_derived'` 표식).
3. **판·manifest**: `stage.manifest.Manifest` 재사용(`v=` 접두 `e_/m_/b_`), `manifest.json` = `{model_id, version, date, basis, equity_builds, stage_snapshot_id, registry_hash, params_hash, n_rows, elapsed_s}`. manifest 없는 점수는 게이트 실패(V2-8). `build_chain.sh gc_step` 은 점수 manifest 가 가리키는 equity 판도 보호(B-9 종결).
4. **게이트 MG**: MG0 스키마 · MG1 행수 = 유니버스(허용 결측 비율 명시) · MG2 total NaN 0·rank 유일 · MG3 골든 픽스처 · MG4 전판 대비 순위 상관 하한(record-only 첫 30일) · MG5 manifest 완비.
5. **전달층 분리**: 엑셀·텔레그램·위키는 엔진과 무관. M4 까지는 v3 `export_scores` 가 compat 표를 읽어 보낸다. 이후 `src/deliver/`(템플릿 레지스트리)로 옮기는 것은 플랜 v2 §6 2·5행.
6. **호환 계층의 만료 규약**: `src/compat/mappings.py` 표마다 `retire_when="<소비자> 가 model/equity 직독으로 옮겨진 뒤"` 를 적고, 만료된 표는 exporter 에서 빠진다. 전부 빠지면 `quant.db` 는 D.2 동결.
